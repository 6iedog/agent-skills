# 每日早报

## 一句话

把某个领域集合的近期动态，压成一份**早餐桌上看/听**的简报：
正文短、比喻准、一条一个数字，产出**单文件 HTML**（音频内嵌，拿到哪都能播）。

**领域是输入，不是本技能的属性**——见「流程 1」。

## 何时用 / 不用

| 用 | 不用 |
|---|---|
| 生成今天的早报 / 每日简报 / 行业晨报 | 做定时任务（用 automation 配置，本技能只管"跑一次") |
| 把若干领域的近期动态汇总成简报 | 深挖单一话题（直接搜即可） |
| 需要"能看也能听"的图文产物 | 个股分析或投资建议 |

## 铁律（先读这条）

**这份简报是说给一个刚起床的人听的，不是给分析师看的。**
所有文字都要经得起"一耳朵听懂"的检验。文风是这技能的核心资产 → `references/style.md`

**没有对外动作的自由。** 生成产物写文件、开预览随便；**发布、发邮件、推到任何消息面之前必须先问**。

## 流程

### 1 · 定领域（**从外部输入，不预设**）

**领域是调用方传入的参数，不是本技能定义的。** 拿到领域列表再动手。

来源优先级：
1. 调用方当场指定（"今天只看金融和极客"）
2. 调用方携带的配置（如定时任务 prompt 里写明的清单）
3. 都没有 → **问用户要哪些领域**，别自己拍脑袋定

每项领域最好带三栏：`领域名` + `关注什么` + `什么算够格`。只给了名字就自己补全后两栏。
详见 `references/sourcing.md`（含三栏写法的参考样例、三条闸门、去重、金融类额外规矩）。

### 2 · 搜

- 逐领域检索，中英文都搜。**每条必须带真实来源链接。**
- 金融数据用结构化来源（行情工具 / 可核实报道），并注明**数据时点**。
- 时间窗：优先最近 24 小时，美股与深夜消息放宽到 48 小时。
- 每领域只留 1–3 条过闸门的。**宁缺毋滥**——没够格的领域就留白。

### 3 · 写 Markdown

写到 `<输出目录>/YYYY-MM-DD-早报.md`（输出目录默认当前工作目录，用户指定则从其指定）。**格式必须严格照下面骨架，否则构建器解析错**：

```
# 早报 · YYYY-MM-DD（周X）

一句半的导语。

## 领域名

### 口语化短标题，20 字以内

正文 80–150 字，短句为主，概念打比方。可带来源链接。

[来源名](https://...)

**为什么值得看：** 最多两句、≤60 字，给结论不给分析。

---

（该领域其余条目重复上述结构）

## 今天安静的领域

没有够格内容的领域，一行带过。传入的领域全都有货则写「没有」。

## 今日主线

一两句话点出暗线；没有就说没有。
```

**每写完一条回头数一遍字数，超了就砍。** 文案越短，语音越短、单文件越小、听着越轻松。

### 4 · 出网页（+ 可选语音）

```bash
python scripts/build.py <输出目录>/YYYY-MM-DD-早报.md
```

- **默认**：图文 + 逐条语音，音频 base64 **内嵌**成单文件（5–10 MB，走到哪都能播）。
- 需要纯图文（快、小）：加 `--no-audio`
- 语音不内嵌（体积小但换环境丢音频）：`--no-embed`
- 细节、换音色、故障排查 → `references/build.md`

> 首次使用若缺 edge-tts，先 `pip install edge-tts`；缺失时构建器会自动降级成无语音网页，不会报错退出。

### 5 · 交付

1. 用 `present_files` 打开生成的 `.html`。
2. 附一两行摘要：**今天最该看的是哪一条，为什么。**

**收尾禁止套话**——不写「希望这份早报对您有帮助」这类废话。

### 6 · 落盘（可选，用户要归档时）

用户要求存档时，把**风格校准、本期主线、宏观判断修正**追加到日志：
`<工作区>/.workbuddy/memory/YYYY-MM-DD.md`（**append-only，不覆盖**）。

跨会话有用的偏好与约定 → `<工作区>/.workbuddy/memory/MEMORY.md`。

## 硬规则

- **不许起常驻进程**：不跑 `http.server`、`serve`、`npm run dev`——跑完不回收会变僵尸占端口。音频已内嵌，直接开 html 就能听。
- **不编造**：标题、数字、链接一律来自真实来源；拿不到就留白。
- **不做个股推荐**：金融部分只讲大盘、板块、宏观。
- **宁可 4 条不凑 7 条。**
