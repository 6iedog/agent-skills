# 组件创建

## 一句话

为**这一次**新建组件产出三样东西：

1. **选定了哪个组件**（如「单选下拉」，而不是「多选下拉」）
2. **该组件的预设提示词**——它就是这个组件的**全面描述**（变体 / 参数 / 场景 / 误用 / 边界），随本 Skill 提供，选定后取出即用
3. **按项目规矩落地的规格**（命名 / 目录 / 样式来源，含项目要求的规格文档）

只交付**约束与结论**，不教消费方怎么写代码——代码由消费方 agent 按项目提示词自行落地。

## 何时用 / 不用

| 用 | 不用 |
|---|---|
| 新建某个组件 | 初始化组件规范 |
| 用户描述模糊，要定位到具体形态 | 审查存量 |
| 补规格文档 | 统一样式 / 建样式 wiki |
| 某个场景该用什么组件 | 单纯写页面（直接消费项目提示词即可） |

右列属于 `component-governance`。

## 组合

```
任务 = 该组件的预设提示词 + 项目组件（创建 + 查找）提示词 + 提问（仅用于选定）
```

**顺序：先选定，后落地。** 组件没定就问「圆角用多少」是浪费。

提问只用来**选定是哪一个**（单选下拉还是多选下拉）；组件的**描述**来自它那份预设提示词，不靠提问凑。

## 流程

### 1 读项目提示词集

读目标项目 `docs/components/README.md` → 按任务取所需的那几份。

**降级**（找不到 `docs/components/`）：
- 明确告知用户「项目还没有组件提示词集」；
- 能就地探索（组件目录、样式源）就先探索；
- 建议先跑 `component-governance` 初始化，再回来创建。

### 2 选定组件

候选来自 `references/preset/` 的**组件清单**（README 索引，一句话说明各自什么时候用）。用**数据特征提问**逐层收窄，定到**一个具体组件**。

- 提问**只用于选定**，不用来拼凑组件描述。
- 选定后**取出该组件的预设提示词**——那是它的完整说明。

提问机制与硬上限 → `references/questioning.md`。

### 3 落地

以**该组件的预设提示词**为内容主体，按项目的**组件创建提示词**落地（命名 / 目录 / 样式来源）；项目若要求规格文档，按 `references/spec-template.md` 的七段产出。
样式值一律**指向样式源**，不复制、不新造。

### 4 回写

把**消歧结论**回写到项目的组件创建提示词（「这个场景用哪种形态」），下次不再问。
**写通用形态，不写组件名。**

## 提问硬规则（速查）

- 单轮 ≤3 题；**总轮次 ≤2 轮**。超限说明推断做得不够，应回退去读代码。
- **问数据，不问形态名**（用户不懂「级联」，但一定知道数据有没有层级）。
- **先读再问**：读数据源 → 读已有组件 → 二分提问 → 明确询问。
- **能推断的绝不问**；推断出的默认值要**显式告知**。
- 用预设选项，不用开放式问句。
