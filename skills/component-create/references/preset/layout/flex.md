# 弹性布局

用**主轴 / 交叉轴**模型对子元素进行一维排列、对齐与分配的布局容器，是页面局部排版的主力。

## 角色与边界

- **是什么**：一个只负责摆放直接子元素的容器，按方向排列，并对齐、分布、换行、伸缩子项。
- **解决什么**：一行或一列里如何排列若干元素、如何分配剩余空间、如何对齐、空间不足时如何伸缩或换行。
- **不解决什么**：
  - 不解决「二维网格、需要行列同时对齐」 → 栅格
  - 不解决「等间距堆叠、无需复杂伸缩」 → 间距组件
  - 不解决「间距由设计系统统一控制、希望集中管理」 → 间距组件
  - 不解决「内容区的整页结构（头 / 侧 / 主体）」 → 布局容器
- **什么时候不用**：只需给一组元素加统一间距 → 间距组件更简洁；需要严格的列对齐与响应式跨列 → 栅格。

---

## UI

### 结构解剖
- **容器**：弹性布局本体，设定方向与对齐
- **直接子项**：参与排布的元素；每个子项可单独设定伸缩、对齐、顺序
- **间隙**：相邻子项之间的统一间距
- **换行产生的行 / 列**：换行后形成的多行，其对齐由「多行对齐」控制

### 尺寸与外观变体
| 轴 | 取值 | 说明 |
|---|---|---|
| 方向 | 水平（行）/ 垂直（列）/ 反向 | 主轴方向，决定排列与对齐含义 |
| 主轴对齐 | 起点 / 居中 / 终点 / 两端 / 环绕 / 均分 | 子项在主轴上的分布 |
| 交叉轴对齐 | 起点 / 居中 / 终点 / 拉伸 / 基线 | 子项在交叉轴上的对齐 |
| 换行 | 不换行 / 换行 / 反向换行 | 空间不足时是否折行 |
| 多行对齐 | 起点 / 居中 / 终点 / 两端 / 均分 / 拉伸 | 换行后各行之间的分布 |
| 间距 | 统一间距（可选分主轴 / 交叉轴） | 子项间隙 |
| 内边距 | 组件内留白 | 与内容的呼吸距离 |

- **方向的语义要注意**：「主轴对齐」的含义随方向反转（水平时是左右分布，垂直时是上下分布），描述时应绑定方向而非固定为「水平居中」。

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| default | 按配置排布，无自身颜色 / 边框 |
| 空间不足（不换行） | 子项按伸缩比例压缩，或溢出（取决于是否允许溢出） |
| 空间不足（换行） | 折到下一行 / 列 |
| 子项被拉伸 | 交叉轴为拉伸时子项填满交叉轴 |

- 弹性布局自身**无 hover / focus / disabled**：它是布局，不是控件。
- 子项的交互态由子项自己负责，布局容器不参与。

### 布局与对齐
- **拉伸（交叉轴）**是默认高危项：会把所有子项拉成同一高度 / 宽度，非预期时需显式改为起点 / 居中。
- **基线对齐**用于把带文字的项按文字基线对齐（如标签 + 输入），跨字号时最稳。
- 不换行且空间不足时，子项会持续压缩：需明确哪些子项允许压缩、哪些必须保持（设最小尺寸 / 不允许收缩）。
- 换行后行间距与交叉轴间距是两个独立概念，不要混为一谈。
- 与滚动结合时：主轴方向的滚动容器与弹性布局嵌套要明确谁负责滚动。
- 子项自身的对齐配置会覆盖容器的交叉轴对齐，需明确优先级，避免「设了不生效」。

### 移动端
- 方向常需随断点在「行 ↔ 列」间切换（横向工具条在窄屏变竖排）。
- 不换行的一行内容在窄屏易挤压变形 → 允许换行或改变方向。
- 触摸目标（子项若可点）≥ 44×44，布局需为其留够空间。
- 断点切换方向时，间距的主轴 / 交叉轴含义随之改变，配置需一并调整。

## 交互

### 核心行为
- 无「打开 / 关闭」概念：布局随容器尺寸变化自动重排。
- 子项的交互由子项承担，布局只在尺寸变化时重新计算分布。

### 指针与手势
- 布局本身不响应指针（除非附带滚动）。
- 触摸端主要变化来自屏幕旋转 / 尺寸变化触发的重排。

### 键盘
| 场景 | 行为 |
|---|---|
| 布局容器 | 不进入键盘序列 |
| 子项可聚焦时 | 按 DOM 顺序与视觉顺序应一致 |

- **视觉顺序与 DOM 顺序一致性**：用方向反转或改变子项顺序时，键盘 / 屏幕阅读顺序必须跟随视觉，否则顺序错乱。

### 焦点管理
- 布局不接收焦点；不改变子项既有焦点顺序。
- 使用「改变排列顺序」时须保证可访问顺序与视觉顺序一致。

### 动画与过渡
- 重排本身通常瞬时；若需过渡（如折叠伸缩），仅对尺寸 / 位移做短过渡，避免整页动画。
- 换行导致的重新布局不做动画。

### 反馈
- 无（布局不产生反馈）。

### 边界交互
- 容器尺寸为 0 / 未定 → 布局塌缩，需给明确尺寸来源。
- 子项超出容器（不换行且不可压缩）→ 溢出，需明确是裁切还是滚动。
- 嵌套多层弹性布局 → 伸缩比例互相干扰，层级应保持浅。

## 数据流

### 输入
- 方向、主轴对齐、交叉轴对齐、换行与多行对齐、间距、内边距。
- 子项各自的伸缩、对齐、顺序、最小 / 最大尺寸。
- 部分配置随断点变化（响应式）。

### 内部状态
- 无业务状态；仅在需要时记录当前生效的断点。

### 输出
- 无业务事件；不抛值。可能抛出「尺寸变化」用于外部联动（可选，少见）。

### 受控 / 非受控
- 布局无受控 / 非受控之分：全部由配置驱动，无自身可变值。

### 异步与竞态
- 无异步。若子项异步加载导致尺寸变化，布局需能稳定重排，不出现跳动。

### 校验与错误
- 无校验。

### 回填与序列化
- 无值概念；配置来自数据时同步刷新。

## 无障碍
- 布局是**结构性容器**，应从可访问树中被当作中性容器，不额外朗读。
- **视觉顺序必须与 DOM / 可访问顺序一致**，否则屏幕阅读器与键盘顺序与用户所见不符（严重的可用性问题）。
- 方向反转等纯视觉手法不能反向于 DOM 顺序。
- 若布局用于整页结构（如「下单栏 + 主内容」），其区域应有对应的地标语义。
- 换行只是视觉折行，不应改变阅读顺序。

---

## 常见误用
- 用弹性布局做二维对齐 → 应换栅格；硬用会靠嵌套凑，结构复杂。
- 交叉轴误用「拉伸」→ 子项被强行等高，视觉失真。
- 只为一组元素加间距却上弹性布局 → 用间距组件更直接。
- 反向排列却不调整可访问顺序 → 键盘 / 朗读顺序与视觉相反。
- 不换行又不设可压缩界限 → 窄屏内容被压扁或溢出。
- 用改变子项顺序来「视觉排序」→ 破坏读屏顺序。
- 深层嵌套弹性布局 → 伸缩关系不可预测。

## 边界与代价
- **视觉顺序 ≠ DOM 顺序** 是硬缺陷，必须避免。
- 二维排布用弹性布局 → 必然多层嵌套，可维护性下降。
- 空间不足且不换行 → 需显式定义压缩 / 溢出策略，否则随机挤压。
- 容器尺寸无来源 → 布局塌缩。
- 深层嵌套 + 多级伸缩 → 行为难以预测，应保持层级浅。
- 子项最小尺寸未设 → 压缩到不可读，须为不可压缩项设下限。
- 容器未定尺寸就依赖拉伸 → 交叉轴拉伸无参照，结果不可预期。
