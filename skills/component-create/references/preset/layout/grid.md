# 栅格

把一行划分为**若干等宽列**、通过断点响应式调整跨列的二维排版系统，用于页面主结构的对齐。

## 角色与边界

- **是什么**：以列（常见 12 / 24 列）为基准的二维布局系统；通过行与列、跨列、偏移、断点来排布内容。
- **解决什么**：多个区块需要**按列对齐**、在不同屏宽下按列数重新分配（如小屏堆叠、大屏并排）。
- **不解决什么**：
  - 不解决「单行 / 单列的简单排列」 → 弹性布局
  - 不解决「只加统一间距」 → 间距组件
  - 不解决「整页的头 / 侧 / 主体结构」 → 布局容器（栅格常作为其内容区内部工具）
  - 不解决「不规则、任意位置的自由布局」 → 定位 / 弹性布局
- **什么时候不用**：只有一两个元素横向排布 → 弹性布局足矣；只需换行堆叠、无按列对齐需求 → 间距 + 弹性布局更简单。

## UI

### 结构解剖
- **行容器**：承载若干列，负外边距抵消列的槽宽
- **列子项**：可指定跨列数、偏移、对齐、断点行为
- **槽宽（列间隙）**：列之间的水平间隙；可区分水平 / 垂直槽宽
- **断点**：屏宽阈值，每个阈值对应一套跨列 / 偏移配置
- **外层容器（可选）**：带最大宽度的居中内容容器

### 尺寸与外观变体
| 轴 | 取值 | 说明 |
|---|---|---|
| 总列数 | 12 / 24 / 自定义 | 决定跨列粒度 |
| 列跨数 | 1 至总列数 | 单个列占几列 |
| 偏移 | 0 至总列数 | 左移留白，形成错位 |
| 对齐 | 水平起点 / 居中 / 终点 / 两端 / 均分 | 列在行内的分布 |
| 垂直对齐 | 起点 / 居中 / 终点 / 拉伸 | 一行内不等高列的对齐 |
| 槽宽 | 常见 8 / 16 / 24 等 | 由间距体系决定，不写死 |
| 断点 | 超小 / 小 / 中 / 大 / 超大（按需） | 每个断点可独立设跨列、偏移、显示隐藏 |
| 外层容器 | 有 / 无 | 有则居中并限制最大宽度 |

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| default | 按当前断点的配置排布 |
| 断点切换 | 跨列 / 偏移 / 顺序重算，可能由并排变为堆叠 |
| 列被隐藏 | 在指定断点不显示（需谨慎，见无障碍） |

- 栅格自身**无 hover / focus / disabled**，是纯布局系统。
- 列内子元素自行负责交互态。

### 布局与对齐
- **列数选型**：12 列适合大多数（2 / 3 / 4 / 6 均可整除），24 列粒度更细更灵活；选型一旦定下，全站统一。
- **槽宽用间距体系的值**，不要随手写魔法数字。
- 行容器需要**负外边距**抵消列内边距，否则最外侧会多出槽宽；这一点常被忽略导致左右不对齐。
- 偏移产生的是「前置留白」，与「跨列 + 空列」效果不同，语义要清楚。
- 相邻多行之间的**垂直间距**要单独给出，栅格只解决水平分配。
- **是否做外层容器要明确**：栅格本身只管列分配；整页居中与最大宽度通常由外层容器承担，二者职责不能混。

### 移动端
- 小屏默认常见做法：**先堆叠（每个列占满宽度）**，再按断点并排。
- 移动端列槽宽可适当缩小，但要保留基本呼吸空间。
- 在窄屏用「隐藏列」表达信息取舍要注意：隐藏的是次要信息，不要隐藏关键内容。
- 触摸端列内可点元素需 ≥ 44×44。

## 交互

### 核心行为
- 无开合 / 选中行为；随视口尺寸变化自动切换断点并重排。

### 指针与手势
- 栅格不响应指针，仅随窗口 / 容器尺寸变化重排。
- 触摸端主要变化来自屏幕旋转与缩放。

### 键盘
| 场景 | 行为 |
|---|---|
| 栅格容器 / 列 | 不进入键盘序列 |
| 列内可聚焦元素 | 视觉顺序（跨列、偏移、顺序调整后）应与 DOM 顺序一致 |

- **用跨列 / 偏移 / 顺序制造视觉布局时，不得让可访问顺序错乱**：偏移产生的留白不改变顺序，但「排序」类属性会，需谨慎。

### 焦点管理
- 栅格不接收焦点，也不改变列内焦点顺序（除非使用了顺序调整，需保证一致）。

### 动画与过渡
- 断点切换导致的列宽 / 位置变化通常瞬时，不做动画。
- 列内展开收起若带动尺寸，只对内容做过渡，不整行动画。

### 反馈
- 无。

### 边界交互
- 视口跨过断点边界时可能出现瞬间抖动 → 过渡应平稳，避免在临界宽度来回跳变。
- 总列数在断点间不一致（如小屏 12 列、大屏 24 列）→ 容易算错跨列，需统一或显式换算。
- 嵌套栅格 → 以**父列宽度**为基准，容易与最外层栅格混淆，层级应克制。

## 数据流

### 输入
- 总列数、槽宽、断点定义。
- 每个列子项的跨列、偏移、对齐、顺序、显示隐藏，及各断点的覆盖值。
- 是否启用外层容器及其最大宽度。

### 内部状态
- 当前生效的断点（用于选择对应配置）。

### 输出
- 无业务事件；可抛出「断点变化」供外部联动（可选）。

### 受控 / 非受控
- 无受控 / 非受控之分：布局完全由配置与当前尺寸决定。

### 异步与竞态
- 无异步；监听尺寸变化需节流 / 合并，避免高频重排。

### 校验与错误
- 无校验。

### 回填与序列化
- 无值概念；断点配置来自数据时同步刷新。

## 无障碍
- 栅格是**视觉排版手段**，应从可访问树中作为中性容器，不额外朗读。
- **列隐藏必须伴随等价处理**：若某列内容在窄屏被隐藏，不要因此丢失关键信息（改为折叠 / 收纳，而非直接消失）。
- 视觉顺序（跨列、偏移、顺序调整）必须与可访问顺序一致。
- 栅格不能作为唯一的结构语义：整页区域应有对应地标语义。
- 列内可交互元素保持全键盘可达与焦点可见。

---

## 常见误用
- 用栅格做单行简单排列 → 弹性布局更轻。
- 忘记行容器的负外边距 → 左右两端多出缝隙，与页面不齐。
- 槽宽写魔法数字，脱离间距体系 → 全站间距不一致。
- 用「隐藏列」隐蔽关键信息 → 小屏用户信息缺失。
- 总列数混用（12 与 24 并存）→ 跨列计算混乱。
- 用栅格承载整页结构并省略外层容器 → 大屏内容横向拉满，可读性差。
- 用顺序调整做视觉排序却不改 DOM → 读屏与键盘顺序错乱。
- 深层嵌套栅格 → 基准宽度混乱，维护成本高。
- 断点数量过多 → 配置呈组合爆炸，维护成本高。
- 列内子元素自带外边距 → 与槽宽叠加，出现双重间距。

## 边界与代价
- **列隐藏必须给等价替代**，否则是信息可达性缺陷。
- 总列数需全站统一，混用会导致跨列语义漂移。
- 缺外层容器时大屏可读性下降，需明确由谁承担最大宽度。
- 嵌套栅格以父列宽为基准，深层嵌套难以推理。
- 断点配置随断点数量线性增长，断点过多会显著增加认知与维护成本。
- 槽宽与列内子元素外边距叠加 → 间距失控，需约定由谁负责间距。
