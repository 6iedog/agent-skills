# 分隔面板

把一块区域切成**两个或更多可调大小的面板**，通过拖拽中间的**手柄**改变各面板占比，可折叠。

## 角色与边界

- **是什么**：一个多面板容器，面板之间由可拖拽手柄分隔，用户可调整各面板尺寸并可折叠某一侧。
- **解决什么**：用户需要**自行调节**两块内容的空间分配——代码 / 预览、目录 / 正文、列表 / 详情。
- **不解决什么**：
  - 不解决「固定宽度、不可调的分栏」 → 布局容器 / 弹性布局
  - 不解决「侧栏折叠但不调宽」 → 布局容器的抽屉 / 折叠
  - 不解决「等分网格」 → 栅格 / 弹性布局
  - 不解决「面板内内容的滚动与取消码」 → 面板内容自行处理
- **什么时候不用**：面板比例固定、无需用户调节 → 用固定布局更简单；面板切换比调宽更合适（如标签页切换）→ 用标签页。

---

## UI

### 结构解剖
- **面板**：被分隔的内容区，各自可设初始尺寸、最小 / 最大尺寸
- **手柄**：面板之间可拖拽的窄条，是唯一交互区
- **折叠按钮（可选）**：手柄上或面板边缘的一键折叠 / 展开控件
- **面板内容容器**：面板内部的滚动与内边距容器

### 尺寸与外观变体
| 轴 | 取值 | 说明 |
|---|---|---|
| 方向 | 水平（左右分）/ 垂直（上下分） | 决定拖拽轴 |
| 面板数 | 2 个 / 多个 / 嵌套 | 多个手柄、可嵌套分组 |
| 尺寸单位 | 像素 / 百分比 | 影响缩放时行为，需明确 |
| 手柄外观 | 细线 / 可见条 / 带抓点 | 越明显越好发现，但别喧宾夺主 |
| 折叠 | 不可折叠 / 可折叠单侧 / 双侧 | 折叠后保留唤起入口 |
| 面板约束 | 最小 / 最大尺寸 | 防止拖到不可用 |
| 吸附 | 无 / 吸附到关键位置 | 如吸附到 0、50%、100% |

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| default | 手柄常态（常为细线或低对比条） |
| hover（手柄） | 手柄加粗 / 变色，明确「可拖拽」 |
| active / dragging | 手柄高亮，光标变更，拖拽中可能显示尺寸提示 |
| focus-visible（手柄） | 明显焦点环，表明可用键盘调整 |
| collapsed | 一侧折叠为最小宽度或隐藏，保留唤起控件 |
| disabled | 手柄不可拖（少数场景） |
| 到达边界 | 手柄到达最小 / 最大尺寸时停止，光标提示受限 |

- 手柄必须**可被发现**：纯 1px 细线在触摸端几乎抓不住，也难被注意到。

### 布局与对齐
- 手柄宽度占位要计入总宽，避免累计误差。
- 面板尺寸受限时，拖拽应在边界处**硬停**，并给出触顶反馈（如光标变化）。
- 折叠后面板隐藏，但**唤起入口必须仍在**（手柄或按钮），否则无法还原。
- 嵌套分隔时，内外手柄的拖拽轴不同，需各自独立。
- 面板内的滚动与手柄拖拽不能冲突（手柄在滚动区外）。

### 移动端
- 拖拽手柄在触摸端命中区要放大（≥ 44×44 的等效宽度），细线不可用。
- 移动端可考虑**不提供拖拽**，改为折叠 / 抽屉切换，或仅保留预设比例。
- 若保留拖拽，需避免与页面滚动手势冲突（明确手势轴）。
- 手柄位置避开系统边缘手势区。

## 交互

### 触发与拖拽
- 主操作：**拖拽手柄**改变相邻面板尺寸。
- 折叠：点手柄上的折叠控件或双击手柄（可选）。
- 键盘：聚焦手柄后按方向键调整（见键盘表）。
- 拖拽方向与手柄方向垂直（水平手柄左右拖，垂直手柄上下拖）。

### 尺寸调整行为
- 拖拽时相邻面板**此消彼长**，总量守恒（一块变宽另一块变窄）。
- 受最小 / 最大尺寸约束，到达边界即停止，不越界。
- 可选：吸附到关键位置（0% / 50% / 100%）便于精确对半。
- 双击手柄可恢复默认比例（可选）。

### 键盘
| 键位 | 行为 |
|---|---|
| `Tab` | 聚焦到手柄（手柄必须可聚焦） |
| `←` / `→`（水平） | 减小 / 增大左侧面板，按固定步长移动 |
| `↑` / `↓`（垂直） | 减小 / 增大上方面板 |
| `Home` | 移到最小尺寸 |
| `End` | 移到最大尺寸 |
| `Enter` / `Space` | 折叠 / 展开（若手柄支持折叠） |
| 修饰键 + 方向键 | 加大步长（可选） |

- **手柄的可访问名称要说明它分隔了什么、当前比例或折叠状态**。
- 手柄当前值（比例）应作为可访问值暴露，键盘调整后同步更新。

### 指针与手势
- 拖拽：按下手柄 → 跟随 → 松手定稿；拖拽中光标变更。
- 触摸：按住手柄拖动；命中区放大；拖出边界即被约束。
- 拖拽不应触发页面滚动或文本选择。

### 焦点管理
- 手柄可聚焦且焦点环可见；拖拽后焦点保留在手柄。
- 折叠后若手柄隐藏，焦点需移到唤起控件或相邻面板。
- 键盘调整后焦点不丢失。

### 动画与过渡
- 拖拽过程**实时跟手**，无延迟动画。
- 折叠 / 展开用短过渡（约 150–250ms）。
- 恢复默认比例可用短缓动，避免瞬移。

### 反馈
- hover 手柄变可见即提示可拖拽。
- 拖拽中可显示尺寸数值 / 比例提示（可选）。
- 到达最小 / 最大尺寸时给触顶反馈。

### 边界交互
- 窗口或容器尺寸变化时，按单位重新计算面板尺寸，不出现负宽度。
- 面板内容超出 → 面板内滚动，不撑破手柄约束。
- 折叠后容器总宽不变（另一面板填补或留白，策略需明确）。
- 极端窄屏下应禁用拖拽或强制折叠。

## 数据流

### 输入
- 面板定义：初始尺寸 / 比例、最小 / 最大尺寸、单位、是否可折叠。
- 方向、手柄外观、吸附策略、默认比例。
- 各面板内容（由使用方提供）。

### 内部状态
- 各面板当前尺寸 / 比例。
- 是否正在拖拽。
- 各面板折叠状态。

### 输出
- **尺寸变化事件**：拖拽结束或过程中抛出新比例 / 尺寸，供外部持久化。
- 折叠 / 展开事件。
- 不携带业务表单值。

### 受控 / 非受控
- 尺寸默认非受控（内部自管），但因用户偏好需持久化，常由外部受控或收到变化事件后写存储。
- 折叠态可受控（与布局容器的折叠统一管理）。
- **二选一必须明确**，混用会出现「拖了又跳回」。

### 异步与竞态
- 无业务异步；拖拽过程若需持久化，应防抖后写入，避免高频写。
- 尺寸在窗口变化与用户拖拽同时发生时，以最近的用户意图为准。

### 校验与错误
- 无业务校验；面板尺寸约束（最小 / 最大）是内置的合法性保证。

### 回填与序列化
- 用户调节的比例应持久化，回填后按单位还原。
- 单位混用（像素 / 百分比）时，回填需按当前容器尺寸换算，否则窗口变化后比例失真。

## 无障碍
- 手柄必须是**可聚焦、可用键盘操作**的控件，不能只支持鼠标拖拽。
- 手柄应有**可访问名称**，说明它分隔的两块内容；并暴露当前比例 / 折叠状态。
- 键盘方向键调整是必备能力；`focus-visible` 必须可见。
- 折叠后隐藏的面板内容应移出可访问序列；唤起控件可被键盘到达。
- 手柄的命中区在触摸端要足够大（等效 ≥ 44×44）。
- 调整后不应打断屏幕阅读器朗读；值变化可被感知但不刷屏。

---

## 常见误用
- 手柄做成 1px 细线且无 hover 提示 → 用户发现不了、抓不住。
- 只支持鼠标拖拽、无键盘路径 → 无障碍缺失。
- 拖拽可把面板拖到 0 宽 → 内容不可用且难恢复，必须设最小尺寸。
- 折叠后不保留唤起入口 → 无法还原。
- 触摸端直接照搬桌面细手柄 → 无法拖动。
- 尺寸单位混用且不换算 → 窗口变化后比例错乱。
- 手柄放在面板滚动区内 → 拖拽与滚动冲突。
- 拖拽过程频繁写存储 → 卡顿。

## 边界与代价
- **键盘可达是硬要求**，只有拖拽不接受。
- 最小 / 最大尺寸约束是必需品，否则拖坏布局无法恢复。
- 折叠必须保留唤起入口，否则功能不可逆。
- 触摸端必须放大命中区，否则不可用。
- 单位混用不做换算 → 响应式下比例漂移。
- 深层嵌套分隔 → 手柄轴与约束相互纠缠，应限制嵌套。
