# 分割线

用一条**细线**在视觉上分隔相邻内容，表达「这是两组不同的东西」；也可带文字充当小标题。

## 角色与边界

- **是什么**：一条水平或垂直的细线，作为内容之间的视觉分隔；可选在中段放一段文字，兼作组标题。
- **解决什么**：在同一区域内把不同语义的内容块分开，降低混读；在垂直排列里区分上下组，在水平排列里区分左右组。
- **不解决什么**：
  - 不解决「需要分组标题且要有层级」 → 标题组件 / 分组容器
  - 不解决「需要卡片级别的边界」 → 卡片 / 面板
  - 不解决「列表项之间的分隔」 → 列表项自身的内建分隔（避免双重线）
  - 不解决「空间分隔但不画线」 → 间距组件
- **什么时候不用**：用间距就能表达分开（如卡片之间的白）→ 不要画线；列表已自带分隔 → 不要叠加；页面结构靠背景色区分 → 不再加线。

---

## UI

### 结构解剖
- **线体**：一条细线，水平或垂直
- **中间文字（可选）**：位于线中段的一段文字，两侧各留线
- **文字与线的对齐**：居中 / 靠左 / 靠右
- **容器 / 包裹层（可选）**：为线提供间距的包裹元素
- **线宽与端点**：线宽全站统一；端点可直角或圆角，需与整体圆角语言一致
- **颜色来源**：取自边框 / 分隔体系变量，而非硬编码色值（保证主题可切换）

### 尺寸与外观变体
| 轴 | 取值 | 说明 |
|---|---|---|
| 方向 | 水平 / 垂直 | 水平用于上下分隔，垂直用于左右分隔 |
| 带文字 | 无 / 有 | 有文字时线在两侧断开 |
| 文字对齐 | 居中 / 靠左 / 靠右 | 影响视觉重心 |
| 线型 | 实线 / 虚线 | 虚线更弱，用于暗示分组又可再合并 |
| 粗细 | 细（常规）/ 粗（强调） | 强调慎用，易像标题下划线 |
| 颜色 | 弱 / 常规 / 强 | 由层级决定，默认最弱 |
| 内边距 | 紧凑 / 常规 / 宽松 | 影响与上下内容的距离 |
| 端点 | 直角 / 圆角 | 需与整体圆角语言一致 |
| 主题适配 | 浅色 / 深色 | 颜色随主题切换，不写死单一灰 |

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| default | 常态线条颜色与厚度 |
| hover | 一般无 hover（非交互）；若被做成可点击则需完整交互态 |
| disabled | 无此概念 |

- 分割线是**静态元素**：默认无 hover / active / focus。若把它做成可拖拽或可点击（如分隔面板的手柄），那是另一个组件，需另附完整交互态。

### 布局与对齐
- **水平线**：宽度默认占满父容器；`inset` 变体可左侧留白对齐文字起点。
- **垂直线**：高度由父容器决定，需有明确高度来源，否则会塌缩不可见。
- 带文字时：文字与两侧线的垂直居中要一致，文字留白均匀。
- 与相邻内容的间距统一，避免贴住上方或下方文本。
- 分割线不应成为 flex / grid 中被拉伸变形的对象；垂直线的 stretch 行为要显式定义。
- 分割线不引入额外层级（z-index），避免盖住相邻内容或浮层。
- 多个分割线之间的内容块，其上下距离应保持一致的节奏，避免疏密不均。

### 移动端
- 垂直线在窄屏可能挤压内容，考虑改用水平线或间距。
- 带文字的分割线文字要短，否则两侧留白被吃掉。
- 触摸端无特殊处理，但要避免被误认为可点击。
- 窄屏用垂直分割线分隔横向元素通常得不偿失，改用间距更稳。
- 若方向在断点间切换（水平 ↔ 垂直），需明确切换点，避免临界宽度抖动。

## 交互

### 核心行为
- 默认**无交互**：不聚焦、不响应点击、不参与键盘序列。
- 若作为可拖拽分栏手柄（分隔面板），则它承载拖拽与键盘调整，属于另一类组件。

### 指针与手势
- 无（非交互）。
- 若被误用为可点击项，必须补齐 hover / focus / 命中区，否则不可用。

### 键盘
| 场景 | 行为 |
|---|---|
| 普通分割线 | 不进入键盘序列，不可聚焦 |
| 承载可交互手柄时 | 交由手柄组件定义（见分隔面板的键盘规范） |

### 焦点管理
- 不接收焦点；不得成为 Tab 停靠点。

### 动画与过渡
- 无动画；出现 / 消失不应引起布局抖动（应占位或静默移除）。

### 反馈
- 无。

### 边界交互
- 垂直线在父容器高度不定时会消失 → 必须给高度来源。
- 连续多条分割线叠加（列表 + 区域分隔）→ 出现双线，需删除其一。
- 分割线在深色 / 浅色主题下颜色要各自可辨，不能写死单一灰。
- 内容为空或未加载时不渲染多余线条，避免出现两条孤立的线。
- 分割线动态增删时不应引发布局抖动（占位或静默移除）。

## 数据流

### 输入
- 方向、线型、颜色层级、是否带文字、文字内容与对齐、内边距。
- 全是静态配置，无业务数据。

### 内部状态
- 无。

### 输出
- 无（非交互，不抛事件）。

### 受控 / 非受控
- 不适用；纯展示，全部由外部配置决定，无自身状态。

### 异步与竞态
- 无。

### 校验与错误
- 无。

### 回填与序列化
- 无值概念；文字来自配置或数据时同步刷新。

## 无障碍
- 分割线是**装饰性**的：应从辅助技术的可访问树中隐藏，不被逐一朗读。
- **不得用分割线承载语义分组**：真正的分组应使用有语义的分组容器或标题（辅助技术靠语义分组，而非视觉线条）。
- 若分割线同时充当组标题（带文字），该文字应有正确的**标题层级**，而不是仅作为普通文本。
- 垂直线不得作为布局承载结构的唯一手段（屏幕阅读器感知不到）。
- 不要用分割线表达「必填 / 错误」等状态语义，状态应由表单控件自身表达。

---

## 常见误用
- 列表项已自带分隔线，又在列表外加分割线 → 双重线。
- 用分割线充当分组标题，但不给标题语义 → 辅助技术无法感知分组。
- 用分割线替代间距 → 一屏满是线条，视觉噪音。
- 垂直分割线未给高度来源 → 渲染不出来。
- 把分割线做成可点击对象却不加交互态与命中区。
- 分割线颜色写死，在暗色主题下看不见。
- 用分割线充当表格列 / 行分隔 → 表格应使用自身边框，避免线条打架。
- 把粗分割线当标题下划线 → 与标题语义混淆，用户误以为是一组标题。

## 边界与代价
- 分割线**不承担语义**，分组必须靠语义容器 / 标题，否则无障碍缺失。
- 与列表内建分隔叠加 → 必然出现双线，属典型误用。
- 垂直线依赖父容器高度，高度不定即失效。
- 用线条代替留白表达分隔 → 视觉负担上升。
- 把装饰元素误做成交互元素 → 需要补齐一整套交互与可访问规则，否则半成品。
- 颜色 / 粗细硬编码 → 主题切换与设计体系调整时失效，需走变量。
- 带文字分割线不更新标题层级 → 结构语义缺失，辅助技术无法导航。
