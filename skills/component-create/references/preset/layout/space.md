# 间距

给一组元素加**统一间距**的轻量容器：沿一个方向排列，相邻项距离一致，可换行、可插分隔符。

## 角色与边界

- **是什么**：一个只负责「排列 + 统一间距」的容器，用同一个间距值管住所有相邻子项。
- **解决什么**：一组元素之间的间距要**集中统一**，而不是逐个元素写外边距导致不一致；以及行内元素组的紧凑排列。
- **不解决什么**：
  - 不解决「需要伸缩、对齐、分配剩余空间」 → 弹性布局
  - 不解决「二维按列对齐」 → 栅格
  - 不解决「整页骨架」 → 布局容器
  - 不解决「不画线就要分隔」的语义分组表达 → 分组容器 / 标题
- **什么时候不用**：需要元素伸缩、对齐、换行分配 → 弹性布局；只需要上下留白、无排列语义 → 直接外边距即可。

---

## UI

### 结构解剖
- **容器**：排列方向 + 间距的设置本体
- **子项**：被统一间距包裹的元素
- **分隔符（可选）**：插在相邻子项之间的视觉符号（竖线 / 圆点）
- **换行后的行**：子项过多换行后形成的行
- **行间距（可选）**：换行后各行之间的距离，可与项间距不同
- **对齐基线**：水平排列时子项按文字基线或视觉中心对齐

### 尺寸与外观变体
| 轴 | 取值 | 说明 |
|---|---|---|
| 方向 | 水平 / 垂直 | 决定间距作用于横向还是纵向 |
| 间距大小 | 小 / 中 / 大（或取自间距体系） | 相邻子项的统一距离 |
| 换行 | 不换行 / 换行 | 空间不足时是否折行 |
| 对齐 | 起点 / 居中 / 终点 / 两端 / 均分 | 主轴分布（继承自弹性能力） |
| 分隔符 | 无 / 自定义符号 | 插在相邻项之间 |
| 紧凑模式 | 关 / 开 | 关时加分隔符，开时去掉分隔符 |
| 内边距 | 无 / 有 | 容器自身留白 |
| 行间距 | 与项间距同 / 单独设定 | 换行后各行之间的距离 |

- **间距值必须取自统一的间距体系**，不要随手写数——本组件的意义就是消除「各处间距不一」。

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| default | 按统一间距排列 |
| 换行 | 超过一行后折行，行间距沿用统一间距或单独设定 |
| 分隔符显示 | 在相邻项之间渲染符号 |
| 空间不足（不换行） | 子项挤压或溢出 |

- 间距组件无 hover / focus / disabled；子项交互态由子项负责。

### 布局与对齐
- **只加间距，不改子项尺寸**：子项保持自身尺寸，间距组件不压缩它们（这一点是与弹性布局的关键区别）。
- **首尾不留间距**：只加「相邻之间」的间距，容器首尾不应多出间距，否则与外部对齐错位。
- 换行后的行间距要明确：是可选项，默认常与项间距一致。
- 分隔符与相邻两项的间距要均匀，分隔符不能歪斜。
- 垂直排列时容器宽度要给定或由内容决定，避免撑满导致子项被拉宽。
- 水平排列时子项高度不一时，需明确按中心或基线对齐，避免参差。
- 分隔符只出现在相邻项之间：行首 / 行末不得出现孤立分隔符。

### 移动端
- 换行在窄屏很常见：确保折行后仍可读、不挤压。
- 若用于工具栏式一排元素，窄屏应允许换行而非溢出。
- 触摸端子项命中区 ≥ 44×44，间距组件本身不限制子项大小。
- 换行后分隔符在行末应隐藏，避免每行尾巴挂一条竖线。

## 交互

### 核心行为
- 无交互：不响应点击、不聚焦、无开合；仅在尺寸变化时重排。

### 指针与手势
- 无。

### 键盘
| 场景 | 行为 |
|---|---|
| 间距容器 | 不进入键盘序列 |
| 子项可聚焦时 | 焦点顺序与视觉顺序一致 |

### 焦点管理
- 不接收焦点，不改变子项焦点顺序。

### 动画与过渡
- 无；换行与间距变化瞬时完成，不做动画。

### 反馈
- 无。

### 边界交互
- 分隔符在换行处是否保留：行末 / 行首不应出现孤立分隔符。
- 嵌套间距容器 → 间距叠加，容易产生过大空白，需克制。
- 子项动态增删 → 间距自动重算，不残留旧间距。
- 子项尺寸差异极大（如文字与图片混排）→ 需明确对齐方式，否则视觉参差。

## 数据流

### 输入
- 方向、间距大小、是否换行、对齐方式、分隔符、紧凑模式、内边距。
- 子项列表（作为内容）。

### 内部状态
- 无业务状态；仅在换行模式下可能记录当前行数（一般不必暴露）。

### 输出
- 无事件、不抛值。

### 受控 / 非受控
- 不适用：纯展示容器，完全由配置决定。

### 异步与竞态
- 无。

### 校验与错误
- 无。

### 回填与序列化
- 无值概念。

## 无障碍
- 间距是**纯视觉**的，应从可访问树中作为中性容器，不额外朗读。
- **不得用间距替代真实语义分组**：分组的可访问界线应靠分组容器 / 标题，而不是「看起来分开了」。
- 分隔符是装饰性插画 / 符号，应标记为装饰，不被朗读。
- 子项顺序即 DOM 顺序，视觉与可访问顺序一致。
- 换行不改变阅读顺序。
- 若间距被用来暗示操作分组（如「危险操作放到一边」），该区分不能只靠空白，需有语义或视觉边界。

---

## 常见误用
- 用间距组件承担伸缩 / 对齐 → 那是弹性布局的职责。
- 间距值随手写、脱离体系 → 与本组件「统一间距」的初衷相悖。
- 首尾多出间距 → 与外部容器对齐错位。
- 用间距制造「视觉分组」但不给语义 → 辅助技术感知不到分组。
- 分隔符不加装饰标记 → 被读成孤立符号。
- 嵌套间距容器 → 空白叠加过大。
- 用间距实现二维列对齐 → 应换栅格。
- 分隔符在换行后不隐藏 → 行末出现孤立竖线。
- 用首尾间距去对齐外部 → 应把对齐交给父容器，而非间距。

## 边界与代价
- 间距值不统一 → 本组件即失去意义，退化为「带方向的盒子」。
- 首尾间距不处理干净 → 对齐问题反复出现。
- 视觉分组无语义 → 无障碍缺失。
- 嵌套叠加 → 空白膨胀，需避免多层嵌套。
- 需要伸缩 / 对齐却用间距硬撑 → 尺寸不可控，必然回归弹性布局。
- 分隔符换行不隐藏 → 视觉出现孤立线条，需在换行处特殊处理。
