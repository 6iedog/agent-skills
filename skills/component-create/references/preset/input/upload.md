# 上传

选择一个或多个本地文件**提交到目标**，并展示上传过程与结果。

## 角色与边界

- **是什么**：触发文件选择 / 接收拖拽，管理文件列表、上传进度与结果的控件。
- **解决什么**：把本地文件传到服务端 / 远端，并让用户看清每份文件的状态。
- **不解决什么**：
  - 文件内容的编辑 / 预览 → 由预览器或编辑器承担
  - 富文本中的图片插入 → 富文本编辑器
  - 远端文件管理（重命名 / 移动 / 删除）→ 文件管理器
  - 大小 / 类型之外的业务校验规则 → 表单或服务端
- **什么时候不用**：只是选一个本地路径而不上传（如「导出到…」）→ 文件选择（无上传语义），不要套上传组件。

---

## UI

### 结构解剖
- **触发区**：按钮或拖拽区，点击打开系统选择器
- **拖拽提示**：图标 + 文案（「点击或拖拽文件到此处」）
- **文件列表 / 图片墙 / 卡片**：已选文件的呈现
- **单条**：图标 / 缩略图、文件名、大小、状态标记、操作（删除 / 重试 / 预览）
- **进度条**：单条进度与 / 或整体进度
- **状态标记**：等待 / 上传中 / 成功 / 失败
- **错误文案**：单条失败原因
- **限制说明**：数量 / 大小 / 类型约束提示
- **添加更多入口**：列表末尾继续添加

### 尺寸与外观变体
- 形态：**按钮 + 列表** / **拖拽区** / **图片墙**（缩略图网格）/ **卡片**
- 单文件 / **多文件**
- 是否可拖拽
- 是否可预览、是否可裁切（裁切多为外接）
- 是否显示进度
- **自动上传** 还是 **手动提交**（攒够后一起提交）
- 是否可排序 / 可多选删除
- 尺寸：小 / 中 / 大；状态类：默认 / 禁用 / 只读

### 视觉状态（逐条）
| 状态 | 触发区 / 列表 | 单条 |
|---|---|---|
| default | 常规边框 / 虚线框 | 常规条目 |
| hover | 边框加深，提示可点 | 显示删除 / 预览操作 |
| focus-visible | 明显焦点环 | 操作按钮焦点环 |
| drag-over（拖入） | 边框高亮 + 背景色变化，提示「松开即上传」 | — |
| uploading | 可显示整体进度 | 进度条 + 百分比 |
| success | — | 成功标记（对勾）+ 可选预览 |
| error | — | 失败标记 + 原因 + 重试入口 |
| disabled | 整体降透明、禁用指针 | 不可操作 |
| readonly | 外观同默认，但不可增删 | 可查看 / 下载 |
| empty | 拖拽区提示占位 | 无条目 |
| reupload（重传中） | — | 与 uploading 区分，避免误认首次上传 |

- **success 与 error 必须用不同颜色 + 不同图标**，不能只靠颜色。

### 布局与对齐
- **列表式**：一行一条，文件名过长截断
- **图片墙**：缩略图等宽等高（固定宽高比），网格留白一致
- 触发区位于列表上方或下方，全系统保持一致
- 进度条与文件名对齐，不遮挡操作按钮

### 移动端
- 拖拽在移动端弱，主用**点击选择**
- 触摸目标 ≥ 44×44；图片墙一般两列
- 大文件上传提示网络与流量

## 交互

### 核心操作
- 点击触发区 → 打开系统文件选择器
- 拖入文件到触发区 → 加入列表
- **自动上传 / 手动提交**二者必须明确，不能含混
- 删除单条 / 全部
- 失败重试单条

### 输入与选择行为
- 多文件：一次可多选；超过数量上限的处理（截断并提示 / 拒绝）
- **校验**：大小、类型（MIME / 扩展名）、数量、图片尺寸；不合格**即时拒绝并提示**，不进入上传队列
- 重复 / 同名文件处理（覆盖 / 跳过 / 并存）
- 拖入文件夹是否递归（通常不支持，须明说）
- 拖到列表特定位置排序（可选增强）

### 键盘
| 键 | 行为 |
|---|---|
| `Tab` | 触发区、每条的操作按钮分别可达 |
| `Enter` / `Space` | 触发文件选择 / 激活聚焦的操作 |
| `Delete` | 删除聚焦项（可选，需可撤销或确认） |

- **拖拽无法用键盘完成，必须提供「点击选择」等价路径**。

### 指针与手势
- 拖入高亮、拖离取消、松手加入
- 触摸滑动不触发上传（避免误触）
- 图片墙可拖拽排序（可选）

### 焦点管理
- 选择文件后焦点回到触发区或列表首项
- 删除一项后焦点移到相邻项，不丢到 body
- 上传中仍可聚焦进行取消 / 删除

### 动画与过渡
- 进度条平滑推进
- 条目进出淡入淡出
- 拖入高亮即时响应

### 反馈
- 进度、成功标记、失败原因与重试入口
- 校验失败**即时**提示（不等上传）
- 整体状态：全部完成 / 部分失败应有汇总提示

### 边界交互
- **上传中删除**：是否可取消（取消请求 + 移除条目），须定义
- **网络失败**：保留文件 + 允许重试，不清空列表
- **部分成功**：多文件中成功 / 失败混合的展示与整体状态须定义
- **大文件**：是否分片 / 断点续传须说明
- **离开页面拦截**：有未完成上传时提示用户确认离开

## 数据流

### 输入
- **文件约束**：大小上限、类型白名单、数量上限、图片尺寸
- 是否多文件、是否可拖拽、是否可预览
- 自动上传 / 手动提交；上传地址或自定义上传器
- **初始文件列表**（受控时）
- 附加参数（随文件一起提交的表单字段）

### 内部状态
- 文件列表：每项的原始文件、状态、进度、结果、服务端返回的 id / url
- 拖拽态
- 整体上传中 / 完成计数

### 输出
- **文件列表变化事件**
- **单文件成功 / 失败事件**（含服务端返回）
- 进度事件
- 手动模式的提交事件
- **值形态必须明确**：上传成功后对外暴露什么——原始文件对象、服务端 id、还是 url；这决定后续提交与回填

### 受控 / 非受控
- 受控文件列表：列表由外部持有，组件只抛变化
- **进度是瞬时状态，通常不上抛为受控值**，须明确边界，否则外部难以同步
- 非受控：内部持有列表

### 异步与竞态
- 多文件并发上传的**并发度**控制（避免请求风暴）
- 取消上传、单条重试
- 进度上报（含分片进度）
- **竞态**：同一文件重试时旧请求须作废，旧结果不得覆盖新结果
- 删除与上传中的冲突处理

### 校验与错误
- 前端校验（大小 / 类型 / 数量）**即时**；服务端校验失败须**映射回对应文件**
- 错误按文件呈现，不只弹全局提示
- 部分失败时整体状态与可提交性须定义

### 回填与序列化
- **已上传文件回填**：通常只有服务端 id / url，需构造「已完成」条目展示
- **提交时对外值**：id / url 数组还是原始文件数组，取决于「先上传后提交」还是「随表单提交」——必须明确
- **上传中不可提交**：提交动作要先检查是否仍在上传

## 无障碍
- 触发区 `role="button"`；拖拽区有明确的文本说明
- 文件列表用列表语义；每条状态用 `aria-live` 播报「上传完成 / 失败」
- 进度用 `progressbar` + `aria-valuenow` / `aria-valuemin` / `aria-valuemax`
- 删除 / 重试 / 预览按钮有可访问名称（不能只靠图标）
- **必须有键盘可达的选择路径**（拖拽的等价）
- `focus-visible` 可见（禁止无替代的 `outline: none`）

---

## 常见误用
- 只支持拖拽、无点击路径 → 键盘 / 移动端不可用
- 校验只在前端或只在后端 → 被绕过 / 体验差
- 上传中允许提交 → 提交数据不完整
- 无进度 / 无重试 → 大文件或弱网体验崩溃
- 失败只弹全局提示、不定位到文件
- 受控列表与内部进度混淆 → 状态不同步
- 未定义成功后暴露的值形态 → 提交数据错

## 边界与代价
- 大文件必须设计分片 / 续传 / 取消，否则易超时失败
- 并发度不控制 → 请求风暴
- 值形态（文件对象 vs id/url）不定义 → 提交数据错
- 上传中删除 / 重试不处理竞态 → 幽灵请求与状态错乱
- 无键盘替代路径 → 不可访问
- 校验不做即时反馈 → 用户填完才发现不合格
