# 表单

**收集、校验并提交**一组字段数据的容器。

## 角色与边界

- **是什么**：把若干字段组织成结构，负责值收集、校验、提交与错误汇总的容器。
- **解决什么**：一次提交多个相关字段，统一校验与提交，并管理字段之间的联动与动态变化。
- **不解决什么**：
  - 单个字段控件本身 → 各输入组件（本组件只组织与协调）
  - 数据的展示 → 描述列表 / 表格
  - 复杂多步 / 分支流程编排 → 分步表单 / 流程编排（本组件是最小提交单元）
  - 服务端业务校验 → 由接口返回，本组件负责映射呈现
- **什么时候不用**：只有一个字段、无校验、且即时生效 → 直接放该控件，不必包一层表单。
- **与「单个字段」的区别**：单字段控件只负责「一个值 + 自身错误态」；表单负责「一组值 + 何时校验 + 何时提交 + 错误汇总 + 动态字段增减 + 字段间联动」。

---

## UI

### 结构解剖
- **表单容器**：承载字段与提交逻辑
- **字段行**：标签 + 控件 + 帮助 / 错误文案
- **字段标签**：可含必填标记
- **必填 / 可选标记**：星号或文字
- **帮助文案**：字段下方的说明
- **错误文案**：字段级错误
- **错误汇总区**：表单级错误列表（可选，字段多时用）
- **操作区**：提交 / 重置按钮
- **分组 / 分节标题**：字段较多时分组
- **动态字段的增删入口**：增一行 / 删一行

### 尺寸与外观变体
- **布局**：垂直（标签在上，默认推荐）/ 水平（标签在左）/ 行内（横向紧凑，筛选场景）
- **标签对齐**：左对齐 / 右对齐
- **必填标记**：星号前置 / 后置 / 文字
- **校验反馈位置**：字段下 / 汇总区 / 两者都有
- **操作区位置**：底部 / 顶部跟随 / 侧边
- 状态类：默认 / 校验中 / 有错 / 提交中 / 禁用

### 视觉状态（逐条）
| 状态 | 字段 | 操作区 |
|---|---|---|
| default | 常规样式 | 提交按钮可点 |
| focus（当前字段） | 字段高亮 | — |
| filled | 显示已填值 | — |
| error | 字段标红 + 错误文案 | 提交后聚焦首个错误 |
| warning | 警告色 + 警告文案 | — |
| validating（异步校验） | 校验中标记 | — |
| disabled | 字段降透明、不可编辑 | 相关按钮禁用 |
| readonly | 可读不可改，值照常提交 | — |
| submitting | 字段通常锁定 | 提交按钮 loading、禁用重复提交 |
| success | （可选）成功态提示 | — |

- **disabled 与 readonly 必须分开**：disabled 不可聚焦、不进表单值；readonly 可聚焦、可复制、值照常提交。

### 布局与对齐
- 字段纵向堆叠，字段间距一致
- 水平布局标签列宽度一致并右 / 左对齐，控件起点对齐
- 行内布局控件对齐、换行规则明确
- **错误文案出现不应引起大幅跳动**：预留高度或平滑撑开
- 字段宽度：统一宽度 / 按内容（如日期窄、文本宽）须一致

### 移动端
- 垂直布局优先，标签在上
- 输入控件占满宽度；触摸目标 ≥ 44×44
- 键盘类型与字段匹配（数字 / 邮箱 / 电话）——由字段控件负责，表单保证 Tab 顺序与焦点流转

## 交互

### 核心操作
- **提交**：校验全部字段 → 全通过则提交；有错则阻止并**聚焦第一个错误字段**
- **重置**：恢复初始值并清空错误（是否也清空「已提交」标记须定义）
- **动态增删字段**：增 / 减一组字段，保留已填值与校验状态

### 输入与选择行为
- **校验触发时机**须逐字段或统一约定：提交时 / 失焦时 / 值变化时（实时）——三者体验差异大，必须明确
- **字段间联动**：某字段值影响其他字段的可用性 / 选项 / 必填
- **条件显示**：字段出现 / 隐藏时其值如何处理——**保留还是清除必须定义**
- 动态新增字段的初始值与校验规则
- 动态字段的字段名 / key 生成规则（不得冲突）

### 键盘
| 键 | 行为 |
|---|---|
| `Tab` | 在字段间顺序移动（顺序须与视觉顺序一致） |
| `Shift` + `Tab` | 反向移动 |
| `Enter` | 在单行文本中是否提交由控件决定；**多行文本中必须是换行**，不得误提交 |

- 表单层须保证：错误字段优先可达；`Enter` 提交不得在 `textarea` 内被误触发。

### 指针与手势
- 无特殊手势；移动端滚动与软键盘弹出不遮挡当前字段

### 焦点管理
- **提交失败：焦点移到第一个错误字段**并滚动使其可见
- 动态增删后焦点落点合理（新增字段的首个输入 / 删除后的相邻字段）
- 提交中锁定交互，避免边提交边改
- 重置后焦点回到表单起点或保持现状（须定义）

### 动画与过渡
- 错误文案出现 / 消失平滑，不引起布局抖动
- 字段增减动画（可选），不明显时可省略
- 分组折叠展开平滑

### 反馈
- 字段级错误**即时**呈现
- 提交中：按钮 loading + 禁止重复提交
- 提交成功：提示 / 跳转由外部决定
- 提交失败：错误映射回字段，或给全局提示；**不可两者都无**

### 边界交互
- **重复提交**：按钮 loading + 请求幂等
- **异步校验竞态**：后发先至时丢弃旧结果
- **提交失败但字段已被修改**：错误须与最新值对应，不能错位
- **条件字段隐藏后**其值的处理（见数据流）
- **离开页面有未保存修改**：拦截并提示
- 校验中 / 提交中再次点击提交的行为须定义

## 数据流

### 输入
- **字段定义**：字段名、标签、控件类型、初始值、校验规则、是否必填、是否禁用
- **布局配置**：垂直 / 水平 / 行内、标签对齐、列宽
- **提交方式**：接口 / 自定义提交器
- 校验策略：是否实时校验、触发时机
- 是否显示错误汇总

### 内部状态
- 各字段当前值（或由外部受控）
- 各字段错误状态与文案
- 校验中标记
- 提交中标记
- **脏标记**（是否被修改，用于离开拦截）
- 动态字段列表

### 输出
- **提交事件**：收集后的值对象（**仅在成功校验后**抛出）
- 值变化事件（可选，整体或逐字段）
- 校验失败事件（含各字段错误）
- 重置事件
- **值形态必须明确**：提交值对象的结构（扁平 / 嵌套）、字段命名、是否包含未填字段、动态字段如何表示

### 受控 / 非受控
- 表单整体可受控（外部持有值对象）或非受控（内部持有 + 初始值）
- **单字段也可各自受控**；两种模式不得混用到互相打架
- 受控表单下列表 / 数组类字段改动须抛**不可变新值**，不能原地改传入对象

### 异步与竞态
- **异步字段校验**（如唯一性）：防抖、竞态丢弃旧结果、提交时再复校一次
- **提交请求**：防重复、超时与失败重试策略
- **提交期间字段被改**：提交内容以「点击提交那一刻的快照」为准还是最新值，**必须定义**
- 多字段并行异步校验的完成顺序与错误聚合

### 校验与错误
- 规则类型：必填、长度、范围、正则 / 格式、自定义、**跨字段**（如两次输入一致）、**异步**（唯一性）
- 触发时机：提交 / 失焦 / 值变化 / 已触碰，逐字段或统一
- 错误呈现：字段下文案 + 字段标红；字段多时加**表单级汇总**
- **跨字段校验**：依赖字段变化后须**重新校验**所有相关字段
- **服务端错误映射**：把接口返回的错误按字段名回填到对应字段，无法映射的落到汇总或全局提示

### 回填与序列化
- 初值 → 字段显示：各控件负责自身回填（含「显示值 ≠ 提交值」的字段，如格式化、级联拆分）
- **未填字段是否提交**（空字符串 / `undefined` / `null`）必须定义，三者在后端语义不同
- **嵌套结构**（数组 / 对象字段）与**动态字段的 key 生成**须明确，避免冲突或丢失
- 提交值应是**构造出的新对象**，不复用可变的内部对象
- 重置就是回填初始值 + 清错误，须与回填走同一套逻辑

## 无障碍
- 表单容器 `role="form"` + 可访问名称
- 每个字段的标签与控件**正确关联**（`for` / `aria-labelledby`），不得只靠视觉邻近
- 必填用 `required` / `aria-required`；错误用 `aria-invalid` + `aria-describedby` 关联错误文案
- **错误汇总用 `aria-live`** 播报；提交失败后读屏能感知
- 字段分组用 `fieldset` + `legend`（或 `group` + `aria-labelledby`）
- 全键盘可达；Tab 顺序与视觉顺序一致
- 焦点落在错误字段时，其错误文案可被读出

## 常见误用
- 只在提交时校验且不提示 → 用户不知错在哪
- 实时校验过于激进（每敲一键就报错）→ 干扰输入
- 错误只弹全局提示、不定位字段 → 无法修正
- 动态字段隐藏时不清值也不校验 → 提交幽灵数据
- 提交按钮不防重复点击 → 重复提交
- 受控 / 非受控混用 → 值不同步
- 单字段页面硬包一层表单 → 过度设计
- 跨字段校验在依赖字段变化后不重算 → 结论过期

## 边界与代价
- 校验触发时机不定义 → 体验不一致（有的实时有的提交才报）
- 异步校验无竞态处理 → 得出错误的校验结论
- 值结构（嵌套 / 空值 / 动态 key）不定义 → 提交数据错
- 提交快照语义不明确 → 提交了用户没看到的值
- 无脏标记与离开拦截 → 数据丢失
- 服务端错误不做字段映射 → 用户无从修改
- 复杂多步流程硬塞进单表单 → 应改用分步表单
