# 数字输入

只接受数字（含小数、正负）的单行输入，带步进按钮与精度、范围约束。

## 角色与边界

- **是什么**：输入框的数值特化版，字符集限定为数字，支持步进、精度位数与上下限。
- **解决什么**：录入有大小 / 精度 / 范围语义的数值（数量、金额、百分比、比例、评分、权重）。
- **不解决什么**：
  - 任意文本 → 输入框
  - 日期 / 时间 → 日期 / 时间选择器
  - 带掩码的编码（电话、邮编）→ 掩码输入
  - 从少数离散值里选 → 选择类控件
  - 粗略地拖一个值 → 滑块（关注「大致区间」而非精确值）
- **什么时候不用**：取值范围小且需要快速直观地挑 → 滑块；只有加减两个动作的纯步进 → 独立的步进器即可，不必带键盘输入。

## UI

### 结构解剖
- **容器**：一行，含边框或底色
- **数值区**：可编辑的数字文本 + 光标 + 占位符
- **步进按钮**：一对「增 / 减」小按钮（上下堆叠 或 左右分列）
- **前缀 / 后缀**：单位（如货币符号、`%`、重量单位）或图标
- **帮助 / 错误文案**：容器下方一行

### 尺寸与外观变体
- 尺寸：小 / 中 / 大 → 影响高度、按钮尺寸、字号
- 步进布局：上下堆叠 / 左右分列 / 无步进（纯输入）
- 步进位置：容器内侧 / 容器外侧（无边框组合）
- 变体轴：精度位数、是否显示千分位、前后缀、是否可清空、是否只读 / 禁用

### 视觉状态（逐条）
| 状态 | 容器 | 数值区 / 按钮 |
|---|---|---|
| default | 边框默认 | 占位符浅色 |
| hover | 边框加深 | 按钮悬停背景微亮 |
| focus | 边框高亮 | 光标可见 |
| focus-visible | 明显焦点环 | — |
| composing（IME） | 同 focus | 光标带下划线 |
| readonly | 外观接近 default | 可聚焦、可复制、不可改 |
| disabled | 整体降透明 | 不可聚焦、按钮不可点 |
| error | 边框红 + 下方文案 | — |
| warning | 边框黄 + 下方提示 | — |
| at-min（达下限） | — | 减按钮置灰 |
| at-max（达上限） | — | 增按钮置灰 |
| stepping（长按中） | — | 按钮处于按下态 |

### 布局与对齐
- 数字建议**右对齐**（便于按位数比较）；带千分位时右对齐更佳——须与项目统一
- 步进按钮固定宽度，数值区自适应
- 前缀后缀与数字间距固定；单位不随滚动
- 超长数字内部横向滚动

### 移动端
- 调起数字键盘（按是否允许小数点、负号决定键位）
- 触摸目标 ≥ 44×44；步进按钮热区放大，或在小屏直接隐藏改用手输
- 长按连续步进在触摸端慎用

## 交互

### 触发与核心操作
- 输入数字字符；点步进按钮按步长增减
- **长按步进**：连续增减，节奏先慢后快
- `↑` / `↓`：按步长增减（是否启用须明确）
- 清空：清成**空值**，而非 `0`

### 输入行为
- 字符过滤：只接受数字、小数点、负号（视是否允许负 / 小数）；非法字符被拒
- 小数点：最多一个；小数点后的位数受精度限制
- 前导零：去除（或按格式化保留）——须明确
- 空值合法性：允许为空（未填）还是自动归零——**须明确**
- 全角数字 / 中文标点：须规范化为半角
- 粘贴：从文本中提取数字，或整段作为数字；非法则拒绝

### 键盘
| 按键 | 行为 |
|---|---|
| `↑` / `↓` | 按步长增减（是否启用须明确） |
| `Enter` | 提交当前值 |
| `Esc` | 还原为聚焦前值 |
| `Tab` | 移出焦点 |
| `Backspace` / `Delete` | 删除字符 |
| `PageUp` / `PageDown` | 大步增减（可选） |
| `Home` / `End` | 光标到行首 / 行尾 |

### 指针与手势
- 点步进按钮：单步；按住：连续（先慢后快）
- 触摸端长按步进慎用
- **滚轮**：悬停时滚轮改变数值——**强烈慎用**，页面滚动中误触会误改；若启用，须仅在聚焦后生效并阻止页面滚动

### 焦点管理
- 步进按钮点击后不应抢焦点，或点击完立即把焦点交回数值区
- 聚焦时全选或置末尾——须明确
- 边界处按步进：不改变值并给出可达反馈

### 动画与过渡
- 步进时数值即时变化，不加过场
- 状态色过渡约 100–150ms

### 反馈
- 触达下限 / 上限：对应按钮置灰或点击无效，可选轻提示
- 非法输入：拒绝录入或标红
- 精度溢出：按策略四舍五入、截断或拒绝——须明确

### 边界交互
- 到达边界：步进按钮、键盘、滚轮**一致夹取**
- 超长数字：横向滚动
- 显示位数与内部存储位数须一致（避免显示 `1.00`、存 `1`）

## 数据流

### 输入
- 配置：值 / 默认值、步长、精度（小数位）、上限与下限、是否允许负 / 小数、千分位、前后缀、尺寸状态
- 来源：外部传入

### 内部状态
- 编辑中的**原始串**（可能非法或未完成，如 `1.`、`-`）
- 焦点态、IME 组合态、是否长按中

### 输出
- **值变化事件**：数值 或 字符串——**形态必须明确**
- 输出时机：每次可解析就输出，还是提交时才输出——须明确
- 空值输出 `null` 还是 `0`——须明确
- 边界夹取后是否回写显示

### 受控 / 非受控
- 受控：值由外部持有，组件只抛新值；外部须回写格式化后的值，否则出现「输入 `1.005` 显示 `1.00` 又变回」
- 非受控：内部持有，给默认值
- **二选一必须明确**

### 异步与竞态
- 一般无异步；若存在联动计算（如换算）须防抖并丢弃过期结果
- 与服务端交互时避免每次按键都提交

### 校验与错误
- 范围、精度、必填——组件只呈现，规则由外部给
- **校验与步进夹取必须一致**：不能一个允许越界一个拒绝

### 回填与序列化
- 初值 → 按精度与千分位格式化显示
- 序列化：推荐输出**数值**；避免把带分隔符的 `1,000` 当字符串提交
- 千分位仅用于显示，提交不带分隔符

---

## 无障碍
- 关联可见标签与单位；帮助 / 错误文案与其关联；错误态标 `aria-invalid`
- 步进按钮提供可读名称（增加 / 减少）
- 数值变化若播报须用 `aria-live`（步进时播报），且避免刷屏
- 键盘全可达；`↑` / `↓` 增减的语义须能向用户解释

---

## 常见误用
- 把滚轮增减默认开启 → 页面滚动时误改数值
- 用浮点数直接存金额 → 出现 `0.1 + 0.2` 类误差
- 把千分位带进提交值
- 允许为空却在校验时当成 `0`
- 步进到边界按钮不置灰
- 全角数字 / 中文标点未规范化

## 边界与代价
- 浮点精度 → 金额、比例必须约定存储与舍入方式（如以最小单位整数存储）
- 显示位数 ≠ 存储位数 → 回填后值被悄悄改写
- 滚轮 / 长按不设限 → 误操作且难撤销
- 步长与下限不对齐（下限 `1`、步长 `3`）→ 永远到不了某些值，须明确是否允许
- 精度、范围、空值三条策略若不明 → 提交值与用户所见不一致
