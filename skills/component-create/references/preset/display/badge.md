# 徽标

附着在某个元素角上的**极简计数或状态提示**，不单独承载导航或操作。

## 角色与边界

- **是什么**：一个小型视觉标记，用数字、圆点或状态色，通知「有新内容 / 有待处理 / 当前状态」。
- **解决什么**：在不打断主流程的前提下，提醒用户某处存在未读、待办或异常。
- **不解决什么**：
  - 不解决「完整的状态说明」 → 状态标签 / 状态点配合文字
  - 不解决「可点击的独立操作入口」 → 徽标若可点，其实质是被附着元素的点击
  - 不解决「消息列表本体」 → 列表 / 通知中心
  - 不解决「进度」 → 进度条 / 进度环
- **什么时候不用**：数字恒为 0 且无意义 → 隐藏徽标而非显示 0；需要表达「已读」 → 徽标消失即已读。

---

## UI

### 结构解剖
- **徽标本体**：数字 / 圆点 / 状态点 / 短文字
- **附着容器**：角标需要相对定位的父元素
- **偏移层**：控制徽标相对父元素角点的位移
- **计数文本**：数字，超上限显示封顶形态
- **状态色底**：语义色背景或色点

### 尺寸与外观变体
| 轴 | 取值 | 说明 |
|---|---|---|
| 形态 | 数字徽标 / 点状徽标 / 状态点 | 数字给数量，点只给「有」，状态点给状态 |
| 尺寸 | 小 / 中 / 大 | 与附着元素尺寸匹配 |
| 颜色 | 默认强调色 / 语义色（成功、警告、错误、信息） | 状态点必须带语义 |
| 封顶 | 不封顶 / 封顶（如 99+） | 超过上限显示「上限+」 |
| 独立 | 附着角标 / 独立展示 | 独立时无偏移概念 |
| 内容 | 纯数字 / 数字+单位 / 纯文字 / 空（点） | |

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| default | 常态底 + 文本色，圆角胶囊 |
| zero / empty | 值为 0 或空 → 按规则隐藏或显示为点 |
| capped | 超过上限显示「99+」，宽度随之变化 |
| overflow 隐藏 | 值超出容量时整枚隐藏而非截断 |
| hover（若可点） | 由附着元素负责高亮，徽标不单独变化 |
| disabled | 随附着元素一起降透明 |
| animated | 出现时短暂缩放 / 弹入 |
| status-点 | 无数字，仅颜色点，颜色即语义 |

- 徽标默认**不可单独交互**：hover / focus 一律落在附着元素上。

### 布局与对齐
- 角标锚定在父元素的一个角（常见右上），用偏移量微调。
- 数字徽标宽度随位数变化，高度固定；单字符可呈正圆，多字符呈胶囊。
- 偏移要保证不遮挡附着元素的关键图形（如图标主体）。
- 独立使用时改为中心对齐，无偏移概念。

### 移动端
- 徽标本体很小，附着元素的**触摸命中区仍须 ≥ 44×44**，不能只让徽标可点。
- 小屏上避免徽标过大压住图标；点数与图标比例要协调。

## 交互

### 核心操作
- 徽标本体通常无操作；「查看 / 清空」通过点击附着元素完成。
- 出现 / 消失由数据驱动，不由用户手动开关。

### 选中或输入行为
- 无输入。值完全由外部数据决定。

### 键盘
| 场景 | 键位 | 行为 |
|---|---|---|
| 附着元素可聚焦 | `Tab` | 焦点落在附着元素 |
| 徽标本体 | — | 不单独进入键盘序列 |
| 可点徽标 | `Enter` / `Space` | 触发附着元素动作 |

### 指针与手势
- 点击徽标 = 点击其附着元素，命中区随附着元素。
- 触摸端不依赖 hover 表达任何状态。

### 焦点管理
- 徽标**不接收焦点**；焦点环由附着元素绘制。

### 动画与过渡
- 出现：短促缩放 / 弹入（约 150–250ms），可加一次轻微脉冲吸引注意。
- 数字变化：宽度过渡平滑，不引起父布局抖动。
- 消失：淡出即可，避免突兀。
- 高频抖动（秒级刷新）应做聚合，避免动画闪烁。

### 反馈
- 徽标本身就是反馈（提醒有新内容），不额外弹提示。
- 数值归零时按规则隐藏，避免「0」的噪音。

### 边界交互
- 超大数值：必须封顶，否则撑破布局。
- 与相邻元素拥挤：偏移需保证不压住其他元素。
- 动态频繁变化：做节流 / 聚合，防止动画与朗读风暴。

## 数据流

### 输入
- 值：数字 / 布尔（是否有）/ 状态枚举
- 上限（封顶值）
- 形态（数字 / 点 / 状态点）、颜色 / 语义
- 是否隐藏零值、独立或附着、偏移

### 内部状态
- 基本无；仅出现动画的过渡相位。
- 若做数字滚动动画，暂存上一显示值。

### 输出
- 默认无输出。
- 若可点，点击事件归属附着元素，徽标本身不抛业务值。

### 受控 / 非受控
- 徽标是**受控展示**：值由外部传入，组件不自行计数与修改。

### 异步与竞态
- 值常来自轮询 / 推送；需处理乱序（旧值后到不应覆盖新值）。
- 高频更新要节流，避免每来一条就重绘抖动。

### 校验与错误
- 值非法（负数、非数字）要有兜底：按 0 或隐藏处理。
- 徽标不承担业务校验。

### 回填与序列化
- 值直接来自数据字段；回填即绑定该字段。
- 上限封顶是渲染规则，序列化时仍保留真实值。

---

## 无障碍
- 徽标若为唯一信息来源，必须提供等价文本（如「5 条未读」），不能只靠颜色点。
- 状态点不可仅用颜色表达状态，须有文字或可访问名称。
- 装饰性纯视觉徽标应被辅助技术忽略，避免与附着元素名称重复朗读。
- 附着元素的可访问名称宜包含徽标语义，读作「消息，5 条未读」。

---

## 常见误用
- 值为 0 仍显示「0」→ 噪音。
- 不封顶，超大数撑破布局。
- 用纯色点表达状态却无文字等价 → 色觉障碍不可知。
- 让徽标本体承担点击 → 命中区过小。
- 把徽标当导航入口或主要操作入口。
- 秒级刷新仍逐条弹入动画 → 抖动。
- 多个徽标的颜色含义不统一。

## 边界与代价
- 数值无上限 → 必须封顶。
- 状态点无文本等价 → 无障碍缺失。
- 徽标作唯一可点目标 → 移动端不可用。
- 高频更新不做节流 → 性能与朗读噪音。
- 偏移不当遮挡图标主体 → 视觉损伤。
