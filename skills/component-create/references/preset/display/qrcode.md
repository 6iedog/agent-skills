# 二维码

把一段**值编码成可扫描图形**的展示元素，支持纠错、中心图标与过期刷新。

## 角色与边界

- **是什么**：将一段字符串（链接 / 文本 / 凭证）编码为方阵图形，供扫描设备解读。
- **解决什么**：跨设备快速传递一段值（手机扫码打开链接 / 登录 / 支付）。
- **不解决什么**：
  - 不解决「扫描摄像头输入」 → 扫码组件（此处只生成展示，不读取）
  - 不解决「短值复制」 → 可复制文本
  - 不解决「条形码」 → 条码组件（另有编码规则）
- **什么时候不用**：值很短且就在同设备 → 直接给文本 / 链接。

---

## UI

### 结构解剖
- **码图形**：由模块方块构成的方阵
- **静默区（留白）**：图形四周必须保留的空白，保证可扫
- **中心图标**（可选）：叠加在中央的徽标 / Logo
- **定位图案**：二维码自带的三个角定位标识
- **说明文字**（可选）：提示「扫码打开」等
- **过期遮罩**（可选）：失效时覆盖并给刷新入口

### 尺寸与外观变体
| 轴 | 取值 | 说明 |
|---|---|---|
| 尺寸 | 小 / 中 / 大 / 自定义 | 越大越易扫 |
| 颜色 | 前景色 / 背景色（须高对比） | 反色可行但须实测 |
| 容错级别 | 低 / 中 / 较高 / 高 | 级别越高越耐污损，但图形更密 |
| 中心图标 | 无 / 有 | 占用纠错冗余 |
| 过期 | 长期有效 / 定时失效 + 刷新 | |
| 静默区 | 标准留白 / 自定义 | 过小会不可扫 |

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| default | 清晰码图 |
| hover | 若可点击（如放大）则反馈 |
| focus-visible | 焦点环 |
| loading | 生成中占位 |
| error | 生成失败占位 / 文案 |
| expired | 覆盖失效遮罩 + 刷新按钮 |
| disabled | 降透明 |

### 布局与对齐
- 图形居中对齐；静默区不可被父容器裁切。
- 中心图标尺寸不超过码图的一定比例，且不遮挡定位图案。
- 说明文字在图形下方居中。

### 移动端
- 触摸端二维码宜大一些；屏幕亮度影响扫描，提供「点击放大 / 调亮」提示更佳。
- 二维码本身不依赖触摸交互；若可点放大需命中区足够。

## 交互

### 触发与核心操作
- 展示为主，无内置操作。
- 过期时提供「刷新」操作重新生成。
- 可选：点击放大全屏，便于他机扫描。

### 选中或输入行为
- 无输入，值由外部给出。

### 键盘
| 场景 | 键位 | 行为 |
|---|---|---|
| 纯展示 | — | 不进入键盘序列 |
| 可点击 / 可刷新 | `Tab` | 聚焦 |
| 可点击 / 可刷新 | `Enter` / `Space` | 放大 / 刷新 |

### 指针与手势
- 点击可放大或触发刷新（视配置）。
- 双指缩放（若支持全屏查看）。

### 焦点管理
- 纯展示不可聚焦。
- 刷新按钮可聚焦；刷新后焦点保持在按钮或码图。

### 动画与过渡
- 刷新时码图做短淡入，避免视觉闪跳。
- 失效遮罩淡入。

### 反馈
- 生成失败给失败态与重试。
- 过期后必须明确提示，不能静默展示失效码（会扫出错误结果）。

### 边界交互
- 值过长：图形更密，须提高尺寸或容错级别，否则不可扫。
- 低对比 / 深色底：需保证对比，避免「看着有、扫不出」。
- 中心图标过大：超出纠错冗余会导致不可扫。
- 定时过期：到点自动失效并提供刷新。

## 数据流

### 输入
- **编码值**（字符串：链接 / 文本 / 凭证 token）
- 尺寸、前景 / 背景色
- 容错级别
- 中心图标资源与其尺寸
- 静默区大小
- 有效期 / 过期策略（若有时效）

### 内部状态
- 生成状态：generating / ready / error
- 是否过期、剩余有效期（若有时效）
- 全屏放大态（若支持）

### 输出
- 刷新事件（重新取值的请求）
- 生成失败事件
- 过期事件（供外部重新签发）

### 受控 / 非受控
- 编码值**受控**：完全由外部给出，组件只渲染。
- 过期 / 刷新由外部值驱动，组件不自行换取新值。

### 异步与竞态
- 值常带时效：到点须失效并刷新。
- 快速多次刷新时丢弃过期生成结果，只保留最新。

### 校验与错误
- 值超长导致不可扫：应提示或自动调大尺寸，不能输出不可扫的码。
- 生成失败给失败态。
- 组件不校验值语义，只保证可编码。

### 回填与序列化
- 值直接来自数据字段；回填即绑定该值。
- 若值为一次性 token，序列化无意义，应以重新签发为准。

---

## 无障碍
- 二维码对屏幕阅读器无意义：必须提供**等价文本或链接**，不能只给图形。
- 说明文字描述用途（如「扫码在手机上打开」）。
- 可点击 / 可刷新时按按钮语义，全键盘可达，焦点可见。

---

## 常见误用
- 只给图形不给等价链接 → 视觉障碍 / 无摄像头用户不可用。
- 中心图标过大吃掉纠错冗余 → 不可扫。
- 静默区被容器裁切 → 不可扫。
- 低对比配色 → 看着有扫不出。
- 值超长仍用小尺寸 → 图形过密不可扫。
- 有效期到点不刷新且静默展示 → 扫出失效结果。
- 用二维码承载关键信息却不含等价文本。

## 边界与代价
- 无等价文本 / 链接 → 无障碍缺失，且单手可及性差。
- 对比不足 / 留白被裁 → 不可扫。
- 中心图标超比例 → 不可扫。
- 值长而不调尺寸 / 容错 → 不可扫。
- 过期不刷新 → 错误传递。
