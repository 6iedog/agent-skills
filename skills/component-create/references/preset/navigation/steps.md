# 步骤条

把一个**多步流程**拆成有序步骤，标出当前步与每步状态（等待 / 进行 / 完成 / 错误）。

## 角色与边界

- **是什么**：按顺序排列的步骤指示器，每步展示序号 / 图标与标题，并用连接线串起整体进度。
- **解决什么**：让用户知道流程走到哪、还剩几步、哪一步出了问题。
- **不解决什么**：
  - 不承担同级内容的互斥切换（无顺序）→ 标签页
  - 不表达「当前页在层级中的位置」→ 面包屑
  - 不负责步骤内容的校验与提交（那是表单 / 流程层）——本组件只**呈现**状态
  - 不做页面间导航 → 导航菜单
- **什么时候不用**：内容是并列且无先后顺序；只有一步；步骤只是装饰性地罗列（无进度含义）。

---

## UI

### 结构解剖
- **容器**：承载全部步骤与连接线
- **步骤项**：指示器（序号 / 图标 / 圆点）+ 标题 + 可选描述文字
- **连接线**：连接相邻指示器，示意顺序
- **当前步强调**：进行中的步骤被突出
- **状态标记**：完成的勾、错误的警示、进行中的高亮或加载
- **可选操作区**：当前步附近的「上一步 / 下一步」按钮（若做页内流程，常由外层提供）

### 尺寸与外观变体
- 方向：**水平**（顶部，流程短）/ **垂直**（左侧或内容旁，含描述时更清晰）
- 形态：编号 + 标题 + 描述 / 编号 + 标题 / **点状简洁**（仅圆点）/ 纯图标
- 标签位置（水平）：指示器下方居中 / 指示器右侧同行
- 是否可点（允许回退到已完成步）
- 是否有连接线、线是否为进度条样式

### 视觉状态（逐条）
| 状态 | 指示器 | 含义 |
|---|---|---|
| wait | 灰色、序号 | 尚未到达 |
| process | 高亮 / 强调色 + 序号，可含加载指示 | 当前进行中 |
| finish | 完成勾 / 对勾图标 | 已完成 |
| error | 危险色 + 警示图标 | 该步校验失败 |
| disabled | 降透明、禁用指针 | 明确不可点击的步 |

- **状态不能只靠颜色**：必须同时用图标（勾 / 警示 / 序号）或文字区分，色盲用户也能辨认。
- process 与 finish 的视觉强度需拉开，避免「已在做」和「已做完」看起来一样。

### 布局与对齐
- 水平：各步等分宽度，标题居中；连接线在指示器之间
- 标题过长：截断或换行，需二选一并保持一致；等分布局下避免挤压邻步
- 垂直：整体左对齐，指示器在左，标题描述在右
- 步数多时水平布局会拥挤 → 考虑垂直或点状

### 移动端
- 水平步骤条在窄屏拥挤 → 压缩为**点状**（只显指示器与当前步标题），或切换为垂直
- 触摸目标（若可点）≥ 44×44
- 描述文字在移动端常省略，只保留标题

## 交互

### 触发与切换
- 点击**已完成**的步 → 回退到该步（仅当业务允许回退）
- 点击进行中 / 未到达的步：默认**不可点**；若允许前进，需先通过当前步校验
- 点击行为是否开启由业务决定，组件提供可点 / 不可点开关

### 选中行为
- 当前步唯一；切换后强调随之转移
- 回退到已完成步**不丢失已完成数据**（数据保留由流程层负责，组件不销毁）
- 是否允许跨过未完成步前进：默认不允许

### 键盘
| 键位 | 行为 |
|---|---|
| `Tab` | 在可点击的步之间移动焦点 |
| `Enter` / `Space` | 激活聚焦的步（回退 / 前进） |
| `←` / `→` | 水平方向：在步之间移动 |
| `↑` / `↓` | 垂直方向：在步之间移动 |
| `Home` / `End` | 跳到首步 / 末步 |

- 不可点击的步不进 Tab 序列。

### 指针与手势
- 点击可点步切换状态
- 悬停可点步给出反馈；不可点步无 hover
- 移动端以点击为主，不依赖 hover

### 焦点管理
- 点击回退后，焦点移交给对应步骤内容区（由外层处理）
- 组件不接管页面主焦点，仅管理自身可点步的焦点

### 动画与过渡
- 连接线进度推进：宽度 / 高度过渡，约 200ms
- 指示器状态切换（序号 → 勾）：淡入或缩放过渡
- 尊重「减少动效」偏好
- 不引起布局抖动

### 反馈
- 状态变化即时可视（颜色 + 图标）
- error 步给出简短原因或引导（可在外层步骤内容中呈现）
- 前进被校验阻塞时，提示当前步的错误

### 边界交互
- 步数过多（水平放不下）→ 压缩为点状或转垂直
- 跳步：不允许跨过未完成步；回退可跨已完成的任意步
- 步骤禁用：因前置条件不满足的步设为 disabled
- 异步校验：提交当前步后才允许前进，期间显示加载并禁用「下一步」

## 数据流

### 输入
- **步骤列表**：`{ 标题, 描述?, 状态?, 是否可点? }` 的有序数组
- **当前步索引**：流程当前所处步骤
- 配置：方向、形态（编号 / 点状 / 图标）、标签位置、是否可点

### 内部状态
- 通常**无独立业务状态**；当前步与各步状态由外部注入
- 仅维护可点步的焦点 / 悬停等瞬时 UI 状态

### 输出
- **步骤切换事件**：目标步索引（回退或前进）
- 点击事件（供外层决定是否允许该切换）

### 受控 / 非受控
- **当前步通常受控**：由流程层持有，组件只抛「请求切到第 N 步」
- 各步状态也由外部注入，组件不自行推导
- 若做非受控，需明确何时自动推进——但流程通常需要严格受控

### 异步与竞态
- 前进常伴随异步校验 / 提交：期间禁用前进、显示加载
- **竞态**：快速点击前进 / 回退时，丢弃过期结果，避免状态跳变
- 外部数据未就绪时，进行中的步可呈现加载

### 校验与错误
- 组件不做校验；校验由流程层在各步执行
- 校验失败 → 该步置为 error 且阻止前进；错误原因由外层展示
- 「能否点某步」由外部通过 `是否可点` 控制

### 回填与序列化
- 当前步可写入 URL / 草稿，刷新后恢复到同一步
- 回填时若步骤集合变化（如分支流程），需校验索引仍有效
- 已完成标记通常来自**流程数据**（哪几步已提交成功），组件不自造

---

## 无障碍
- 用有序列表表达步骤顺序
- 当前步标注「当前步骤」语义，屏幕阅读器可读
- 每步状态用文字 / 图标表达，**不单独依赖颜色**
- 可点与不可点有语义区分（可点步为可操作元素，不可点步为纯呈现）
- 全键盘可达；`focus-visible` 可见

---

## 常见误用
- 用步骤条承载无先后顺序的并列内容 → 应用标签页
- 步数过多仍用水平编号形态 → 拥挤，应转点状 / 垂直
- 仅用颜色区分状态 → 色盲用户无法辨认
- 点击回退后丢失已完成数据 → 用户白填
- 允许跨过未完成步前进 → 流程断裂
- 把校验 / 提交逻辑塞进步骤条组件 → 职责越界

## 边界与代价
- 步数超过约 5–6 步：水平编号形态放不下，**必须**压缩或转垂直
- 状态**必须**同时用图标 / 文字表达，不能只靠颜色
- 回退**必须**保留已填数据（由流程层保证，组件不销毁步骤内容）
- 前进**必须**受当前步校验约束，不得跨过未完成步
- 当前步**应受控**，由流程层持有，否则多入口流程会状态错乱
- 异步校验期间**必须**禁用前进并给出加载态
