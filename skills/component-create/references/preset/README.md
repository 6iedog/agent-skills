# 预设组件提示词（随 Skill 提供，与项目无关）

**一个具体组件一份文件**，全文是这个组件的**全面描述**：它有哪些变体、每个参数意味着什么、什么时候用、什么时候不该用、到什么程度会出问题。

## 组织方式

```
preset/
├── README.md          本索引
├── general/           通用
├── layout/            布局
├── navigation/        导航
├── choice/            选择
├── input/             输入
├── display/           展示
├── feedback/          反馈
└── overlay/           弹层
```

## 每份含哪些维度

每份都按「角色与边界 → UI → 交互 → 数据流 → 无障碍 → 常见误用 → 边界与代价」逐段写全，**不是要点索引卡**。

| 维度 | 内容 | 作用 |
|---|---|---|
| 角色与边界 | 是什么 / 解决什么 / **不解决什么** / 什么时候不用 | 判断诉求是否该用它，并指向相邻组件 |
| UI | 结构解剖、尺寸与外观变体、**视觉状态逐条**、布局与对齐、移动端 | 让 agent 知道要做哪些结构与视觉态 |
| 交互 | 触发与开合、选中/输入行为、**键盘**、指针与手势、焦点管理、动画与过渡、反馈、边界交互 | 让 agent 知道每个操作与键位的预期行为 |
| 数据流 | 输入、内部状态、输出、受控/非受控、异步与竞态、校验与错误、回填与序列化 | 让 agent 知道值从哪来、怎么变、往哪去 |
| 无障碍 | 角色与 aria、全键盘可达、焦点可见 | 保证可访问 |
| 常见误用 | 什么情况下**不该**用它 | 避免误用 |
| 边界与代价 | 到什么程度会出问题 | 提前设限 |

## 覆盖范围

已覆盖**通用 / 布局 / 导航 / 选择 / 输入 / 展示 / 反馈 / 弹层**八类。

**有意不纳入**（它们不是「一个可复用的界面组件形态」，写不出 UI / 交互 / 数据流）：

- 基础设施类：全局配置、应用容器、工具函数、图标资源集。
- 第三方高阶组件：某个生态里的「专业版表格 / 表单 / 布局」等封装套件。

## 硬规则

- **必须与组件库无关**：描述通用形态，不写某个库的组件名，也不抓取某个库的文档（抓取器必然绑死一个库，换库即失效）。
- 参考成熟组件库的是它的**信息组织方式**与**覆盖范围**，不是它的内容。
- 新增一个组件：在对应类目录建 `<name>.md`，按上表维度写，并更新本索引。
- 相邻组件必须在「不解决什么」里互相指路——这类文件的价值就在于**帮模型选对形态**。
