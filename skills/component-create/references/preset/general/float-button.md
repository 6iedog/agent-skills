# 悬浮按钮

固定在视口某个角位、浮在内容之上的**全局入口按钮**，可展开为动作组。

## 角色与边界

- **是什么**：不随内容滚动、长期停留在视口固定位置的浮动控件；常作为页面级主操作或工具入口。
- **解决什么**：让某个重要动作（新建、返回顶部、联系、工具）**随时可达**，且不占用正常内容区。
- **不解决什么**：
  - 不解决「表单内主操作」 → 普通按钮（按钮不该飘着）
  - 不解决「全局导航」 → 导航栏 / 侧边栏
  - 不解决「多个并列信息入口」 → 底部标签栏 / 工具栏
  - 不解决「需要常驻且可读的列表入口」 → 侧栏或快捷面板
- **什么时候不用**：同一页面已有明确的、固定的主操作入口 → 再放悬浮按钮就是重复噪音；内容本身很短（无需滚动、无需随处可达）→ 不必悬浮。

---

## UI

### 结构解剖
- **主按钮**：圆形（或胶囊形），承载一个图标
- **图标**：语义明确的单图标；展开态可切换为关闭图标
- **动作子项**：展开后逐条出现的附属按钮（各带图标 + 可选文字标签）
- **徽标**：角上的数字 / 圆点提示有更新（可选）
- **文字标签**：可选的常显或展开时出现的说明
- **工具提示**：悬停时的一句话说明（可选）

### 尺寸与外观变体
| 轴 | 取值 | 说明 |
|---|---|---|
| 尺寸 | 默认 / 小 | 影响直径与图标尺寸 |
| 角位 | 右下 / 左下 / 右上 / 左上 | 默认右下，避免遮挡主内容与浏览器手势区 |
| 展开方向 | 向上 / 向下 / 向左 / 向右 | 由角位与空间决定 |
| 形态 | 单个动作 / 动作组 | 动作组展开后是多个子项 |
| 外观 | 实心 / 描边 / 白底 | 需在任意背景上保持可辨 |
| 特殊行为 | 返回顶部 / 主操作入口 | 返回顶部常随滚动显隐 |
| 徽标 | 无 / 圆点 / 数字 | 数字超上限时显示为「99+」 |

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| default | 常态悬浮，带阴影区分于内容 |
| hover | 抬升阴影加深，可轻微放大 |
| active（按下） | 轻微下沉 / 缩小 |
| focus-visible | 明显焦点环 |
| open（动作组展开） | 主按钮图标切换为关闭，子项依次出现 |
| entering / leaving | 随滚动阈值出现或隐去（返回顶部场景） |
| dragging（可拖拽时） | 跟随指针，松手吸附到最近角位 |
| disabled | 降透明、不可点（少见） |
| badge | 角上显示圆点或数字 |

- 悬浮按钮**必须有阴影或描边**，否则与内容混在一起无法辨认。
- 可拖拽变体必须给出「正在拖拽」的视觉，并让点击与拖拽可区分（移动阈值）。

### 布局与对齐
- 距视口边缘保留安全间距（横竖一致），不与系统手势区、滚动条重叠。
- 展开的动作子项与主按钮**居中对齐**，间距统一，形成清晰竖列 / 横列。
- 悬浮按钮浮在内容之上，使用足够高的层级，但不遮挡关键操作与表单。
- 返回顶部变体应在滚动过一定距离后才出现，不长期占据角位。

### 移动端
- **避让安全区**：底部要避开系统手势条 / Home 指示条，用安全区留白。
- **避让软键盘**：输入时软键盘弹出，悬浮按钮应上移或隐藏，不能被压在键盘下、也不能遮住输入区。
- 触摸目标 ≥ 44×44，动作子项同样达标。
- 动作组展开的子项若带文字，文字要短；纯图标子项必须可被读出。
- 与底部固定操作栏同时存在时，需明确层级，避免叠压。

## 交互

### 触发与展开
- 点击主按钮：单动作 → 直接执行；动作组 → 展开子项。
- 动作组再点主按钮 / 点外部 / `Esc` → 收起。
- 返回顶部变体：点击后平滑滚动到顶部。
- 展开方向由可用空间决定，靠近边缘时自动换向。

### 动作选择行为
- 展开后点击某子项：执行该动作并收起动作组（除非该动作会打开弹层）。
- 展开时给子项依次入场动效，形成**明确的方向序列**。
- 子项与主按钮的关系要清楚：子项不应被误当成独立常驻按钮。

### 键盘
| 键位 | 行为 |
|---|---|
| `Tab` | 聚焦到悬浮按钮（若动作组，聚焦主按钮） |
| `Enter` / `Space` | 展开 / 收起动作组，或触发单动作 |
| `↑` / `↓`（或按展开轴） | 在已展开的子项间移动焦点 |
| `Esc` | 收起动作组，焦点回到主按钮 |
| `Home` / `End` | 跳到首 / 末个子项（可选） |

- 收起时子项**不可 Tab 到达**（隐藏即移出可访问序列）。
- 返回顶部按钮也需可键盘触发并聚焦可见。

### 指针与手势
- 触摸：点按主按钮展开，点按子项执行；点外部收起。
- 可拖拽变体：长按或直接拖动移动位置，短按仍是点击；用移动阈值区分拖与点。
- 松手后吸附到最近角位，避免停在会遮挡内容的位置。

### 焦点管理
- 展开动作组后，焦点可进入子项；收起后焦点回到主按钮。
- 可拖拽后位置变化不应夺走焦点，也不应把焦点丢到 body。
- 若按钮随滚动隐藏，隐藏时须移出可访问序列，避免「Tab 到看不见的按钮」。

### 动画与过渡
- 出现 / 隐藏：淡入淡出 + 轻微位移动，约 150–250ms。
- 动作组展开：子项按方向依次入场（位移 + 淡入），收起倒序。
- 主按钮图标展开 / 收起时旋转切换。
- 拖拽跟手，松手吸附用短缓动。

### 反馈
- 点击后若动作异步，主按钮或子项应显示加载态。
- 徽标数字更新即时反映。
- 返回顶部滚动过程平滑，避免瞬移造成位置迷失。

### 边界交互
- 与内容底部元素（底部栏、悬浮卡片）重叠时，需明确谁在上、是否遮挡。
- 页面同时存在多个悬浮按钮 → 应合并或明确主次，避免角位争抢。
- 软键盘弹出、旋转屏幕、窗口尺寸变化 → 重新计算位置与安全区。
- 拖拽到角落边界时限制在可视区内。

## 数据流

### 输入
- **动作定义**：单动作或动作列表（图标、标签、可访问名称、处理函数 / 动作标识）。
- 配置：角位、尺寸、展开方向、徽标值、是否可拖拽、显示阈值（返回顶部场景）。
- 滚动容器引用（判断显示时机与滚动目标）。

### 内部状态
- open（动作组展开与否）
- 显示与否（返回顶部场景，按滚动阈值）
- 当前位置（可拖拽变体）
- 是否正在拖拽 / 是否正在加载

### 输出
- **动作事件**：点击子项时抛出对应动作标识，业务逻辑由外层承接。
- 开合事件（供埋点）。
- 位置变化事件（可拖拽变体）。
- 通常**不携带表单值**，不参与表单数据。

### 受控 / 非受控
- 开关（展开态）默认非受控，内部自管；需要外部联动时可受控。
- 位置（可拖拽）通常内部持有并持久化，外部可给初始位置。
- 显示与否（返回顶部）由内部按滚动位置自管。

### 异步与竞态
- 动作可能异步（如提交、加载），触发后需防重复并显示进行中。
- 位置持久化写入需防抖，避免拖拽过程频繁写存储。
- 滚动显隐判断需节流，避免高频滚动下抖动。

### 校验与错误
- 悬浮按钮不做校验；若动作需要权限 / 前置条件，应在触发前判断并给出原因（禁用或提示）。
- 动作失败要反馈到上层提示，按钮不静默。

### 回填与序列化
- 可拖拽位置应可持久化（本地存储），回填后仍吸附在合法角位。
- 动作列表可来自配置 / 运行时数据，变化时子项同步刷新，展开态若失效则收起。

## 无障碍
- 主按钮与每个子项都需**可访问名称**（纯图标尤其如此）。
- 动作组展开时，子项应可被键盘依次到达；收起时应移出可访问序列。
- 展开 / 收起的可访问状态要同步（是否展开、有几项）。
- 徽标数字应能被读出，或至少有等价描述（不能只靠视觉圆点）。
- 返回顶部按钮需可键盘聚焦触发；隐藏时移出可访问序列。
- 可拖拽位置对屏幕阅读器无意义，不应作为信息唯一来源。
- `focus-visible` 必须可见。

---

## 常见误用
- 把表单的主操作做成悬浮按钮 → 飘着且随滚动移动，提交入口不稳。
- 悬浮按钮无阴影 / 无描边 → 与背景混在一起。
- 动作组子项没有清晰的方向入场 → 用户看不出它们从属同一入口。
- 移动端不避让安全区 / 软键盘 → 被手势条或键盘遮挡。
- 返回顶部按钮长期常驻 → 无谓占用角位。
- 一页放多个悬浮按钮 → 角位争抢、层级混乱。
- 可拖拽却无移动阈值 → 点击总被误判成拖拽。
- 用纯视觉圆点表达有更新 → 屏幕阅读器与色觉障碍用户不可知。

## 边界与代价
- **必须避让移动端安全区与软键盘**，否则核心操作不可达。
- 动作组收起后子项**必须**移出键盘序列，否则出现「Tab 到隐藏项」。
- 可拖拽位置持久化要防抖，否则拖拽卡顿。
- 悬浮按钮层级过高会遮挡内容与弹层，层级需克制并明确。
- 同时存在多个悬浮入口 → 主次必然混乱，应合并。
- 徽标数字不设上限显示 → 长数字撑破角标，需「99+」。
