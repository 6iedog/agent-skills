# 文字提示

附着在某个元素旁的**一句话说明**，随触发出现、随离开消失，**纯文本、绝不可交互**。

## 角色与边界

- **是什么**：绑定到一个触发元素的短文本浮层，用于补充该元素的含义，本身不参与任何操作。
- **解决什么**：界面空间有限，无法把解释文字平铺出来——图标按钮的含义、被截断文本的完整值、字段/术语的解释。
- **不解决什么**：
  - 内容里需要按钮 / 链接 / 输入 → 气泡卡片（popover）
  - 需要用户停留阅读、复制、交互 → 就地说明或帮助页
  - 需要用户确认或做选择 → 确认弹窗 / 下拉面板
  - 承载必须被看到的关键信息（如错误、必填提示）→ 应直接呈现，不能藏在提示里
- **什么时候不用**：
  - 触发元素本身已有完整可见文本，再挂提示只是重复 → 噪音，去掉
  - 该解释对完成任务是必需的 → 直接放在页面上（常显文案 / 帮助图标旁的说明）
  - 移动端没有 hover 又无法提供长按路径 → 不要依赖它承载信息

---

## UI

### 结构解剖
- **容器**：一小块浮层，圆角、留白、常带轻微阴影
- **文本**：一到两句纯文本；不出现图标按钮、链接、列表
- **箭头（可选）**：指向触发元素的小三角，帮助建立视觉关联
- **触发元素**：工具提示所附着的对象（图标、图标按钮、截断文字、字段标签）

### 尺寸与外观变体
- 尺寸：随内容自适应，宽度有上限（常见约等于若干字符宽），超出换行
- 外观：单行（短） / 多行（稍长）；是否带箭头
- 位置：上 / 下 / 左 / 右四个主方位，及四角共 12 个方向位
- 主题：浅色 / 深色（深色在中性背景下更醒目）

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| hidden | 不显示，DOM 可不存在或不可见 |
| appearing（出现中） | 淡入 + 轻微位移，脱离鼠标后仍短暂保留 |
| visible | 稳定显示，可多行 |
| disappearing（消失中） | 淡出，短过渡 |
| 触发元素 focus-visible | 触发元素自身显示焦点环，提示随之出现 |

- 提示本身无 hover / active / disabled 概念（不可交互）。
- 提示出现时**不该改变布局**：必须脱离文档流（浮层）。

### 布局与对齐 / 定位
- 默认贴合触发元素的某一侧，并与触发元素**对齐**（居中或靠边对齐）
- **12 方位 + 自动避让**：默认方位若出屏，自动翻转到对侧或相邻侧
- 箭头始终指向触发元素，翻转后箭头位置同步
- 多行时限制最大宽度，避免形成巨大的文本块
- 相邻元素都有提示时，先移开一个再移入另一个，不应同时弹出两个

### 移动端
- **移动端一般没有 hover**：不能靠悬停触发
- 替代方式：长按（展示后点击别处消失）或把该解释改为常显 / 气泡卡片
- 触摸目标小（如行内图标）时，长按手势容易误触页面选择，需谨慎
- 提示出现位置要避开手指遮挡区域

## 交互

### 触发与开合
- 桌面：
  - **悬停**触发元素，等待**延迟**（避免划过就闪）后出现
  - 移开后有**延迟**再消失（避免鼠标在触发元素与提示之间移动时闪烁）
  - **聚焦**（键盘 Tab 或点击）也触发，保证键盘可达
- 移动端：长按或点按触发元素后出现
- 出现延迟与消失延迟通常为一小段时间（如几百毫秒），具体值由使用方设定，目的是防抖
- 触发元素被禁用时是否仍显示提示：若提示是在解释「为何禁用」，应允许在禁用元素上触发（此时用外层包裹承接手势）

### 关闭行为
- 移开指针 / 失去焦点 → 延迟后消失
- `Esc` → 立即消失
- 点击页面其他位置（移动端 / 长按场景）→ 消失
- 滚动、页面切换、触发元素被移除 → 消失

### 键盘
| 键位 | 行为 |
|---|---|
| `Tab` | 聚焦到触发元素 → 显示提示 |
| `Shift+Tab` | 离开触发元素 → 隐藏提示 |
| `Esc` | 立即隐藏提示 |

- 提示本身**不可聚焦、不可 Tab 进入**（它没有可交互内容）。

### 指针与手势
- 悬停进入触发元素 → 计时出现
- 指针从触发元素移向提示本身：提示不可交互，指针移入提示区域应视为离开触发元素（延迟消失）
- 触摸端：长按触发、松手或点别处消失

### 焦点管理
- 提示**不接收焦点**，不得把焦点从触发元素抢走
- 键盘用户按 `Tab` 聚焦触发元素时，屏幕阅读器应能读到提示文本（见无障碍）
- 隐藏提示不应导致焦点丢失或回跳

### 动画与过渡
- 出现 / 消失：短淡入淡出 + 与方位一致的轻微位移，约 100–150ms
- 过渡要足够快，避免用户已移开指针提示才慢慢浮现
- 关闭时若已进入进入动画，应能取消，不出现「滞后悬浮」

### 反馈
- 提示不产生状态变更，无成功 / 失败语义
- 触发元素本身若有加载 / 禁用态，其样式与提示互不干扰

### 边界交互
- **内容超长**：换行并限制宽度；若长度已超过一两句，应改为就地说明或气泡卡片，而不是让提示变成一大块
- **多个 tooltip 并存**：同一时刻只显示一个；相邻触发元素切换时先收旧开新，不叠层
- 触发元素靠近视口边缘：自动避让，必要时收缩或翻转方位
- 触发元素滚动出屏：提示随之消失或跟随
- 触发元素尺寸变化 / 被卸载：提示必须同步隐藏

## 数据流

### 输入
- **内容**：纯文本（可含最小化的富文本，但**不得含可交互元素**）
- **关联方式**：与触发元素的绑定（包裹触发元素 / 通过属性指向触发元素）
- **配置**：默认方位、是否显示箭头、出现与消失延迟、是否禁用
- **受控开关（可选）**：由外部控制显隐

### 内部状态
- visible（是否显示）
- 实际生效方位（经避让计算后的方位）
- 出现 / 消失计时器（延迟控制）

### 输出
- 通常**无业务输出**（纯说明，不改任何数据）
- 可抛出 open / close 事件用于埋点或联动

### 受控 / 非受控
- 默认非受控：由内部根据悬停 / 聚焦自行开合
- 需要外部控制时提供受控开关，内部不再自行判断

### 异步与竞态
- 内容通常为同步静态文本；若内容需异步取（如远程解释），要处理加载与失败，避免空提示
- 快速划过多个触发元素时，需**取消上一个的待显示计时**，否则会错位弹出

### 校验与错误
- 提示不承担校验；它是补充信息，不是错误呈现渠道
- 不要用提示展示必填 / 格式错误（会被忽略且移动端不可及）

### 回填与序列化
- 无值回填概念；若内容来自数据，触发元素变化时内容需同步更新

---

## 无障碍
- 触发元素与提示建立可访问关联（如把提示文本作为触发元素的可访问描述），使屏幕阅读器在聚焦时朗读
- **键盘聚焦即显示**，保证仅用键盘的用户也能得到信息
- 提示内容不得包含必须交互才能获取的信息
- 不要把提示当唯一信息源：装饰性文字不必挂提示，重复信息只会增加朗读噪音
- 出现 / 消失应能被辅助技术感知，但不应打断用户当前朗读

---

## 常见误用
- 提示里放按钮 / 链接 → 用户点不到，应用气泡卡片
- 把关键信息（必填、错误、操作结果）只放在提示里 → 移动端与键盘用户看不到
- 文字过长 → 提示框膨胀成一大块，应改就地说明
- 对已有完整可见文本的元素再加提示 → 纯噪音
- 移动端照搬 hover 触发 → 无 hover 时信息不可达
- 无延迟直接弹出 → 鼠标划过一片区域时满屏闪烁

## 边界与代价
- **必须可键盘触发**（聚焦即显示），否则无障碍缺失
- **移动端必须提供长按等替代**，否则信息不可及
- 内容超过一两句：**不要用提示**，改就地说明或帮助页
- 出现 / 消失延迟是必需品，不是可选项——去掉会引入误触闪烁
- 一旦内容需要交互，就不再是工具提示，应换用气泡卡片
