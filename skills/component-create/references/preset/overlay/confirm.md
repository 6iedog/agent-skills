# 确认弹窗

极简模态，**只问「确定 / 取消」**，用于给一个动作加一道确认。

## 角色与边界

- **是什么**：模态的特例，结构最简——一句说明 + 两个按钮，不承载复杂内容。
- **解决什么**：动作有后果（尤其**不可逆 / 危险**）、需要用户再点头一次。
- **不解决什么**：
  - 只是告知结果 → 消息提示
  - 需要填表 / 需要多步 → 模态对话框
  - 只是补充说明、无决策 → 气泡卡片 / 文字提示
  - 每个操作都弹 → 训练用户无脑点确定，反而不安全
- **什么时候不用**：低风险、可撤销、可频繁发生的操作不要弹；用撤销 + 提示替代。

---

## UI

### 结构解剖
- **遮罩层**：覆盖全屏，压暗背景并拦截点击
- **容器**：窄卡片，宽度受限
- **图标 / 强调符**：危险场景可放警告图标（可选）
- **标题**：一句说明动作本身（如「删除这条记录？」），即主体文案
- **补充说明**：一两句后果描述（可含数量、可恢复性）
- **底部操作区**：仅两个按钮——确认 + 取消
- **补充输入**（可选变体）：如「输入名称以确认」

### 尺寸与外观变体
- 宽度：固定窄（小）/ 自适应（中），不做大尺寸
- 外观：标准 / 危险强调（确认按钮用危险色、标题旁带警示图标）
- 内容：纯确认 / 带后果说明 / 带补充输入（仅最高风险）
- 触发来源：由其他操作触发，非常驻

### 视觉状态（逐条）
| 状态 | 遮罩 | 容器 / 文案 | 按钮 |
|---|---|---|---|
| default | 半透明压暗 | 静置 | 确认（可危险色）+ 取消 |
| entering | 淡显 | 淡入 + 轻微缩放 | — |
| closing | 渐隐 | 淡出 | — |
| hover | — | — | 悬停按钮背景变化 |
| focus-visible | — | — | 明显焦点环；**默认焦点在取消** |
| loading | — | 文案不变 | 确认按钮 spinner + 禁用，取消一并禁用 |
| error | — | 显示失败说明，不关闭 | 恢复可点，可重试 |

### 布局与对齐 / 定位
- 居中定位；宽度窄、内容单列，保证一眼读完
- 文案不超过约两行；更长说明应改模态或引导页
- 按钮右对齐；破坏性操作建议「取消」在左、「确认」在右，并与全局方向约定一致

### 移动端
- 仍可居中，宽度占满减去安全边距
- 按钮可撑满 / 纵向堆叠，触摸目标 ≥ 44×44
- 避免把危险按钮放在拇指最易误触处且默认聚焦

## 交互

### 触发与开合
- 由其他操作触发（删除按钮、离开未保存页、覆盖已有数据等），非独立打开
- 触发时把「将受影响的对象 / 数量」作为输入传入
- 打开即聚焦到**安全按钮**（取消）

### 关闭行为
| 关闭来源 | 是否默认可关 | 说明 |
|---|---|---|
| Esc | 是 | 等价于取消 |
| 点击遮罩 | 视场景 | 危险场景常关闭此项，防误触 |
| 取消按钮 | 是 | 明确否定 |
| 确认按钮 | 是 | 确认后由外部执行动作 |
| 关闭按钮 | 通常省去 | 极简，两个按钮已够 |

- 危险操作提交前**不再**弹第二个确认（本层即最后一道）
- 用户确认后由**外部**执行动作；执行中保持本层 loading

### 键盘
| 键 | 行为 |
|---|---|
| Tab | 在「取消 / 确认」之间循环，停在容器内 |
| Shift+Tab | 反向循环 |
| Enter | 触发**当前聚焦**按钮；初始聚焦在取消，故回车 = 取消 |
| Esc | 取消并关闭 |
| Space | 激活聚焦按钮 |

- 关键：**默认焦点落在「取消」**，防止回车误确认危险动作
- 危险场景**不**把焦点或回车默认指向确认按钮

### 指针与手势
- 点击按钮执行对应结果
- 危险场景下若已开启「点遮罩可关」，点遮罩等同取消
- 移动端不做下滑关闭（内容极简，无必要）

### 焦点管理
- 打开前记录触发元素；打开后聚焦取消按钮；关闭后**归还触发元素**
- 焦点陷阱：只在两个按钮间循环，不允许 Tab 逃逸到背景

### 动画与过渡
- 淡入 + 轻微缩放，约 120–200ms；关闭反向
- 短促即可，避免「等待动画」的延迟感
- 减少动态偏好时退化为淡入淡出

### 反馈
- 确认并提交时：确认按钮 loading + 禁用，防重复点击
- 成功：由外部关闭并给出结果反馈
- 失败：**不关闭**，显示失败说明，恢复按钮可点

### 边界交互
- 与模态：本层是模态的特例，结构更简；一旦需要内容就升为模态
- 嵌套：确认弹窗不应再触发另一个确认弹窗
- 连续触发：短时间内多次触发要合并 / 忽略后续，避免叠层

## 数据流

### 输入
- 标题文案（说明是什么动作）
- 补充说明（后果、数量、可恢复性）
- 确认按钮文案与类型（常规 / 危险）
- 取消按钮文案
- 遮罩点击是否可取消
- 是否带补充输入及其校验规则

### 内部状态
- open
- loading / submitting
- 补充输入值（若带输入）
- 触发元素记录

### 输出
- **确认事件**：外部据此执行动作；可附带补充输入值
- **取消 / 关闭事件**
- 不承担业务动作本身，只抛出「用户选了哪边」

### 受控 / 非受控
- 通常**受控**：open 由外部持有，因为它是某个流程的一部分
- 混用会导致「确认后不关」或「取消后还开着」

### 异步与竞态
- 确认后若动作异步：进入 loading，期间禁止二次确认与关闭
- 失败可重试；**不要把失败静默成成功**
- 竞态：动作进行中忽略重复确认事件

### 校验与错误
- 极简确认**不做字段校验**；带补充输入时校验输入是否匹配（如名称一致）
- 校验失败时禁用确认按钮并给出提示，不关闭

### 回填与序列化
- 无表单回填概念；带补充输入时初始值为空
- 确认结果只传递「选边 + 必要输入」，业务数据由外部持有

---

## 无障碍
- `role=alertdialog`（危险 / 需立即注意）或 `role=dialog`；遮罩存在时 `aria-modal=true`
- 标题用 `aria-labelledby` 关联，说明用 `aria-describedby`
- 默认聚焦安全按钮，Esc 可达
- 焦点陷阱；关闭后焦点归还
- 危险语义通过文案传达，不能只靠颜色

---

## 常见误用
- 给低风险操作也弹确认 → 产生「点确定」肌肉记忆
- 危险按钮用主色且默认聚焦 → 回车误删
- 不说明后果 → 不知道删了什么、能否恢复
- 文案只写「确定 / 取消」→ 看不出确认的是什么动作
- 拿它塞表单一 → 职责越界，应用模态

## 边界与代价
- 危险确认：确认按钮用**危险色**，默认焦点**不落在危险按钮**，文案点明对象与可恢复性
- 批量操作点名数量（将影响 N 项）
- 泛滥使用会降低整体安全感，只在真正需要处使用
- 带补充输入只用于最高风险场景，普通确认不应加负担
