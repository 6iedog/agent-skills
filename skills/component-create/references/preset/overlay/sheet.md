# 全屏 / 半屏层

从屏幕底部升起的**移动端页面级浮层**，占据半屏或整屏，承载本可用模态 / 抽屉提供的内容。

## 角色与边界

- **是什么**：附着在视口底部的浮层，可停在半屏高度、也可上拉为全屏；内部承载一段完整的页面内容。
- **解决什么**：窄屏空间不足，无法像桌面那样用侧边抽屉 / 居中模态承载表单、选择器、详情——用底部升起的层给出足够空间与清晰的开合手势。
- **不解决什么**：
  - 桌面宽屏布局 → 用模态框 / 抽屉更合适（本组件为移动优先）
  - 只是一句提示 → 消息提示 / 工具提示
  - 需要用户必须处理才能继续的强打断 → 模态框（本组件是可关闭的容器，不强制阻断）
  - 从侧边滑入的导航 → 抽屉
- **什么时候不用**：
  - 内容很少、一两行可内联完成 → 就地展开或气泡卡片
  - 宽屏主场景 → 不要为了「统一」而在桌面也升起底部层，会显得空洞
  - 需要与底层同屏对照阅读 → 抽屉 / 分栏

## UI

### 结构解剖
- **遮罩**：层后方的半透明背景，隔离底层内容
- **容器**：从底部升起的面板本体，圆角位于顶部两角
- **拖拽手柄**：容器顶部中央的小横条，提示可上下拖拽
- **标题栏（可选）**：标题 + 关闭按钮，可含辅助操作
- **内容区**：主体，承载表单 / 列表 / 选择器等
- **底部操作区（可选）**：主 / 次按钮，固定在容器底部
- **安全区留白**：顶部（刘海 / 状态栏）与底部（横条）的额外内边距

### 尺寸与外观变体
- **全屏**：占据整个视口，常用于复杂表单 / 多步流程 / 详情
- **半屏（底部）**：停在约屏幕一半高度，常用于选择器 / 快捷操作
- 高度档位：半屏 / 全屏 / 自定义吸附点
- **可拖拽高度**：可在半屏与全屏之间拖动并吸附
- 标题栏：有 / 无；关闭按钮位置
- 是否带底部操作按钮区

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| closed | 容器移出视口，遮罩不可见 |
| opening | 遮罩淡入、容器自底向上位移进入 |
| half（半屏停靠） | 容器顶部停在半高吸附点 |
| full（全屏停靠） | 容器铺满视口，仅顶部保留圆角或直接顶到安全区 |
| dragging | 手指拖动中，遮罩透明度随高度**联动变化** |
| releasing | 松手后按速度 / 位置吸附到最近档位 |
| closing | 容器下移、遮罩淡出 |
| scrollable | 内容超一屏时内部可滚动 |

- **遮罩与背景有视觉关联**：容器越高遮罩越深，越低遮罩越浅，形成层次感并预示关闭阈值。

### 布局与对齐 / 定位
- 容器贴底、横向占满（或接近占满）视口宽度
- 拖拽手柄居中于容器顶部
- **吸附点**：常见为「半屏 / 全屏」两档；拖动到位或按速度决定吸附目标
- 内容区独立滚动，标题栏与底部操作区**固定不滚**（sticky）
- 顶部安全区（刘海 / 状态栏）与底部安全区（横条）必须留白，避免内容被遮挡

### 移动端
- 面向触摸：拖拽手柄、下拉关闭、边界回弹
- **内部滚动与系统下拉刷新的冲突**：内容已滚到顶部时继续下拉，应表达为「下拉关闭本层」而不是触发页面刷新；需在容器内拦截并区分
- **软键盘遮挡**：输入框聚焦时视口高度变化，容器与按钮需随之上移，确保输入与主按钮可见
- 触摸目标 ≥ 44×44

## 交互

### 触发与开合
- 打开：从底部升起，同时遮罩淡入
- 打开时应**锁定底层滚动**（body 不随手指滚动）
- 关闭：关闭按钮、拖拽到下方超过阈值、点击遮罩、系统返回
- 打开后初始停在：半屏（若内容少）/ 全屏（内容一屏以上）

### 关闭行为
- **下拉手势关闭**：从手柄 / 顶部区域向下拖，超过速度或位移阈值即关闭；未达阈值回弹
- 点击遮罩 → 关闭（若该流程允许轻量取消）
- 关闭按钮 → 关闭
- **系统返回键（Android）** → 关闭本层；若层内还有子级（如子选择器）先关子级
- **iOS 边缘返回手势** → 一般由系统接管；底部层不应与页面侧滑返回冲突，必要时禁用层内水平滑动
- 关闭时若键盘处于打开状态，先收键盘再收起容器，避免高度跳变

### 键盘
| 键位 | 行为 |
|---|---|
| `Tab` / `Shift+Tab` | 在层内可聚焦元素间移动，**不逃逸到遮罩后** |
| `Esc` | 关闭本层（外部键盘场景） |
| `Enter` / `Space` | 触发当前聚焦的按钮 |
| 系统返回键 | 关闭本层 / 先关子级 |

- 键盘焦点**限定在层内**（层为顶层的临时视图）。

### 指针与手势
- 拖拽手柄：上下拖动改高度，松手吸附
- 从顶部下拉关闭
- 内部列表滚动到边界后继续下拉：转为关闭意图（而非页面刷新）
- 内部横向滑动组件（轮播等）不得与关闭手势冲突

### 焦点管理
- 打开：焦点进入层内（首个可聚焦元素或标题栏）
- 关闭：焦点**归还触发元素**，不丢到 body
- 层内子选择器打开 / 关闭时，焦点在子级与层间正确流转
- 遮罩后的内容对键盘不可达

### 动画与过渡
- 开：容器自底上移 + 遮罩淡入，约 200–300ms，带缓出
- 关：容器下移 + 遮罩淡出
- 高度吸附：松手后平滑过渡到目标档位
- 遮罩透明度随拖动高度**实时联动**
- 键盘弹出导致的位移要平滑，不出现突兀跳动

### 反馈
- 拖拽到关闭阈值附近可有轻微反馈（如遮罩变浅提示即将关闭）
- 提交类操作由内容区自行给反馈（加载 / 成功 / 失败）
- 关闭本身无需额外提示

### 边界交互
- 内容超一屏：内部滚动，标题栏与底部按钮固定
- 软键盘弹出：容器可上移，底部按钮保持可见
- 安全区：内容与按钮避开刘海与底部横条
- 快速连点遮罩 / 返回：关闭防抖
- 网络 / 异步内容：打开时加载，失败在层内显示错误与重试

## 数据流

### 输入
- **内容**：由使用方传入的任意页面内容（表单 / 列表 / 选择器）
- 配置：初始档位（半屏 / 全屏）、是否可拖拽、是否显示手柄、是否显示关闭、遮罩是否可点关闭、标题
- 触发上下文：打开时的来源（哪个按钮 / 哪一行）

### 内部状态
- open（开合）
- 当前高度档位（half / full / 自定义）
- 拖拽进度（用于遮罩联动与阈值判断）
- 内容滚动位置
- 键盘 / 视口高度变化状态

### 输出
- open / close 事件
- 档位变化事件（半屏 ↔ 全屏）
- 关闭原因（按钮 / 遮罩 / 手势 / 返回键）——便于区分「取消」与「完成」
- 内容区提交结果由内容区自身抛出

### 受控 / 非受控
- 非受控：内部自管开合与档位
- 受控：open 与档位由外部持有，组件抛出请求
- **二选一必须明确**；受控档位时拖拽结束需把目标档位抛回外部确认

### 异步与竞态
- 打开即加载内容的场景：处理加载 / 空 / 错误
- **竞态**：关闭后又立即重开、或快速切换内容时，丢弃过期请求结果
- 关闭动画期间重新打开：需取消关闭动画，避免状态错乱

### 校验与错误
- 本组件不承担校验；表单校验由内部表单实现
- 若内容含必填且用「完成」关闭，需保证校验失败时**不关闭**并提示

### 回填与序列化
- 组件本身不持有业务值；内容区的初值通过内容传入
- 关闭原因可用于决定「确认提交」还是「丢弃」——必须明确区分取消与完成

## 无障碍
- 容器：`dialog`（模态语义）或明确的区域角色，并标注可访问名称（标题）
- 打开时焦点进入层内，关闭时归还触发元素
- 层内焦点循环，遮罩后内容对键盘 / 屏幕阅读器不可达
- 提供可被辅助技术触达的关闭方式（关闭按钮），不能只依赖手势
- 拖拽高度纯视觉增强，不承载唯一交互——所有功能都必须有非手势替代
- 安全区留白不影响可访问名称与顺序

---

## 常见误用
- 在桌面宽屏也用它 → 内容被拉得很空，应换模态 / 抽屉
- 不能下拉关闭又没有明显关闭按钮 → 用户被困住
- 输入框被软键盘遮挡 → 无法看清输入与主按钮
- 半屏内容超出却不支持上拉 / 滚动 → 内容被截断
- 内部下拉滚动到顶误触发页面刷新 → 手势冲突
- 忽略安全区 → 内容被刘海 / 底部横条遮挡
- 关闭原因不区分 → 「取消」与「完成」被混为一谈导致误提交

## 边界与代价
- **必须**提供明确关闭方式（关闭按钮 / 下拉手势 / 返回键），至少一种可被辅助技术触达
- **必须**处理软键盘遮挡与视口高度变化
- 内容超一屏**必须**支持内部滚动，不截断
- **必须**处理下拉刷新与关闭手势的冲突，以及顶部 / 底部安全区留白
- 系统返回键（Android）与 iOS 边缘返回需明确映射，避免与层内手势冲突
- 与抽屉 / 模态的边界：宽屏用侧边或居中容器，本组件是移动端页面级承载形态
