# 加载中

一个旋转的指示图形，告诉用户「系统正在处理，请稍候」，可独立居中显示，也可包裹在内容 / 页面之上。

## 角色与边界

- **是什么**：持续旋转的视觉符号（可配说明文字），表示处理中，不预示进度也不预示结构。
- **解决什么**：**时长与结构都不确定**的等待——接口请求、后台运算、页面切换，给出「没死机、在工作」的信号。
- **不解决什么**：
  - 不解决「已知内容结构的加载」 → 骨架屏
  - 不解决「有百分比的耗时任务」 → 进度条
  - 不解决「加载失败」 → 错误态 / 结果页
  - 不解决「操作结果反馈」 → 全局提示
- **什么时候不用**：加载在约 300ms 内完成 → 不显示（避免闪烁）；已知内容形状 → 骨架屏；能估算进度 → 进度条。

## UI

### 结构解剖
- **旋转图形**：环形 / 弧线 / 点阵等循环动画
- **说明文字**：可选的一行提示（如「加载中…」「正在提交」）
- **遮罩层**：全屏 / 局部半透明蒙层，用于隔绝交互
- **容器**：独立居中版 / 包裹内容版（叠加在目标区域中央）

### 尺寸与外观变体
- 尺寸：小（内联于按钮 / 行内）/ 中 / 大
- 形态：独立式（自己占一块居中）/ 包裹式（套在别的元素或区域上）
- 遮罩：无 / 局部遮罩 / 全屏遮罩
- 文字：无 / 有说明
- 主题：浅色 / 深色下保持可读对比

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| active | 图形匀速旋转，持续循环 |
| 内联小尺寸 | 常与文字同行，用于按钮 / 标签内 |
| 包裹内容 | 覆盖在目标区域中央，内容可被淡化 |
| 全屏遮罩 | 覆盖整个视口，阻断背景交互 |
| 延时未达 | 处于延时窗口内时**不显示**（避免闪烁） |
| disabled | 无（加载态本身即不可交互） |
| 深色主题 | 图形颜色随主题适配，保持可见 |

### 布局与对齐
- 独立式：在容器内**水平垂直居中**
- 包裹式：居中于被包裹区域的中央，不改变被包裹内容尺寸
- 说明文字在图形下方居中，与图形保持间距
- 尺寸与所在场景匹配：按钮内用小，整页等待用大

### 移动端
- 全屏遮罩下的尺寸适中，配可读文字
- 触摸环境下遮罩须真正拦截点击，防重复提交
- 避免动画过重导致低端设备卡顿

## 交互

### 触发与出现（核心操作）
- 由「加载中」状态驱动显示，加载结束即隐藏
- **延时出现**：超过短阈值（如约 200–300ms）才显示，避免快速请求闪一下
- **最短展示时长**：若已显示，则至少停留一小段，避免出现即消失的抖动

### 交互行为
- 独立式：不承载交互
- 包裹式 / 全屏遮罩：**阻断被覆盖区域的交互**，防止加载中重复触发
- 全屏遮罩时应锁滚动（可选，视场景）

### 键盘
| 键 / 操作 | 行为 |
|---|---|
| `Tab` | 加载图形不进入焦点序列 |
| 遮罩期间 | 焦点应被限制在当前区域（若有），避免跑到被遮挡元素上 |

### 指针与手势
- 无主动指针行为
- 遮罩层拦截点击，防止穿透触发底层操作

### 焦点管理
- 加载图形**不被聚焦**
- 全屏遮罩期间，若页面仍有可聚焦元素，需确保它们不可达或被禁用
- 加载结束移除遮罩后，焦点回到合理位置，不丢失

### 动画与过渡
- 匀速循环旋转，节奏恒定、无跳变
- 遵循「减少动态」偏好时改用更平缓的方式（如弱淡入淡出）
- 遮罩淡入淡出，约 150–250ms

### 反馈
- 加载即反馈：让用户知道请求已发出
- 若等待时间可能很长，附说明文字以缓解焦虑
- 超时后应转为错误态，不能无限旋转

### 边界交互
- **永不结束**：必须有超时兜底，否则永远转
- **重复触发**：遮罩须阻挡第二次点击
- **并发请求**：多个加载态叠加时需正确计数，全部结束才隐藏

## 数据流

### 输入
- `loading`：是否加载中
- 尺寸、形态（独立 / 包裹）
- 是否遮罩（无 / 局部 / 全屏）
- 说明文字
- 延时阈值 / 最短展示时长
- 被包裹的目标（包裹式时）

### 内部状态
- 延时计时器（是否已达显示阈值）
- 最短展示计时器
- 遮罩的进入 / 退出过渡状态

### 输出
- 一般无输出事件
- 可选：超时事件、显隐切换事件（供埋点）

### 受控 / 非受控
- **强受控**：`loading` 由外部持有，组件只渲染与做显隐节流
- 延时 / 最短时长属内部行为，可配置

### 异步与竞态
- 快速切换（loading 频繁 true/false）时，需重置计时器避免闪烁
- 并发多个请求时，外部应按计数聚合为一个 `loading`，避免加载态忽隐忽现
- 组件卸载后清理计时器与动画

### 校验与错误
- 加载态不负责结果判断
- **超时必须兜底**为错误态，不能只靠旋转
- 失败后须能退出加载态，防止「转不停」

### 回填与序列化
- 无值可回填或序列化
- 与数据源解耦，可复用于任意异步场景

## 无障碍
- 加载图形对读屏隐藏（装饰）；
- 用 `aria-busy="true"` 标注加载中的容器，完成后移除
- 提供对读屏可见的「正在加载」文本（可视觉隐藏）
- 遮罩期间确保被遮挡内容不可被聚焦 / 不可交互
- 遵循「减少动态」偏好，弱化旋转
- 说明文字应真实可读，不只是一个空转的图形

## 常见误用
- 已知内容结构仍用居中转圈 → 应使用骨架屏（更少跳动）
- 加载极快也显示 → 出现即消失，闪烁
- 用加载中表达「加载失败」或「没有数据」→ 应分别是错误态 / 空状态
- 遮罩不拦交互，用户重复点击导致重复提交
- 无超时兜底，接口挂了页面一直转

## 边界与代价
- 加载 < 约 300ms：应延时出现，否则闪一下更糟
- 全屏遮罩 + 长等待：用户既不能操作也看不到进展，体验差，应改进度或骨架
- 并发计数不聚合：加载态抖动
- 旋转动画过重：低端设备掉帧
- 无超时：永久旋转，用户无法判断是否卡死
- 遮罩期间焦点未隔离：读屏 / 键盘仍可到达被遮内容
