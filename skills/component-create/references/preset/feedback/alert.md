# 警告提示

内嵌在内容流里的一条**常驻提示条**，按类型（信息 / 成功 / 警告 / 错误）传达与当前页面或操作相关的信息，不会自动消失。

## 角色与边界

- **是什么**：占据页面一块固定区域的提示条，随内容一起排版，用户可随时回看。
- **解决什么**：需要用户**注意到并理解**、且可能反复查看的信息（如「当前为只读模式」「表单有 3 处需修正」「该操作不可撤销」）。
- **不解决什么**：
  - 不解决「一次操作做完就走的短反馈」 → 全局提示
  - 不解决「异步事件 + 标题 + 描述 + 操作」的浮层 → 通知提醒
  - 不解决「必须用户点确认才能继续」 → 确认弹窗
  - 不解决「单个表单字段的格式错误」 → 表单项自身的错误态
  - 不解决「页面为空 / 加载失败」的整页占位 → 空状态 / 结果页
- **什么时候不用**：信息看一眼即可、无需回看 → 全局提示；信息强阻塞主流程 → 确认弹窗 / 模态；只是页内一句说明 → 普通说明文字。

## UI

### 结构解剖
- **类型图标**：随类型变化的图标，是快速识别的主要线索
- **标题**：一句话结论（可选）
- **说明文字**：补充正文（可选；可与标题二选一或并存）
- **操作区**：一个或多个内联操作（文字按钮 / 链接），如「重试」「查看详情」
- **关闭按钮**：可关闭时出现在右上或行尾
- **横幅式变体**：去掉圆角与左右外边距、通栏铺满容器或页面顶部

### 尺寸与外观变体
- 类型：信息 / 成功 / 警告 / 错误
- 语气：常规（圆角卡片）/ 横幅式（通栏强调）
- 内容：仅标题 / 标题 + 说明
- 可关闭：可关闭 / 不可关闭 / 由外部控制是否显示
- 操作区：无 / 单操作 / 多操作
- 外观：填充底色 / 浅色底 + 边框 / 左侧色条

### 视觉状态（逐条）
| 状态 | 外观 |
|---|---|
| info | 中性色系，传达说明性信息 |
| success | 正向色系，传达已成功 |
| warning | 警示色系，传达需注意但未出错 |
| error | 错误色系，传达已出错或高风险 |
| 横幅式 | 通栏、无圆角，弱化「卡片」感、强化「系统级」感 |
| 可关闭 | 显示关闭按钮，悬停时按钮更明显 |
| 关闭中 | 高度收拢 + 淡出，不留下空隙 |
| 禁用（无操作） | 若操作项被禁用，需有禁用样式且不可点 |

- **类型 ≠ 严重度随机分配**：错误色只用于「出错 / 高风险」，警告色用于「可能有问题」，不要为吸引眼球滥用错误色。

### 布局与对齐
- 图标与首行文字**顶对齐**，而非整块垂直居中（多行文本时更稳）
- 说明文字与标题左对齐，缩进对齐标题文本（不顶到图标下）
- 操作区在文字下方或行尾；多条操作按主次排列
- 横幅式通栏时内容左右内边距与页面栅格一致

### 移动端
- 优先横幅式或整宽，避免窄卡片挤压文字
- 关闭按钮触摸目标 ≥ 44×44，靠边时留出安全间距
- 长文案允许换行，不截断关键信息

## 交互

### 触发与出现（核心操作）
- 由外部条件或数据决定是否渲染，出现即常驻，**不自动消失**
- 可出现于：页面顶部、表单上方、区块内、对话框内
- 关闭：点关闭按钮 / 点操作项后按逻辑收起（由外部状态决定）

### 操作与反馈行为
- 点击操作项：执行对应动作（重试 / 跳转 / 展开详情），动作结果由外部反馈
- 关闭：仅收起本条；是否记住「不再显示」由外部决定
- 关闭**不代表问题已解决**，不要用关闭代替修复

### 键盘
| 键 / 操作 | 行为 |
|---|---|
| `Tab` | 依次聚焦操作项、关闭按钮 |
| `Enter` / `Space` | 触发聚焦的操作项 / 关闭 |
| `Esc` | 一般**不**关闭（非浮层）；若为浮层化横幅可选关闭 |

### 指针与手势
- 点击关闭按钮收起
- 无拖拽行为（如需可关闭的浮层，用通知提醒）

### 焦点管理
- 出现时**不抢焦点**（它是被动信息，不是对话框）
- 若因操作结果导致页面重排，注意焦点不要丢失
- 关闭后焦点处理：若关闭按钮获得了焦点，关闭后焦点回到合理位置（如页面主体）

### 动画与过渡
- 出现 / 消失：高度展开收拢 + 淡入淡出，约 150–250ms
- 不得引起周围内容的剧烈跳动；列表式多条依次入场时错开延迟

### 反馈
- 点击操作项需给出明确的加载 / 结果反馈（不自带则须联动其他反馈组件）

### 边界交互
- **多条堆叠**：同一区域出现多条时，需明确是纵向堆叠还是只显示最严重一条
- **超长文案**：换行而非截断；补齐「查看详情」展开
- **可关闭的重要警告**：若为本可避免的错误，允许关闭但需外部记录

## 数据流

### 输入
- 类型：info / success / warning / error
- 标题、说明文字
- 操作项列表：`{ 文案, 类型, 回调 }`
- 是否可关闭
- 是否横幅式
- （受控时）是否显示

### 内部状态
- 本条是否已关闭（可关闭且非受控时）
- 展开 / 收起（若说明文字可展开）
- 内容区的进入 / 退出过渡状态

### 输出
- 关闭事件（供外部埋点或记录）
- 操作项点击事件（携带操作标识）
- 是否「不再提示」被勾选

### 受控 / 非受控
- **显示与否**：受控优先（外部决定何时出现、何时消失），组件只上报关闭意图
- 若允许组件内部关闭，则父层需能同步这一状态，避免「关了又冒出来」

### 异步与竞态
- 操作项触发异步（如重试）时，需在操作项上给出进行中 / 禁用态，防重复点击
- 若内容来自远程（如错误详情），需处理加载 / 失败

### 校验与错误
- 组件自身不做校验，只**呈现**校验结论
- 「表单有 N 处错误」这类汇总提示，须与字段级错误保持一致、可跳转定位

### 回填与序列化
- 「不再显示」若需持久化，应存于用户偏好而非组件内部，并可在设置中恢复

## 无障碍
- 错误 / 警告类：`role="alert"`，出现即被读屏播报
- 信息 / 成功类：`role="status"`（礼貌播报，不打断当前朗读）
- 类型不能只靠颜色区分，须同时有图标与文字
- 操作项为真实可聚焦控件，`focus-visible` 可见
- 关闭按钮有可读的名称（如「关闭提示」）

## 常见误用
- 用警告提示做「操作成功」的一次性反馈 → 应使用全局提示
- 把错误色当强调色到处用，导致真正出错时失去警示力
- 关键错误做成「可关闭」，用户一关就当没发生
- 一条提示塞进整段说明，缺少标题与层次
- 横幅式提示遮挡了页面主操作（如顶栏按钮）

## 边界与代价
- 同一区域堆叠 > 2–3 条：需合并或只留最严重一条
- 可关闭的关键错误：必须同时在别处留痕（日志 / 待办）
- 文案超过约 2 行：应收起为标题 + 可展开详情
- 颜色是唯一区分手段：色觉障碍用户不可用
- 用关闭动画替代真实修复：问题仍在，只是看不见
