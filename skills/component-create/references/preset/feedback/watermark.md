# 水印

把重复的**文字或图片标记**平铺叠加在内容之上，用于标识来源、版权或保密级别；只做视觉覆盖，**不拦截任何交互**。

## 角色与边界

- **是什么**：覆盖在容器内容表层、按网格重复的浅色标记（如用户名、时间、ID、logo）。
- **解决什么**：内容溯源与泄露威慑——截图 / 拍照外带时仍带着归属与时间信息，起到「留痕」作用。
- **不解决什么**：
  - 不解决「真正的访问控制 / 加密」 → 权限系统、密级控制
  - 不解决「可见的品牌展示」 → 普通 logo / 图标
  - 不解决「内容自身的版权声明文本」 → 页面内的说明文字
  - 不解决「防止截图」——水印只能威慑，无法阻断
- **什么时候不用**：需要真正阻断未授权访问 → 权限；只是展示一次品牌标识 → 普通图标；内容本身对遮挡极敏感（如精细图表）→ 慎用或大幅降透明度。

## UI

### 结构解剖
- **标记内容**：文字（用户名 / 时间 / 工号 / ID / 保密提示）或图片（logo）
- **平铺网格**：标记按固定行距、列距重复排列，铺满整个容器
- **叠加层**：位于内容之上的独立层，贯穿容器尺寸
- **可选单条居中水印**：大号半透明标记置于中央（区别于平铺）

### 尺寸与外观变体
- 类型：文字水印 / 图片水印 / 图文混排
- 排列：平铺重复 / 单条居中
- 密度：行距 / 列距（由间距参数决定疏密）
- 旋转：水平 / 倾斜（常见约 -30° 至 -45°）
- 透明度：浅（弱干扰）/ 常规 / 深（强提示）
- 内容：单个字段 / 多字段拼接（用户 + 时间 + ID）

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| 常态 | 浅色重复标记，低对比、不喧宾夺主 |
| 深色内容 | 需在深浅背景上都可辨，常带轻微描边或双重色 |
| 密集模式 | 间距更小、标识更多，干扰更强 |
| 稀疏模式 | 间距更大，干扰更小但更易被裁掉 |
| 单条居中 | 仅一块大标记，视觉更克制 |
| 内容加载完成 | 水印层仍在最上层，不被内容覆盖 |
| 容器尺寸变化 | 自适应重排铺满，不留空白带 |

### 布局与对齐
- 覆盖**整个目标容器**（含滚动区域可见部分），不留边角空白
- 网格相对容器对齐，随容器尺寸变化重排
- 位于内容之上（高层级），但**不改变内容布局尺寸**
- 旋转时以网格单元中心为轴，避免边缘截断产生断带

### 移动端
- 密度不宜过高，避免小屏上过于眼花
- 字号相应缩小但保持可辨
- 不因水印影响内容的可滚动与点按

## 交互

### 触发与呈现（核心操作）
- 随容器渲染即出现，无需用户操作
- 全生命周期叠加在内容之上，直到容器卸载
- 内容动态变化（滚动、翻页）时不重复创建，只随容器重排

### 交互行为
- **完全不拦截交互**：水印层对指针「透明」，底层内容照常可点、可选、可滚动
- 不承载任何按钮 / 链接
- 不作为可选择文本的一部分（避免复制时带入水印串）

### 键盘
| 键 / 操作 | 行为 |
|---|---|
| `Tab` | 水印层不进入焦点序列 |
| — | 无键盘交互 |

### 指针与手势
- 指针可穿透水印层操作底层内容
- 拖拽 / 滚动事件不受水印影响

### 焦点管理
- 水印**不作为焦点目标**
- 不改变任何已有焦点行为

### 动画与过渡
- 一般无动画
- 若需防篡改，可让标记位置随内容轻微重排；**不建议**做闪烁等干扰性动效
- 遵循「减少动态」偏好，去除任何不必要的动态

### 反馈
- 无反馈职责（纯展示）

### 边界交互
- **动态高度容器**：内容变高时水印需覆盖新增区域
- **滚动容器**：确认水印是覆盖可视区还是整个滚动内容——后者会随内容滚动
- **打印 / 导出**：需确保水印一并输出（否则形同虚设）
- **嵌套容器**：避免多层水印叠加导致过暗

## 数据流

### 输入
- 内容：要展示的文字（可拼接用户、时间、ID 等）或图片源
- 字体 / 字号 / 粗细 / 颜色
- 行距、列距（密度）
- 旋转角度
- 透明度
- 排列方式：平铺 / 单条居中
- 目标容器尺寸或占满父容器

### 内部状态
- 容器的**实测尺寸**（用于计算平铺数量与网格）
- 随尺寸变化的重排结果
- 标记内容（若异步获取，如当前用户名）

### 输出
- 一般无输出事件
- 可选：水印渲染完成事件（供埋点）

### 受控 / 非受控
- **强受控**：内容、密度、样式由外部提供
- 组件内部只做尺寸测量与平铺计算
- 水印内容不应由组件自行拼装业务字段，拼接规则属于外部

### 异步与竞态
- 若水印内容来自异步（用户信息 / 服务端下发），需在拿到后再渲染，避免先空后闪
- 内容更新（如切换用户）时需整体刷新水印
- 容器尺寸频繁变化（响应式 / 折叠）时需节流重排

### 校验与错误
- 内容为空时**不应渲染空水印**，避免诡异空隙
- 图片水印加载失败需降级为无（或文字），不能留下空白块
- 不负责业务校验

### 回填与序列化
- 水印内容常需**持久化来源信息**（时间戳、用户），以便溯源
- 内容应可从当前会话 / 服务端稳定回填，刷新后一致

## 无障碍
- 水印层对读屏**整体隐藏**（`aria-hidden`），避免反复播报相同文字造成噪音
- 若水印承载**保密提示**等必要信息，应在页面内有等价的可读文本，而非仅靠水印
- 不参与焦点、不拦截键盘与指针
- 颜色对比不宜过低到完全不可见，也不宜高到遮盖内容
- 不使用闪烁动效，避免触发光敏不适

## 常见误用
- 把水印当作安全屏障，以为能防泄露 → 它只是威慑，需配合权限
- 水印层拦截了点击 / 滚动，导致内容无法操作
- 透明度过高，遮住正文影响阅读
- 只覆盖可视区而打印 / 导出时丢失 → 留痕失效
- 水印文字被读屏逐条播报，干扰使用
- 密度过大，密集重复造成视觉噪音

## 边界与代价
- 水印**无法真正防止截图 / 拍照**：只能溯源与威慑，安全仍靠权限
- 透明度与干扰度是取舍：太淡易被裁掉，太浓影响阅读
- 单条居中水印容易被裁切 / 涂抹，平铺更难去除
- 深色与浅色内容混合：单一颜色的水印会有一侧看不清
- 动态容器不重排：内容变长后下部无水印，留出可利用空白
- 打印 / 导出未随行：水印存在感形同虚设
- 大容器高分屏下计算与渲染开销：需控制网格密度
