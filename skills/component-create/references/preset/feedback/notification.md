# 通知提醒

从屏幕**角落滑出**的浮层卡片，含标题、描述与可选操作，用于传达需要用户**留意但不立即打断**的异步事件。

## 角色与边界

- **是什么**：带更多信息的浮层通知卡片，通常固定在视口一角，可堆叠多条。
- **解决什么**：把「后台发生的事」告知用户——任务完成、收到新消息、系统升级提示——信息量比一行提示更大，且可携带操作。
- **不解决什么**：
  - 不解决「一行轻量的即时反馈」 → 全局提示
  - 不解决「常驻页面、需要回看」的说明 → 警告提示
  - 不解决「必须处理完才能继续」 → 模态对话框
  - 不解决「整页流程结论」 → 结果页
- **什么时候不用**：内容只有一句话且看一眼即可 → 全局提示；与当前操作强相关、需要马上读 → 警告提示（内嵌）；会打断用户当前任务 → 模态。

## UI

### 结构解剖
- **类型图标**：信息 / 成功 / 警告 / 错误
- **标题**：一行结论
- **描述**：补充说明，可多行、可含链接
- **操作区**：一个或多个按钮（如「查看」「稍后」）
- **关闭按钮**：通常在右上角
- **时间 / 来源**：可选，标注事件时间或来源系统
- **容器**：固定定位卡片，从指定角落滑入并堆叠

### 尺寸与外观变体
- 类型：info / success / warning / error
- 弹出位置：右上 / 右下 / 左上 / 左下（默认右上，避免遮挡主操作区）
- 是否带操作区
- 持续时间：自动关闭 / 永不自动关闭（需手动）
- 尺寸：常规卡片 / 紧凑单行

### 视觉状态（逐条）
| 状态 | 外观 / 行为 |
|---|---|
| entering | 自对应边滑入 + 淡入 |
| visible | 停留，倒计时进行中 |
| hover | 悬停暂停倒计时、显示关闭按钮 |
| leaving | 向对应边滑出 + 淡出 |
| 堆叠 | 多条纵向排列，新的出现在同侧 |
| 超出上限 | 更早的条目被折叠为「+N」或移出 |
| 已读 | 若与消息中心联动，标记已读并弱化 |

### 布局与对齐
- 固定在视口某角，与边缘保持安全间距
- 多条纵向堆叠，间距一致；新条目插入位置固定（一般最靠近角落）
- 堆叠占满高度时，内部滚动或折叠计数
- 卡片内标题在上、描述居中、操作在下，左对齐

### 移动端
- 常改为**顶部整宽**或底部滑入，避免角落卡片过窄
- 触摸目标 ≥ 44×44
- 不依赖 hover，关闭按钮默认可见
- 单条宽度接近整宽，留安全边距

## 交互

### 触发与出现（核心操作）
- 通常由**异步事件**驱动（轮询 / 长连接 / 后台任务回调）或命令式调用
- 从角落滑入；按设置**自动关闭**或**保持直到手动关闭**
- 关闭：点关闭按钮 / 点操作项后按逻辑关闭 / 点击卡片跳转

### 操作与消失行为
- 点击操作项：执行对应动作并通常关闭本条（由外部决定）
- 点击卡片主体：可跳转详情（此时整卡可作为可点击区域）
- 多条同时到达：按队列 / 堆叠展示，不能互相覆盖

### 键盘
| 键 / 操作 | 行为 |
|---|---|
| `Tab` | 若可达，依次聚焦操作按钮与关闭 |
| `Enter` / `Space` | 触发聚焦的操作 / 关闭 |
| `Esc` | 可选：关闭最上一条 |

- 若通知不被 Tab 捕获，须保证带操作的通知仍有可达路径（如消息中心）。

### 指针与手势
- 点击关闭 / 操作
- 悬停暂停倒计时
- 移动端可选**滑动关闭**（横向滑出）

### 焦点管理
- 出现时**不抢焦点**（异步通知不应打断输入）
- 若整卡可点击，须提供键盘等价操作
- 关闭一条后，焦点应回到合理位置，不丢进无主状态

### 动画与过渡
- 进入 / 退出：滑入滑出 + 淡入淡出，约 200–300ms
- 多条重排时平滑位移，不闪跳
- 折叠计数变化时给出轻微过渡

### 反馈
- 操作项点击后须有进行中 / 结果反馈
- 若通知代表进行中的任务，应有进度或状态更新（联动进度条 / 加载中）

### 边界交互
- **短时间多条到达**：限流 / 合并 / 折叠为计数，避免刷屏
- **永不自动关闭**：必须保证有明确关闭路径，否则堆积
- **超长描述**：限制行数或提供「展开 / 查看详情」
- **页面已不可见的通知**：转入消息中心，不静默丢失

## 数据流

### 输入
- 类型、标题、描述
- 操作项列表：`{ 文案, 回调, 类型 }`
- 弹出位置
- 持续时间（或「永不」）
- 是否可关闭
- 事件标识 / key（用于更新、去重、已读）

### 内部状态
- 全局**通知队列**
- 每条倒计时 / 悬停暂停标志
- 堆叠顺序与折叠计数
- 进入 / 退出过渡状态

### 输出
- 打开 / 关闭事件（含原因）
- 操作项点击事件
- 点击卡片跳转事件
- 已读状态变更（与消息中心联动时）

### 受控 / 非受控
- 命令式调用为主：外部触发「弹一条通知」，并拿到关闭句柄
- 若与消息中心/收件箱绑定，列表本身应是受控数据源，浮层只是它的一个视图
- 同 key 更新语义需明确：是替换内容还是新增一条

### 异步与竞态
- 高频事件要限流；同 key 通知应就地更新而非重复新增
- 长连接断线重连后，需去重已展示过的通知
- 页面切换 / 卸载时清理队列与计时器

### 校验与错误
- 组件不做业务校验；错误通知需带可读原因
- 重复失败的同源通知应合并，避免刷屏

### 回填与序列化
- 未读 / 已读状态若需持久化，存于消息数据源而非组件内部
- 刷新后，未处理的通知应由数据源重新提供，而非依赖浮层残留

## 无障碍
- 信息类：`role="status"`，`aria-live="polite"`
- 错误 / 警告类：`role="alert"`，`aria-live="assertive"`
- 类型不能仅靠颜色，须有图标与文字
- 自动关闭需留足阅读时间；有操作的通知不建议自动关闭
- 关闭与操作按钮有可读名称；整卡可点击时提供键盘等价
- 堆叠多条时，读屏应能感知新到条目而不重复播报旧条目

## 常见误用
- 拿通知提醒做「保存成功」等一次性轻反馈 → 应使用全局提示
- 与用户当前操作强相关的错误做成角落浮层，用户根本没看 → 应内嵌警告提示
- 弹出位置遮挡主操作区（如右下角挡住提交按钮）
- 全部设为自动关闭，用户来不及看到带操作的通知
- 同一事件重复弹多条，造成刷屏

## 边界与代价
- 同时可见 > 3–5 条：需限流 / 折叠计数
- 遮挡主内容或主操作：须选对角落并留安全间距
- 永不自动关闭 + 无关闭路径：必然堆积
- 描述超过约 3 行：应限制行数或引导至详情
- 依赖 hover 暂停：触摸端不成立，移动端需默认可关闭
- 纯浮层承载重要通知：页面刷新即丢，须有消息中心兜底
