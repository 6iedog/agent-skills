# 骨架屏

用一组**灰色占位块**预先勾出内容的大致结构，在真实内容到达前占据版面，降低空白感与加载后的布局跳动。

## 角色与边界

- **是什么**：模拟真实内容形状的占位图形（文本行、头像圆、图片矩形、按钮条），带轻量动画表示加载中。
- **解决什么**：**已知内容结构**的加载等待（列表、卡片、详情、表格），让用户提前预判页面布局，减少跳动。
- **不解决什么**：
  - 不解决「结构未知 / 时长未知的等待」 → 加载中
  - 不解决「有百分比的耗时任务」 → 进度条
  - 不解决「加载失败」 → 错误态 / 结果页
  - 不解决「真的没有数据」 → 空状态
- **什么时候不用**：加载在约 300ms 内完成 → 直接显示内容（骨架会一闪而过）；内容结构随数据变化、无法预判 → 用加载中；局部按钮的短等待 → 用按钮内的加载态。

## UI

### 结构解剖
- **占位图形**：文本行（短条）、头像（圆）、图片 / 缩略图（矩形）、按钮（圆角条）、标签（小圆角）
- **组合容器**：把上述基本块拼成与真实内容一致的结构
- **动画层**：闪烁或波光扫过
- **常见预设形态**：列表项骨架、卡片骨架、表格行骨架、详情 / 表单骨架、头像 + 两行文字骨架

### 尺寸与外观变体
- 形态：列表 / 卡片 / 表格 / 详情 / 头像文字混排
- 动画：无（静态）/ 闪烁（明暗脉动）/ 波光（高光扫过）
- 圆角：与真实元素一致（头像全圆、图片按内容圆角）
- 密度：占位行数 / 卡片数量可配
- 亮度：浅底 / 深色主题下的对应灰阶

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| 静态 | 仅有灰色块，无动画 |
| 闪烁（pulse） | 整体透明度规律脉动 |
| 波光（shimmer） | 高光自一侧扫向另一侧，循环 |
| 主题适配 | 深色模式下灰阶相应反转，仍保持低对比 |
| 过渡完成 | 内容就绪时骨架淡出、真实内容淡入，避免闪跳 |

### 布局与对齐
- 每个占位块的**位置与尺寸要与真实内容对应**，尤其是关键区块的高度与列宽
- 文本行宽度可参差（模拟真实换行），最后一行常更短
- 多块之间的间距与真实内容一致，避免加载完成后整体位移
- 表格骨架的列宽应与真实列对齐

### 移动端
- 占位数量相应减少，避免首屏全是灰块
- 高度与真实元素一致，保证加载完成不跳动
- 动画开销小，避免低端设备上抖动

## 交互

### 触发与出现（核心操作）
- 在数据加载开始时渲染，加载完成后由外部切换为真实内容
- **延时出现**：加载超过短阈值（如约 200–300ms）才显示，避免快速加载时闪一下
- 可用**最短展示时长**客服短暂闪烁

### 交互行为
- 骨架本身**不可交互**，不承载操作
- 若外层容器可点击（如可点卡片），骨架期间应避免误触或有明确处理
- 不响应悬停高亮等真实内容的交互态

### 键盘
| 键 / 操作 | 行为 |
|---|---|
| `Tab` | 骨架占位不进入焦点序列 |
| — | 无键盘操作 |

### 指针与手势
- 无指针交互（避免把占位误当可操作项）

### 焦点管理
- 骨架**不作为焦点目标**
- 切换为真实内容时**不抢焦点**（除非整页首次加载需重置到标题）
- 加载导致的内容替换不应使当前焦点元素消失无故丢失

### 动画与过渡
- 闪烁 / 波光循环，节奏恒定、避免过快引起烦躁
- 遵循「减少动态」偏好时降级为静态灰块
- 骨架 → 真实内容的切换用短淡入淡出，不产生跳动

### 反馈
- 骨架即「正在加载」的反馈
- 长时间停留（超过预期）时，可叠加说明或转为失败态

### 边界交互
- **加载失败**：必须切换到错误态 + 重试，不能永远停在骨架
- **加载超时**：超时后转为错误或「仍在加载，请稍候」
- **部分内容先到**：可先渲染已到达的部分，其余仍用骨架

## 数据流

### 输入
- 形态：列表 / 卡片 / 表格 / 详情 / 头像文字
- 占位数量 / 行数 / 列数
- 动画类型（静态 / 闪烁 / 波光）
- 是否启用延时 / 最短展示时长
- 是否正在加载（切换为真实内容的开关）

### 内部状态
- 延时计时器（是否已达阈值显示）
- 动画相位
- 骨架 ↔ 内容的切换过渡状态

### 输出
- 一般无输出事件
- 可选：加载超时事件、渲染完成事件（供埋点）

### 受控 / 非受控
- **强受控**：由外部传入「是否加载中」，组件只负责渲染对应形态
- 延时 / 最短时长属组件内部行为，可配置但不上报业务值

### 异步与竞态
- 快速连续切换（加载→完成→再加载）时，需取消 / 重置计时器，避免显示错乱
- 组件卸载后清理计时器与动画

### 校验与错误
- 骨架不负责校验；错误场景由外部切换到错误态
- 需保证「失败时不会残留骨架」——这是常见漏洞

### 回填与序列化
- 无值可回填或序列化
- 与数据源解耦：同一骨架形态可服务多个数据端点

## 无障碍
- 骨架对读屏**隐藏**（纯装饰），避免播报一堆无意义方块
- 加载状态用 `aria-busy="true"` 标注在容器上，并在完成后移除
- 可提供一句对读屏可见的「正在加载」文本（视觉隐藏）
- 遵循「减少动态」偏好，关闭闪烁 / 波光
- 深色主题下保持低对比，避免刺眼

## 常见误用
- 用骨架屏表示「真的没有数据」→ 应使用空状态
- 结构与真实内容差异大，加载完成后整页跳动 → 骨架的意义（防跳）失效
- 加载极快仍显示骨架 → 一闪而过，闪烁感
- 加载失败后骨架不消失 → 用户以为一直卡住
- 骨架块做成可点击 / 可聚焦，误导用户

## 边界与代价
- 加载 < 约 300ms：显示骨架反而更糟，应延时出现
- 骨架与真实结构不对齐：加载完成时布局跳动，伤害体验
- 骨架行数 / 卡片数与真实差异过大：加载后内容长度突变
- 动画过密或过快：在长列表上造成视觉噪音与性能压力
- 失败 / 超时无兜底：骨架会永久停留
- 深色主题未适配：灰阶突兀
