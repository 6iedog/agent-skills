# 全局提示

页面顶部居中**轻量弹出**的短消息，出现后**自动消失**，不打断当前操作，常用于一次性操作结果的即时反馈。

## 角色与边界

- **是什么**：脱离文档流的全局浮层小条（图标 + 一句话），短暂停留后自动退场。
- **解决什么**：把「刚才那个操作成没成」用最低打扰的方式告诉用户（保存成功、复制失败、网络异常）。
- **不解决什么**：
  - 不解决「需要标题 + 描述 + 操作」的浮层通知 → 通知提醒
  - 不解决「需要回看、常驻页面」的说明 → 警告提示
  - 不解决「必须确认才继续」 → 确认弹窗
  - 不解决「表单字段级错误」 → 表单项错误态
- **什么时候不用**：信息可能被用户回看 → 通知提醒 / 警告提示；结果是用户主动触发的整页流程结论 → 结果页；需要用户立刻决策 → 确认弹窗。

## UI

### 结构解剖
- **类型图标**：随类型变化，提供非颜色的识别线索
- **文字内容**：一行简短提示（可含少量强调），一般不换行或最多两行
- **关闭按钮**：可选；可关闭时鼠标移入更明显
- **操作链接**：可选，一条极短动作（如「撤销」「查看」）
- **容器**：全局浮层，固定在视口顶部水平居中，脱离内容流

### 尺寸与外观变体
- 类型：信息 / 成功 / 警告 / 错误 / 加载中
- 是否可关闭
- 是否带操作链接
- 停留时长：短（约 1.5s）/ 常规（约 3s）/ 长（约 5s，用于需阅读的内容）
- 位置：顶部居中（默认），也可顶部偏移避开固定顶栏

### 视觉状态（逐条）
| 状态 | 外观 / 行为 |
|---|---|
| entering | 自上方轻微位移 + 淡入 |
| visible | 停留，倒计时进行中 |
| hover（可关闭时） | 悬停**暂停倒计时**，关闭按钮显形 |
| leaving | 向上淡出 |
| 多条堆叠 | 纵向排列，新的一条出现在固定一侧 |
| 加载中 | 图标持续旋转，**不自动消失**，需手动/程序关闭 |
| 已关闭 | 从队列移除，下方条目上移补位 |

### 布局与对齐
- 默认**水平居中**、贴近视口顶部；有固定顶栏时向下偏移其高度
- 多条时纵向堆叠并保持间距，不重叠
- 相邻提示的进出不引起其余提示的抖动（用固定占位或平滑位移）

### 移动端
- 宽度接近整宽（留左右安全边距），避免过窄折行
- 顶部留出状态栏 / 刘海安全区
- 触摸环境下不依赖 hover，关闭按钮默认可见

## 交互

### 触发与出现（核心操作）
- 由**命令式调用**触发，不依赖在页面里预先放一个组件位置
- 出现后按设定时长**自动消失**
- 手动关闭：点关闭按钮 / 悬停暂停后再离开
- 加载中类型**不自动消失**，由后续成功 / 失败调用结束它

### 消失与替换行为
- 同一时刻多条：按**队列**依次或并排展示，不能互相顶掉到看不见
- 更新语义：某些场景用「同 key 更新」替换上一条（如连续保存），避免刷屏
- 关闭语义：手动关闭仅移除此条，不影响其他条

### 键盘
| 键 / 操作 | 行为 |
|---|---|
| `Tab` | 若可达，聚焦关闭按钮 / 操作链接 |
| `Enter` / `Space` | 触发聚焦的关闭 / 操作 |
| `Esc` | 可选：关闭当前（或最新）一条 |

- 建议默认**不被 Tab 捕获**（它是短暂通知），但若带可交互操作则须可达。

### 指针与手势
- 点击关闭按钮立即移除
- 悬停暂停倒计时（桌面端），移开后继续
- 不提供拖拽 / 滑动（保持轻量）

### 焦点管理
- **绝不抢占焦点**：出现时不得改变用户当前聚焦元素
- 若用户正在输入，提示不得使其失焦
- 不进入焦点陷阱；关闭后不改变原焦点

### 动画与过渡
- 进入 / 退出：轻微位移 + 淡入淡出，约 150–250ms
- 多条入场可错开，但整体节奏要快，避免拖沓
- 退出后其余条目平滑补位，不闪跳

### 反馈
- 提示本身就是反馈：成功用成功色，失败用错误色 + 简短原因
- 加载中提示须能被后续结果替换，不能悬停在那里无人收尾

### 边界交互
- **连续快速触发**：必须排队或按 key 合并，避免堆成一屏
- **上一条还未消失又来一条**：明确是叠加、替换还是丢弃旧条
- **时长设为「不自动关闭」**：必须保证有后续关闭路径，否则永不消失

## 数据流

### 输入
- 类型：info / success / warning / error / loading
- 内容文字（可含富文本片段）
- 停留时长（或「永不」）
- 是否可关闭
- 操作链接：`{ 文案, 回调 }`
- 更新标识（用于合并同 key 提示）

### 内部状态
- **全局队列**：当前展示中的提示列表
- 每条各自的**倒计时计时器**
- 悬停暂停标志
- 进入 / 退出过渡状态
- （合并模式下）key → 条目的映射

### 输出
- 每条关闭事件（含原因：超时 / 手动）
- 操作链接点击事件
- 队列长度变化（供外部限流）

### 受控 / 非受控
- 本质是**命令式 API**：通过全局方法调用（如「打开一条成功提示」），而非受控 prop
- 命令式也要提供关闭句柄，便于程序化收尾（尤其加载中）
- 若改为组件式声明，则需明确由外部维护队列，组件只渲染

### 异步与竞态
- 高频调用要限流 / 合并；后到的同 key 提示应更新而非新增
- 「先显示加载中 → 再显示成功」这一对调用必须有明确对应关系，避免错配
- 页面切换 / 卸载时，未结束的提示要能清理，不残留

### 校验与错误
- 组件不做业务校验；错误提示的内容由外部提供
- 同一操作重复失败时的重复提示需去重，避免刷屏

### 回填与序列化
- 一般不持久化；刷新页面后即丢失
- 若需跨路由保留，须由外部显式重建队列

## 无障碍
- 信息 / 成功：`role="status"`，`aria-live="polite"`
- 错误 / 警告：`role="alert"`，`aria-live="assertive"`，立即播报
- 类型同时以图标与文字表达，不只用颜色
- 自动消失的内容须留足阅读时间；过短（< 约 2s）对读屏与低视力不友好
- 关闭按钮有可读名称；若建议不被 Tab 捕获，也要确保带操作时可达

## 常见误用
- 把需要用户确认或被回看的信息做成自动消失的提示 → 会「错过就没了」
- 用错误提示但内容含糊（只说「失败」不讲原因）
- 多条同时涌出堆满屏幕，反而干扰操作
- 在表单输入中弹提示并抢走焦点，打断输入
- 用全局提示承载带标题、描述、多操作的通知 → 应升级为通知提醒

## 边界与代价
- 同一时刻可见 > 3 条：需限流或合并（常见上限 3–5 条）
- 停留 < 约 2s：用户来不及读完
- 内容超过两行：不适合此形态，改用通知提醒或警告提示
- 加载中类型忘记收尾：会永久停留在页面
- 依赖 hover 暂停：在触摸端不成立，移动端需默认可关闭
