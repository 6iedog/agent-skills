# 结果页

用一整块居中的页面（或区块）向用户交代**某个流程的最终结果**：成功、失败、警告、无权限、找不到、服务异常，并给出下一步操作。

## 角色与边界

- **是什么**：一个承载「状态图示 + 标题 + 说明 + 操作区」的整页 / 整块布局，用于流程收尾。
- **解决什么**：用户提交、支付、上传、访问某资源之后，需要明确知道**结果是什么、接下来做什么**。
- **不解决什么**：
  - 不解决「流程正常但没有内容」 → 空状态
  - 不解决「一次轻量操作结果」 → 全局提示
  - 不解决「需要用户确认才继续」 → 确认弹窗
  - 不解决「表单字段级错误」 → 表单项错误态
- **什么时候不用**：页面功能正常只是暂无数据 → 空状态；结果无需专门页面、就地反馈即可 → 全局提示 / 警告提示。

---

## UI

### 结构解剖
- **状态图示**：插画或状态图标，是情绪与类型的第一信号
- **标题**：一句话结论（如「提交成功」「页面不存在」）
- **副说明**：解释原因、影响或建议，可多行
- **操作区**：主按钮 + 次按钮（如「返回首页」「重试」「查看详情」）
- **附加内容**：结果相关的补充信息（订单号、金额、错误码、排查指引）
- **可选流程引导**：失败时列出可能原因与下一步

### 尺寸与外观变体
- 类型：成功 / 失败 / 警告 / 信息 / 无权限（403）/ 找不到（404）/ 服务异常（500）
- 展示范围：整页居中 / 卡片内区块 / 对话框内
- 图示：插画 / 图标 / 无
- 操作数：单操作 / 主次双操作 / 多操作

### 视觉状态（逐条）
| 类型 | 图示与色彩 | 典型标题与操作 |
|---|---|---|
| 成功 | 正向色系 + 完成图标 | 「提交成功」→ 返回 / 查看 |
| 失败 | 错误色系 + 失败图标 | 「提交失败」→ 重试 / 返回 |
| 警告 | 警示色系 + 提示图标 | 「部分成功」→ 查看详情 / 重试 |
| 信息 | 中性色系 | 「已提交审核」→ 返回 |
| 无权限 403 | 中性 / 警示 | 「暂无访问权限」→ 申请 / 返回 |
| 找不到 404 | 中性 | 「页面不存在」→ 返回首页 |
| 服务异常 500 | 警示 | 「服务开小差了」→ 重试 / 稍后再试 |
| 加载中（等待结果） | 过渡态 | 可用加载中占位 |

- **类型决定语气**：成功要正向但不浮夸，失败要说明**原因与出路**而非仅报错。

### 布局与对齐
- 内容**整体居中**，纵向留白充足，形成「独立页面」感
- 图示在上，标题、说明、操作依次向下
- 说明文字限制最大宽度（避免长行难读），居中对齐
- 多个操作按钮水平排列，主操作更醒目

### 移动端
- 图示缩小、留白收紧，避免操作按钮被挤到折叠区外
- 操作按钮可纵向堆叠、整宽，保证触摸目标 ≥ 44×44
- 说明文字不截断，必要时折叠为「展开更多」

## 交互

### 呈现与操作（核心操作）
- 由路由或流程状态进入，**立即展示结果**，无需用户触发
- 主操作：进入下一步（返回首页 / 查看详情 / 继续）
- 次操作：重试 / 返回上一步 / 联系支持
- 未登录或会话失效时，可提供「重新登录」

### 操作行为
- 点击操作项：执行跳转或重试，执行中给出加载反馈并防重复点击
- 重试：应重新发起原请求并切回「加载中」态，而非停留在结果页

### 键盘
| 键 / 操作 | 行为 |
|---|---|
| `Tab` | 依次聚焦操作按钮与链接 |
| `Enter` / `Space` | 触发聚焦的操作 |
| `Esc` | 若为对话框 / 抽屉内结果，可关闭返回 |

### 指针与手势
- 点击按钮触发对应操作
- 无拖拽 / 滑动需求

### 焦点管理
- 整页进入 / 路由切换后，焦点应移到结果标题或页面主体，使读屏能播报结果
- 结果页展示**不抢焦点**打断用户（区别于模态）
- 对话框内结果页关闭后，焦点回到触发元素

### 动画与过渡
- 图示可有轻量入场动画（淡入 / 轻微缩放），约 200–400ms
- 成功 / 失败切换时避免夸张动效
- 遵循「减少动态」偏好时降级为静态

### 反馈
- 重试 / 跳转等操作本身需有加载 / 成功 / 失败反馈
- 失败页的「重试」失败时应更新说明，而非无变化

### 边界交互
- **结果依赖异步数据**：如订单详情，需处理数据加载中 / 加载失败
- **多次重试仍失败**：应升级为「稍后再试 / 联系支持」并提供可读错误码
- **参数缺失**：如详情页缺 id，应退化为信息型结果而非报错崩溃

## 数据流

### 输入
- 类型：success / error / warning / info / 403 / 404 / 500
- 标题、副说明
- 操作项列表：`{ 文案, 类型（主/次）, 回调 或 跳转目标 }`
- 图示（插画 / 图标）
- 附加内容（订单号、错误码、指引）

### 内部状态
- 操作项的进行中状态（重试按钮的加载 / 禁用）
- 附加内容的展开 / 收起
- 图示入场过渡状态

### 输出
- 操作项点击事件（携带操作标识）
- 重试请求的发出
- 结果曝光事件（供埋点）

### 受控 / 非受控
- **完全受控**：类型、文案、操作均由外部提供，组件只负责呈现与转发事件
- 组件不自行决定结果类型，也不内建跳转目标

### 异步与竞态
- 进入结果页可能需要拉取详情数据，需处理加载 / 失败
- 重试请求需防重复、防竞态（后发覆盖先发时丢弃旧结果）
- 结果页长时间停留后返回再进入，应重新按当前状态渲染

### 校验与错误
- 组件不做业务校验；错误原因与错误码由外部提供
- 对用户可见的错误信息要**可读**（避免直接抛原始堆栈）
- 权限类结果应提供申请 / 登录入口，而非死路

### 回填与序列化
- 需展示的上下文（订单号、错误码）应从路由参数或状态中稳定获取
- 刷新页面后结果页应可重建（依据后端状态或路由参数），不能只靠内存

---

## 无障碍
- 整页结果应有可读的**主标题（一级标题）**，供读屏与跳转
- 页面标题与结果类型一致，便于无障碍导航
- 写内容在标题之后，操作按钮位于末尾，符合阅读顺序
- 操作按钮为真实控件，`focus-visible` 可见
- 图示若为装饰性插画，对读屏隐藏；若承载信息，则提供文字替代
- 类型不能仅靠颜色，须有文字与图标

## 常见误用
- 用结果页表达「暂无数据」→ 应使用空状态
- 成功页塞入过多无关信息，冲淡结论
- 失败页只报「出错了」不给原因与出路
- 把短暂的操作反馈也做成整页结果
- 无权限 / 404 做成死路，没有返回或申请入口

## 边界与代价
- 为每种错误单独造页：维护成本高，需统一容器 + 类型驱动
- 文案过长：需限制宽度并考虑折叠
- 结果依赖异步数据却无加载 / 失败态：会白屏
- 重试不做防抖 / 竞态：可能重复提交
- 移动端操作按钮过多：会挤压内容或超出首屏
- 刷新后无法重建结果页：用户回退再进会丢失上下文
