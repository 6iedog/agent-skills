# 空状态

当页面或列表**流程正常却没有任何内容**时展示的占位：用插画 + 文案 + 操作说明「这里为什么是空的、接下来能做什么」。

## 角色与边界

- **是什么**：居中展示的「图示 + 标题 + 说明 + 操作」，占据本该有内容的位置。
- **解决什么**：把「空白页」变成有信息、有出路的页面，区分**无数据**与**加载中 / 出错**。
- **不解决什么**：
  - 不解决「正在加载」 → 骨架屏 / 加载中
  - 不解决「加载失败 / 无权限 / 找不到」 → 结果页（错误态）
  - 不解决「有百分比的耗时过程」 → 进度条
  - 不解决「首次使用的新手引导」的分步教学 → 引导 / 帮助组件（可作入口）
- **什么时候不用**：正在加载 → 骨架屏；请求出错 → 错误态 + 重试；确实有内容（哪怕只有一条）→ 正常渲染。

---

## UI

### 结构解剖
- **图示**：插画 / 图标 / 简单图形，表达情境
- **标题**：一句说明「这里是什么状态」（如「还没有数据」「没有匹配结果」）
- **说明文字**：可选，补充原因或建议
- **操作区**：主操作（如「新建」「重新加载」「清除筛选」）+ 可选次操作
- **区域容器**：占位通常撑起一块合理高度，居中显示

### 尺寸与外观变体
- 场景：无数据（首次）/ 搜索无结果 / 筛选无结果 / 初始化引导 / 无权限 / 网络错误
- 图示：插画 / 图标 / 无
- 范围：整页 / 表格内 / 卡片内 / 列表内
- 操作数：无 / 单操作 / 主次操作

### 视觉状态（逐条）
| 场景 | 文案倾向 | 典型操作 |
|---|---|---|
| 无数据（首次） | 「还没有内容」 | 主操作：新建 / 导入 |
| 搜索无结果 | 「没有找到与 X 相关的结果」 | 建议：换个关键词 |
| 筛选无结果 | 「没有符合条件的内容」 | 清除 / 放宽筛选 |
| 初始化引导 | 「开始创建你的第一个 X」 | 引导创建 + 查看示例 |
| 无权限 | 「暂无访问权限」 | 申请 / 返回 / 登录 |
| 网络 / 加载出错 | 「加载失败」 | 重新加载 |

- **不同场景文案必须区分**：搜索无结果不能复用「暂无数据」的通用文案。

### 布局与对齐
- 内容**水平居中**，垂直方向根据容器高度居中或靠上留白
- 图示在上，标题、说明、操作自上而下
- 说明限制最大宽度，长文居中易读
- 表格 / 列表内空状态应撑出合理行高，不塌缩成一条线

### 移动端
- 图示缩小、留白收紧，操作按钮纵排整宽
- 触摸目标 ≥ 44×44
- 说明文字不截断，必要时折叠

## 交互

### 呈现与操作（核心操作）
- 由数据状态驱动展示，随内容为空而出现，有内容则消失
- 主操作：引导用户产生内容（新建 / 导入 / 返回 / 重试）
- 次操作：查看示例 / 帮助 / 清除筛选

### 操作行为
- 点击主操作：跳转创建流程 / 触发重试，执行中给出加载反馈
- 「清除筛选」类操作：清除后若仍为空，应更新文案为「无数据」而非继续显示「筛选无结果」
- 无操作的空状态：仅展示，不引导

### 键盘
| 键 / 操作 | 行为 |
|---|---|
| `Tab` | 依次聚焦操作按钮 / 链接 |
| `Enter` / `Space` | 触发聚焦的操作 |
| — | 图示不参与焦点 |

### 指针与手势
- 点击操作按钮
- 无拖拽需求

### 焦点管理
- 区域变为空状态时**不抢焦点**（区别于模态）
- 若空状态由搜索触发，焦点通常留在搜索框，便于修改关键词
- 操作按钮可聚焦，`focus-visible` 可见

### 动画与过渡
- 出现 / 消失可用轻淡入，约 150–300ms
- 轻微插图动画可选，遵循「减少动态」偏好时降级为静态
- 从「有内容」到「空」的切换避免剧烈布局跳动

### 反馈
- 触发重试 / 清除筛选等操作后须有结果反馈
- 重试失败应更新说明，而非无变化

### 边界交互
- **空状态由搜索 / 筛选引起**：文案需回显关键词或条件，并提供清除入口
- **权限不足**：给出申请 / 登录路径，避免死路
- **加载失败与真正的空**：必须分开，失败要能重试
- **图示加载失败**：需有降级（图标 / 纯文字）

## 数据流

### 输入
- 场景类型：无数据 / 搜索无结果 / 筛选无结果 / 引导 / 无权限 / 出错
- 标题、说明文字
- 图示
- 操作项列表：`{ 文案, 类型（主/次）, 回调 或 跳转 }`
- 上下文信息（搜索关键词、生效的筛选条件）

### 内部状态
- 操作项的进行中状态（重试 / 新建的加载）
- 图示 / 内容进入过渡状态

### 输出
- 操作项点击事件（携带操作标识）
- 清除筛选 / 重试等动作的发出

### 受控 / 非受控
- **完全受控**：由外部根据数据状态决定渲染哪个场景
- 组件不自行判定「是搜索无结果还是无数据」，该判断属于业务层
- 组件只呈现 + 转发事件

### 异步与竞态
- 重试请求需防重复、防竞态
- 搜索无结果的判定应等搜索请求结束再下结论，避免「搜索中」闪出空状态
- 快速切换筛选条件时，后发结果覆盖先发

### 校验与错误
- 组件不做业务校验
- **必须区分「空」与「错」**：请求失败不能渲染为空状态，否则用户误以为没有数据
- 无权限要走在权限判断之后，避免泄露资源是否存在

### 回填与序列化
- 搜索关键词、筛选条件应可从路由 / 状态回填，保证刷新后空状态文案一致
- 无值需要序列化

## 无障碍
- 空状态区域提供可读的标题（`heading`），使读屏能播报当前状态
- 图示若为装饰性，对读屏隐藏；若承载信息，提供文字替代
- 状态变化（内容变空）可用 `aria-live="polite"` 礼貌播报
- 操作按钮为真实控件，`focus-visible` 可见
- 文案要具体，避免只有一张无文字的插画
- 网络错误场景提供重试，保证键盘可达

## 常见误用
- 用空状态表达「加载失败」或「无权限」→ 应使用结果页 / 错误态
- 搜索无结果复用「暂无数据」通用文案，不提示关键词
- 空状态没有出路（不给任何操作），用户被困
- 加载中也显示空状态，导致「先空一下再出内容」的闪跳
- 权限不足直接显示空状态，掩盖真实原因

## 边界与代价
- 空状态与加载态 / 错误态混用：用户无法判断是没数据还是出错
- 插画过大：挤压首屏，移动端尤甚
- 无操作引导：页面变成死胡同
- 重试不防抖 / 不更新文案：用户反复点但无变化
- 搜索无结果不显示关键词：用户不知为何为空
- 图示依赖网络大图：加载不出时整块空白，需本地降级
