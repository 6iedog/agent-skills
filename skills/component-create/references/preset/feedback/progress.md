# 进度条

用一段**已填充的比例**表示任务的完成度，让用户知道进度和剩余。

## 角色与边界

- **是什么**：以轨道 + 填充的形式表达「已完成 / 总量」，可配百分比或状态。
- **解决什么**：能**估算进度**的耗时任务（上传、下载、批量处理），给用户确定感与等待预期。
- **不解决什么**：
  - 不解决「只知道在处理、不知进度」 → 加载中
  - 不解决「内容结构固定的占位」 → 骨架屏
  - 不解决「任务结果」的整页结论 → 结果页
- **什么时候不用**：进度不可知 → 用加载中；任务在约 1s 内完成 → 不显示（会一闪而过）；只是展示已完成比例的静态数值 → 普通文本 / 徽标。

---

## UI

### 结构解剖
- **轨道**：未完成部分的底槽
- **填充**：已完成部分，宽度 / 弧长随百分比变化
- **文字信息**：百分比数值、当前步数、剩余时间（可选）
- **状态图标**：成功 / 异常时替换或叠加在指示器上
- **分段：把轨道切成若干等分块**（用于步骤型进度，如「第 3 / 5 步」）

### 尺寸与外观变体
- 形态：线形（水平）/ 环形 / 仪表盘（半环 / 圆弧带刻度）
- 尺寸：细 / 常规 / 粗；环形分小 / 中 / 大
- 文字：不显示 / 显示百分比 / 显示百分比 + 附加说明
- 状态：进行中 / 成功 / 异常 / 不确定
- 分段：连续 / 分块（步进式）
- 线形可带条纹 / 流光以强化「进行中」感

### 视觉状态（逐条）
| 状态 | 表现 |
|---|---|
| default（进行中） | 填充按百分比，用主进度色 |
| success | 填充满格 + 成功色 + 成功图标 |
| exception / error | 填充停在出错处 + 错误色 + 错误图标 |
| active | 进行中可带流动 / 条纹动画表示正在推进 |
| indeterminate（不确定） | 无具体百分比，填充循环滑动 |
| disabled | 降透明、不作为可交互元素时无交互态 |
| 分段 · 已完成 | 已完成的块用完成色填充 |
| 分段 · 当前 | 当前块用进行色，可带动画 |
| 分段 · 未开始 | 未开始的块保持底槽色 |

### 布局与对齐
- 线形默认撑满容器宽度；需多列表格内使用时限制最大宽度
- 进度文字：线形中常右对齐（百分比在右侧）或居中显示在轨道内/上方
- 环形 / 仪表盘：数值居中于环内
- 与相邻文本基线对齐，避免高低错位

### 移动端
- 线形优先、尽量窄高比，避免过粗
- 环形尺寸适配小屏，数值字号相应缩小
- 触摸环境避免依赖 hover 查看细节

## 交互

### 触发与更新（核心操作）
- 本身是**被动展示**组件，不承载主操作
- 进度由外部数据驱动，随上传 / 轮询 / 流式事件更新填充
- 到达 100% 或状态切换时，由外部决定下一步（关闭、跳转、显示结果）

### 交互行为
- 纯展示型：不可点击
- 若支持点击跳转 / 定位（如点击进度跳到某段），需明确可点区域与键盘等价
- 可取消的任务：常**在进度条旁配一个取消按钮**，而非进度条本身可点

### 键盘
| 键 / 操作 | 行为 |
|---|---|
| `Tab` | 纯展示型不参与；带交互（可点 / 可拖）时须可达 |
| `Enter` / `Space` | 触发聚焦的交互行为 |
| `←` / `→` | 仅当进度可被用户调节时才支持（罕见） |

### 指针与手势
- 纯展示无指针交互
- 若可拖拽调节（如播放进度），需同时支持键盘微调

### 焦点管理
- 不作为焦点目标（除非自身可交互）
- 进度更新时**不抢焦点**，也不打断读屏当前朗读

### 动画与过渡
- 填充变化：平滑过渡（约 200–400ms），避免数值跳变造成突兀
- 不确定态：填充循环滑动，节奏恒定；遵循「减少动态」偏好时降级为静态或弱动画
- 条纹 / 流光：匀速，不加速跳动

### 反馈
- 进度本身即反馈：数值变化让用户感知推进
- 完成 / 失败需带回视觉状态（颜色 + 图标 + 文案），不能只停在某个百分比

### 边界交互
- **进度回退**：若允许（重试、重算），要平滑回退而非瞬间归零闪跳
- **长时间停在某值**：可附文字说明（如「正在处理最后一步」）避免用户误以为卡死
- **骤跳到 100%**：真实进度更新要平滑，避免假进度制造不信任

## 数据流

### 输入
- `percent`：0–100 的已完成比例
- `status`：进行中 / 成功 / 异常 / 不确定
- 是否显示百分比 / 文字说明
- 形态：线形 / 环形 / 仪表盘；尺寸
- 分段数量（步进式时）

### 内部状态
- **动画插值**：把新 percent 平滑过渡到目标值（显示值 ≠ 立即等于输入值）
- 不确定态循环动画的相位
- 进入 / 退出过渡状态

### 输出
- 到达完成 / 切换状态时的回调（可选）
- 无用户值产出（除可拖拽变体外）

### 受控 / 非受控
- **强受控**：percent 与 status 完全由外部持有，组件只渲染
- 组件内部只维护动画过渡，不回写数值
- 若有「自动演示」需求（如展示用），才允许内部自增，但须与真实进度区分模式

### 异步与竞态
- 更新源常为轮询 / 流式响应；**乱序到达的旧百分比要丢弃**（按时间戳或序号）
- 轮询下需处理「长时间无更新」：可切换为不确定态或给出提示
- 组件卸载后停止计时 / 动画，避免泄漏

### 校验与错误
- 边界值：percent < 0 视为 0，> 100 视为 100（或按状态钳制）
- 状态与数值一致性：success 通常意味着 100%；exception 保留出错时数值
- 不代替业务异常处理，只呈现状态

### 回填与序列化
- 不持久化进度值本身；页面刷新后由任务源重新提供
- 若任务可续传，进度需与后端记录对齐，避免从 0 重新开始

## 无障碍
- 使用 `progressbar` 角色，暴露 `aria-valuenow`、`aria-valuemin`、`aria-valuemax`
- 不确定态：省略 `aria-valuenow` 或标注为不确定
- 提供可读的文本标签（如「上传进度 60%」），不依赖视觉填充
- 状态切换（成功 / 失败）用 `aria-live` 礼貌播报
- 遵循「减少动态」偏好，弱化或去除循环动画
- 颜色之外另有文字 / 图标表达成功与异常

## 常见误用
- 用「假进度」把用户晃到 100% 再长时间等待 → 失去信任
- 进度不可知却硬做进度条 → 应使用不确定态或加载中
- 任务 < 1s 也显示进度条 → 一闪而过，反而闪烁
- 用颜色区分成功 / 异常却无文字 / 图标
- 在进度条自身上做「取消」，取消语义不清 → 应配独立按钮

## 边界与代价
- 进度回退 / 长时间停滞：需配套说明，否则被认为卡死
- 假进度或骤跳：损害信任，宁用不确定态
- 高频更新（每秒多次）：需节流，避免渲染抖动与动画打架
- 动画与真实到达不一致：视觉上要平滑，但不能长期落后于真实值
- 环形 / 仪表盘在小屏过密：刻度与文字会拥挤
- 分段数过多（> 约 10 段）在小屏难以分辨
