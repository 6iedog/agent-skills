# 多选下拉

收起时在触发器内收纳**已选的多个值**（标签平铺或计数折叠），展开后可**同时勾选多项**。

## 角色与边界

- **是什么**：一个可展开的选项容器，同一时刻可以有多个值被选中，选中结果是**一个数组**。
- **解决什么**：可选项多到无法平铺、又需要从中选多个、且希望收起后仍能看出选了哪些。
- **不解决什么**：
  - 只能选一项 → 单选下拉
  - 选项少、希望全部直接可见 → 复选框组
  - 需要「已选 / 未选」两栏对照挑选 → 穿梭框
  - 允许用户**自造**新值（输入不存在的项） → 标签输入
  - 层级 / 跨层多选 → 树选择
  - 必填 / 数量格式校验 → 属于表单层，本组件只呈现错误态
- **什么时候不用**：选项 ≤ 5 且不常变 → 复选框组（直接可见更快）；选项成百上千、又要反复核对已选 → 穿梭框。

## UI

### 结构解剖
- **触发器**：一行（或多行）。左为「已选收纳区」，右为下拉箭头；可含前缀图标
- **已选收纳区**：容纳已选项的容器，有三种形态——**标签平铺**（每项一个小标签）、**计数折叠**（只显示「+N」）、**纯计数**（只显示「已选 3 项」）
- **标签**：单个已选项的胶囊块，通常带独立删除按钮（×）
- **折叠计数**：超出可视上限时，用「+N」表示还有 N 项未展示
- **占位符**：未选任何项时的浅色提示文字
- **面板**：浮层，含选项列表
- **选项行**：文本 + 左侧复选框标记（多选必须让「可多选」一眼可见）+ 可选副文本 / 说明
- **全选行**：面板顶部的「全选 / 反选 / 清空」批量操作行（可选）
- **搜索框**：可搜索时固定在面板顶部
- **分组标题**：分组模式下每个分组的标题行
- **状态占位**：面板内的加载 / 空 / 错误位

### 尺寸与外观变体
- 尺寸：小 / 中 / 大 → 同时影响触发器高度、标签尺寸、选项行高
- 收纳形态：标签平铺 / 计数折叠 / 纯计数（值越多越应偏向折叠）
- 状态类：默认 / 错误（红边）/ 警告 / 禁用
- 外观：带边框 / 无边框（工具栏内）/ 填充式
- 触发器可挂：前缀图标、后缀图标、已选计数、清空按钮
- 标签可配置：是否显示删除按钮、是否截断超长标签文本

### 视觉状态（逐条）
| 状态 | 触发器 / 已选收纳区 | 面板 / 选项 |
|---|---|---|
| default | 边框默认、占位符浅色 | — |
| hover（触发器） | 边框加深 / 背景微亮 | — |
| hover（标签） | 标签背景微亮 | — |
| hover（标签删除按钮） | 删除按钮显形 / 变色 | — |
| focus-visible | 明显焦点环 | — |
| open | 边框高亮 + 箭头翻转 | 面板出现 |
| selected（选项） | 对应标签出现在触发器内 | 该行显示勾选标记 + 高亮 |
| active（按下选项） | — | 选项行背景加深 |
| disabled（整体） | 整体降透明、禁用指针 | 打不开 |
| disabled（单个选项） | — | 该项灰显、不可勾选 |
| readonly | 外观同 default，但不可展开、标签无删除按钮 | — |
| loading | 触发器可显示 spinner | 面板内骨架 / spinner |
| error | 边框红 + 下方错误文案 | — |
| empty | — | 面板内空状态文案（+ 可选引导） |
| overflow（已选超上限） | 折叠为「+N」或换算成计数 | — |

- **disabled 与 readonly 必须分开**：disabled 不可聚焦、不进表单值；readonly 可聚焦、可复制、值照常提交。

### 布局与对齐
- 面板宽度默认与触发器对齐；内容超长时可加宽
- 面板最大高度受限，选项多时**列表内滚动**
- 靠近视口底部时**向上翻转**，避免出屏
- **收纳区换行策略要明确**：超出宽度是「换行撑高触发器」还是「折叠为 +N」——两者体验差异大，必须二选一并保持一致
- 单个标签超长文字截断，悬停显示完整值

### 移动端
- 桌面式多选下拉在小屏体验差：改为**底部弹层选择器**（半屏 / 全屏），触发区显示「已选 N 项」
- 触摸目标 ≥ 44×44
- 标签上的删除按钮在小屏要放大命中区，避免误触
- 选项列表占满宽度，不做窄浮层；已选计数常驻底部确认条

## 交互

### 触发与开合
- 打开：点击触发器 / 聚焦时 Enter、Space / 方向键下
- 关闭：再次点击、Esc、点击外部、Tab 移出；**点击/勾选选项本身不关闭面板**
- 面板自动避让视口边缘

### 选中行为（与单选下拉的核心差异）
- **勾选一项后不收起**：多选的典型诉求是连续勾多项，收起会打断操作
- **再点已选项 = 取消勾选**（单选下拉是收回但不取消，这里必须能取消）
- 触发器内的标签点 × 直接移除该项，不打开面板
- 打开时高亮应落在**第一项**（多选无「唯一当前项」，一般不做「跳到已选项」）
- **全选**：一键勾选当前可见（或全部）选项；**反选**：已选↔未选整体翻转
- **清空**：一键移除全部已选
- **选择上限**：达到上限后其余未选项变为不可勾选（灰显 + 提示），而不是勾了再弹错
- **超限行为必须明确**：超出时是拒绝勾选、还是自动挤掉最早/最后一项——推荐**拒绝并提示**，不可静默替换

### 键盘
| 键 | 行为 |
|---|---|
| `Tab` | 聚焦 / 离开触发器 |
| `Enter` / `Space` | 关闭态：打开面板；打开态：勾选 / 取消勾选当前高亮项（**不收起**） |
| `Esc` | 关闭面板，**不改变已选值** |
| `↑` / `↓` | 在高亮项间移动 |
| `Home` / `End` | 跳到首 / 末项 |
| 字符键 | typeahead 跳到以该字符开头的项；搜索模式下由搜索框接管 |
| `Backspace` | （标签平铺且触发器可聚焦时）删除最后一个标签，语义应统一 |
| 搜索模式 | `↑`/`↓` 在结果间移动，`Enter` 勾选 |

### 指针与手势
- 移动端：点触发器 → 底部弹层；勾选后**停留在弹层**，由确认条或返回关闭
- 悬停选项行高亮；悬停触发器内标签显示删除按钮
- 长按 / 右键标签可扩展为快捷移除（可选，非必须）

### 焦点管理
- 关闭后焦点**回到触发器**（不得丢到 body）
- 可搜索模式：面板打开即聚焦搜索框
- 从触发器内标签删除项后，焦点应留在触发器而非跳到页首

### 动画与过渡
- 面板出现 / 消失：轻微位移 + 淡入淡出，约 100–200ms
- 箭头翻转
- 标签新增 / 移除：轻微高度过渡，避免触发器抖动；**收起类过渡慎用**，长列表动画易卡
- 不引起布局抖动

### 反馈
- 异步选项：打开时显示加载；失败显示错误 + 重试入口
- 达到选择上限时，未选项灰显并给出可读提示
- 单次勾选本身不额外提示（标签出现即反馈）

### 边界交互
- 超长列表：内部滚动，并在打开时滚动定位到第一项
- **已选值从数据源消失**：须明确处理（保留为「已失效」标签 或 自动移除），不可静默丢失
- 选项极多 + 全选：需限制「全选」作用范围（仅当前可见结果）或给出确认，避免一次勾上千项
- 快速连续勾选 / 搜索请求：防抖、防竞态

## 数据流

### 输入
- **选项数据**：`{ 值, 展示文本, 是否禁用?, 分组? }` 的列表
- 数据来源：静态数组 / 远程接口
- 分组结构：组名 + 组内选项
- 其他配置：占位符、默认已选数组、尺寸、状态（错误 / 禁用）、是否可搜索、是否可清除、**标签最大显示数**、**选择数量上限**
- **是否可搜索与多选的组合**：可搜索时注意「已选但被搜索过滤掉」的项是否仍保留在收纳区（一般应保留，否则用户以为被清空了）

### 内部状态
- open（开合）
- 已选值的本地镜像（非受控时）
- 高亮索引（键盘导航）
- 搜索词（可搜索模式）
- 加载 / 错误（异步）
- 列表滚动位置
- 标签收纳的溢出计算（当前能平铺几个、折叠几个）

### 输出
- **值变化事件**：新值数组（可选带旧值 + 本次是新增还是移除）
- 打开 / 关闭事件（供外部联动）
- 搜索事件（异步搜索时把搜索词抛给外部）
- 触顶事件 / 超限提示事件（达到上限时，可选）
- **值形态必须明确**：是 id 数组还是选项对象数组——这决定回填、去重与比较

### 受控 / 非受控
- 受控：值数组由外部持有，组件只在事件里抛出**新数组**（不要原地改动传入数组），自身不存值
- 非受控：内部持有，给默认已选数组
- **二选一必须明确**；混用会出现「点了不变」或「外部改了不刷新」

### 异步与竞态
- 远程加载要处理加载 / 空 / 错误三态
- **竞态**：后发请求先返回时丢弃过期结果（按请求标识或时间戳）
- 搜索防抖；同一关键词可缓存，不重复请求
- **已选值的回填与选项加载不同步**：先显示已知标签，选项到位后再补全展示文本

### 校验与错误
- 组件只负责「当前值数组」；必填（至少一项）/ 数量上下限校验在表单层
- 错误由外部传入（错误标记 + 文案），组件负责呈现
- 触顶属于交互约束，应在勾选时即时反馈，不留给提交时再报错

### 回填与序列化
- 初值数组 → 显示：逐项按值查选项取展示文本；查不到的项兜底（显示原始值 或 标记失效）
- **顺序语义**：数组顺序是否有意义必须定义——若「顺序无关」则比较时需集合化（排序 / 去重后比），否则会出现「选的一样却判定为变化了」
- **值比较**：对象值须按 id 比较，不能按引用；去重也按 id

## 无障碍
- 触发器：`combobox` / `button` + `aria-expanded`、`aria-haspopup`
- 面板：`listbox` + `aria-multiselectable`；选项 `option` + `aria-selected`
- 已选数量与内容对屏幕阅读器可读（如「已选 3 项：A、B、C」）
- 标签删除按钮需有可读名称（如「移除 A」），不能只有图形
- 全键盘可达；`focus-visible` 可见（禁止无替代的 `outline: none`）
- 禁用项标 `aria-disabled`；达到上限时说明原因

## 常见误用
- 只有 3–5 项仍用多选下拉 → 复选框组
- 不设收纳策略、选项一多标签撑爆触发器，遮挡后续内容
- 不设选择上限，或超限时静默替换已选项
- 勾选后自动收起 → 打断连续多选
- 把「全选」放在成百上千条数据上 → 一次勾取导致卡顿
- 拿它做「允许用户自造新值」 → 标签输入
- 把组件当成「能看清已选 / 未选对照」的工具 → 穿梭框

## 边界与代价
- 已选 > 约 5 项：**必须**启用计数折叠（+N）或改纯计数，否则标签溢出
- 选项 > 约 15 条：**必须**可搜索
- 移动端：必须换底部弹层选择器
- 值形态 / 顺序语义不明确 → 回填、去重与「是否变化」判断错乱
- 全选不限定范围 → 大数据下的一次性性能与误操作风险
