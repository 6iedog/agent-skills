# 复选框组

若干项**全部平铺可见**，各自独立，可**同时勾选多项**，结果是一个数组。

## 角色与边界

- **是什么**：一组相互独立的复选框，各项可单独勾选 / 取消，整体取值是**一组值**。
- **解决什么**：选项不多、希望全部直接可见、可任意多选、并需要看清「哪些勾了」的场景。
- **不解决什么**：
  - 选项多、需要收起 / 搜索 → 多选下拉
  - 选项多且需「已选 / 未选」两栏对照挑选 → 穿梭框
  - 允许用户**自造**新值 → 标签输入
  - 本质互斥只能选一个 → 单选按钮组 / 分段控件
  - 需要「是 / 否」单一开关语义 → 开关 / 单个复选框
  - 必填 / 数量约束校验 → 属于表单层，本组件只呈现错误态
- **什么时候不用**：选项 > 约 8 → 多选下拉（否则占满一屏）；选项成百上千 → 穿梭框或带搜索的列表。
- **与「单个复选框」的区别**：单个复选框是**一个布尔值**（是 / 否），组件是**一个数组**（选中的多个值），并额外承载全选、半选、组约束等组级职责。

## UI

### 结构解剖
- **组容器**：承担分组、布局与组级文案，并承载数组值
- **组标签**：整组标题（如「订阅内容」），可选
- **单项**：勾选方块 + 文本；方块与文本为一个整体命中区
- **勾选标记**：未选为空格方块，已选为方块 + 对勾
- **文本标签**：可换行；可含副文本 / 说明行
- **全选项**：组顶部（或底部）一个「全选」控制，联动整组
- **半选标记**：全选项在「部分选中」时显示的横杠态（indeterminate）
- **说明行**：每项下方的一行解释文字
- **辅助位**：组下方的帮助文案 / 错误文案 / 已选计数

### 尺寸与外观变体
- 尺寸：小 / 中 / 大 → 影响方块边长、行高、字号、间距
- 排列：**纵向**（一列堆叠，默认，最稳）/ **横向**（一行平铺，选项短时）
- 内容：纯文本 / 带说明 / 带图标
- 是否含全选 / 反选
- 状态类：默认 / 错误（整组标红）/ 禁用（整体 / 单项）

### 视觉状态（逐条）
| 状态 | 组容器 | 单项 |
|---|---|---|
| default | — | 空格方块 + 常规文本 |
| hover | — | 方块描边加深 / 背景微亮 |
| focus-visible | — | 明显焦点环（落在被聚焦项上） |
| checked | — | 方块填充 + 对勾 |
| indeterminate（半选） | — | 仅全选项显示：方块横杠（**不是对勾**） |
| active（按下项） | — | 方块轻微缩放 / 背景加深 |
| disabled（整体） | 整组降透明、禁用指针 | 全部不可交互 |
| disabled（单项） | — | 该项灰显、不可勾选 |
| readonly | 外观同 default，但不可改选 | 保持可读 |
| error | 组标签 / 方块变红 + 组下错误文案 | 方块描边变红 |
| loading | 可显示骨架或禁用整组 | 占位项 |

- **disabled 与 readonly 必须分开**：disabled 不可聚焦、不进表单值；readonly 可聚焦、可复制、值照常提交。

### 布局与对齐
- **纵向**：最稳，项与项等距堆叠，长文本不挤压；默认推荐
- **横向**：仅当各项文本都很短时用；换行时第二行对齐首行起点
- 方块与文本垂直居中对齐；带说明行时方块与首行文本对齐（非整块居中）
- 全选项与普通项视觉上应有所区分（间距或分隔），避免被当成一个可选值
- 组级错误文案 / 计数放在整组下方，与组对齐起点

### 移动端
- 纵向排列优先，触摸目标 ≥ 44×44
- 横向排布在小屏应换行为纵向或两列
- 方块与文本命中区整体可点，间距加大防误触

## 交互

### 核心操作
- 点击任意项 → **立即切换该项的勾选状态**，互不影响
- 无「开合」「提交」步骤；勾选即生效（作为表单字段时通常在提交时统一使用）
- **全选**：一键勾选全部项；**再次点击已全选的「全选」→ 取消全部**
- **半选态**：当且仅当「部分项被选中」时，全选项显示横杠态；点一下半选的全选 → 勾选全部
- **全选 / 反选必须与值数组联动**：全选后的数组应等于全部可选值（不含禁用项）

### 选中 / 输入行为
- 点击项 ≈ 点击方块 ≈ 点击文本，命中区一致
- 各项**独立**：勾选一项不影响其他项
- **禁用项的处理**：全选通常只作用于「可选中的项」，禁用项不被选中，也不计入「全选是否达成」的判定
- 可配置「最少选 N 项 / 最多选 N 项」：达到上限后其余项灰显或拒绝勾选并提示
- 组件本身不提供「清空」之外的批量操作；清空 = 值数组置空

### 键盘
| 键 | 行为 |
|---|---|
| `Tab` | **逐项**停留（与单选组不同：复选框组每个项都是独立 Tab 停靠点） |
| `Space` | 切换当前聚焦项的勾选状态 |
| `Enter` | （可选）同 Space，视框架约定 |
| `Home` / `End` | （可选）跳到首 / 末项 |

- 关键差异：复选框组**不是**单一 Tab 停靠点，每项都能被 Tab 到；这是与单选组 / 分段控件的核心无障碍区别。

### 指针与手势
- 移动端：点按项即切换；不做滑动多选（可选增强，非默认）
- 悬停项高亮，提示可点

### 焦点管理
- 焦点落在**被操作的项**上（复选框组无「唯一选中项」概念）
- 切换某项后焦点停留在该项，便于连续 Tab 到下一项
- 整组禁用不可聚焦；单项禁用跳过 Tab
- 全选项是可聚焦的独立控件

### 动画与过渡
- 勾选标记（对勾）出现：方块填充 + 对勾缩放淡入，约 100–150ms
- 半选横杠切换平滑，不与对勾混淆
- 说明行、错误文案出现时预留或平滑撑开，不引起布局抖动

### 反馈
- 勾选即反馈（方块填充 + 对勾）
- 触顶 / 触底（数量约束）时即时提示，不留给提交
- 组级错误由外部传入，显示在组下方

### 边界交互
- 组内仅一项时：等价于「单个复选框是否需要勾选」，评估是否为布尔语义
- 选项动态增删：已选值若从数据中消失，须明确处理（标记失效 / 自动移除）
- 全选与过滤：若列表被搜索 / 过滤，全选作用于「全部」还是「当前可见」必须明确，否则会误勾隐藏项
- 大量项 + 全选：一次勾取应能接受，项数极大时应改组件

## 数据流

### 输入
- **选项数据**：`{ 值, 展示文本, 是否禁用?, 说明? }` 的列表
- 数据来源：静态数组 / 远程接口
- 其他配置：默认选中数组、布局方向、尺寸、是否含全选、最少 / 最多选择数、状态（错误 / 禁用）
- **是否为「全选达成」提供判定**：默认选中数组是否已包含全部可选值

### 内部状态
- 受控模式下几乎无内部状态（值由外部持有）
- 非受控：内部当前值数组
- 全选项的**半选态**（由值数组与全部可选值比较得出，或内部缓存）
- 加载 / 错误（异步选项时）

### 输出
- **值变化事件**：新值数组（可选带旧值 + 变化项）
- 全选 / 反选 / 清空事件（可选，便于区分是用户逐个点还是批量操作）
- **值形态必须明确**：是 id 数组还是选项对象数组

### 受控 / 非受控
- 受控：值数组由外部持有，组件只在事件里抛出**新数组**（不要原地改动传入数组），自身不存值
- 非受控：内部持有，给默认选中数组
- **二选一必须明确**；混用会出现「点了不变」或「外部改了不刷新」

### 异步与竞态
- 选项远程加载要处理加载 / 空 / 错误三态
- **竞态**：后发请求先返回时丢弃过期结果（按请求标识或时间戳）
- 已选值的回填与选项加载不同步时，先按已知 id 保留选中，选项到位后补全展示文本

### 校验与错误
- 组件只负责「当前值数组」；必填（至少一项）与数量上下限校验在表单层
- 错误由外部传入（错误标记 + 文案），组件负责呈现；错误态作用于**整组**
- 「至少选一项」应通过组下提示表达，而不是仅禁用提交按钮

### 回填与序列化
- 初值数组 → 显示：逐项按值查选项置为勾选；查不到的项兜底（显示原始值 或 标记失效）
- **顺序语义**：数组顺序是否有意义必须定义——「顺序无关」时比较需集合化（排序 / 去重后比），否则会出现「勾的一样却判定为变化了」
- **半选态判定**：由「已选 ∩ 可选」的数量与全部可选数量比较得出，禁用项须排除在分母外
- **值比较**：对象值须按 id 比较，不能按引用；去重也按 id

## 无障碍
- 组容器：`group` + `aria-labelledby`（关联组标签）
- 单项：`checkbox` + `aria-checked`（半选态用 `mixed`）
- 全选项：`checkbox`，半选时 `aria-checked="mixed"`，并保证读屏能理解「部分选中」
- 每项独立可聚焦（Tab 逐项），Space 切换
- 禁用项标 `aria-disabled`
- 全键盘可达；`focus-visible` 可见（禁止无替代的 `outline: none`）
- 组级错误 / 计数文案与组建立关联，供屏幕阅读器读出

## 常见误用
- 选项 > 约 8 项仍平铺 → 占满一屏，应改多选下拉
- 全选没有半选态 → 部分选中时状态表达矛盾（全选看起来「没选」）
- 把全选也当成一个可选值参与数组 → 值语义污染
- 「至少选一项」只禁用提交按钮、不给提示 → 用户不知为何提交不了
- 与单选按钮组混用语义 → 复选框组是多选，不是互斥
- 列表被过滤时全选误勾隐藏项 → 作用范围未定义清楚

## 边界与代价
- 选项 > 约 8 项：改用多选下拉
- 有「全选 / 至少一项 / 最多 N 项」约束时，必须显式提示并即时反馈，不能只靠禁用提交按钮
- 数组顺序语义不明确 → 「是否变化」判断错乱
- 半选态判定不排除禁用项 → 全选逻辑错误
- 组内只有一项却当组用 → 语义退化为单复选框，应重新评估
