# 平台路由参考

本文提供平台判断细节、边界情况与兜底策略。

平台判定影响的是「读哪份平台差异规范」与「点击目标阈值」，详见文末。

## 识别信号详解

### 信号 1：用户显式声明（最高优先级）

识别这些表述：

| 表述 | 判定 |
|---|---|
| 「这是 PC 端」「后台管理」「桌面端」 | web |
| 「移动端」「H5」「小程序」「App」 | mobile |
| 「响应式」「一套代码两端跑」 | 先问，不要猜 |

「响应式 / 一套代码两端跑」是最容易出错的场景。此时必须询问，因为 PC 与移动端的交互差异不是响应式能自动解决的（hover 在触摸设备上没有意义、拖拽在移动端会与页面滚动冲突）。

### 信号 2：依赖清单

读取项目 `package.json` 的 `dependencies` 与 `devDependencies`：

| 检测到 | 判定 |
|---|---|
| `antd`、`@ant-design/*`、`element-plus`、`shadcn` 相关、`@radix-ui/*`、`mui`、`chakra-ui` | web |
| `vant`、`antd-mobile`、`@tarojs/*`、`uni-app`、`@ionic/*` | mobile |
| 同时存在两套 | 询问用户；或多端项目按主要目标端判定 |
| 都没有 | 走信号 3 |

`@radix-ui/*` 和 `shadcn` 判为 web 时要注意：这两类是无样式组件库，视觉规范需要完全由项目令牌提供 —— 若项目用它们，令牌体系要覆盖得比用成品库更全。

### 信号 3：目录与文件特征

| 特征 | 判定 |
|---|---|
| `src/pages/`、`app.json`、`project.config.json` | mobile（小程序） |
| `.wxml`、`.wxs`、`.nvue`、`.uvue` | mobile |
| `miniprogram/`、`unpackage/` | mobile |
| `src/components/`、`src/layouts/`、`src/pages/`（单页应用） | web |
| `.tsx`、`.jsx`、`.vue` + SPA 结构配置 | web |
| `app/`、`pages.json`、`manifest.json` | mobile（uni-app 或 Taro） |

`src/pages` 在两种架构下都存在（小程序与某些 SPA 约定），因此**不能单独作为判据**，需结合 `app.json` / `pages.json` 等标志文件。

### 信号 4：询问用户

用 `AskUserQuestion` 单独发一轮，只问平台，不要与其他问题混在一起。混在一起会导致用户对平台问题的回答受其他问题干扰。

## 边界情况处理

### 情况 A：需求跨越两端

例：「做一个筛选组件，PC 和移动端都要」。

处理：分别委派两次，生成两个平台的实现，**但共用同一份 `.ui-kit/` 产出物**。共用是关键——`tokens.json` 与 `conventions.md` 是跨平台的，只有 `catalog/` 里的组件规格需要标注适用平台。

做法：先处理优先级高的一端（通常是 web），再处理另一端时复用已沉淀的令牌与约定，只在 `platform-web.md` / `platform-mobile.md` 的差异处分支。

### 情况 B：多端项目（同一仓库既含 PC 又含 H5）

用目录归属判断，而非整个仓库判断。对每个具体组件需求，先看它要落在哪个目录，再定平台。路由的粒度是**单个组件**，不是整个项目。

### 情况 C：无法判定且用户未回答

若用户未回答就继续了，按 `web` 处理，但在最终回复中**明确标注**：

> 未检测到明确平台信号，按 PC 端处理。若实际是移动端，hover 态、触控热区、滚动冲突等规范需重新校验。

不要静默假设。静默假设是这类流程最隐蔽的失真来源。

## 判定后做什么

平台判定只影响两件事：

```
1. 读哪份平台差异规范
   → PC       → 治理包的 references/platform-web.md
   → 移动端   → 平台差异规范尚未收录，需向用户确认关键约束
                （触控热区、安全区、手势冲突）

2. 触控目标尺寸阈值不同
   → PC       → check_tokens.py --platform web  （24px 下限）
   → 移动端   → check_tokens.py --platform mobile（44px 下限）
```

**按需读取很重要**：如果需求只是「用已有组件改个文案」，走复用路径就不必加载平台规范、提问脚本、契约。这能让简单需求保持轻量，不必每次都把整套规范灌进上下文。

**不要用移动端阈值卡 PC 组件** —— 鼠标精度高，44px 在密集工具栏里会导致布局撑开。
