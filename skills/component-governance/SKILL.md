# 组件治理

## 一句话

维护目标项目的**组件提示词集**——把「这个项目的组件该怎么用、怎么找、怎么建」写成模型能读的自然语言说明，落在该项目的 `docs/components/`，随仓库提交。

产出的是**提示词**（约束性说明），不是数据文件、不是缓存、不是代码模板。

## 何时用 / 不用

| 用 | 不用 |
|---|---|
| 初始化组件规范 | 新建某个具体组件 |
| 制定 / 修订组件提示词 | 为某个场景挑组件形态 |
| 审查存量组件是否合规 | 写页面 / 加功能（直接消费现有提示词即可） |
| 项目没有统一样式，需要建立 | |
| 维护样式 wiki | |

右列属于 `component-create`。

## 产物形态

```
docs/components/
├── README.md        清单：有哪些提示词、各管什么（固定名，模型靠它取对）
├── <组件使用提示词>  必备：在这个项目里怎么写才算对
├── <组件查找提示词>  必备：已经有什么、去哪找
├── <组件创建提示词>  必备：新建时按什么规矩，含样式 wiki
└── …               按项目需要增加，用到再加
```

文件名自定（能看懂即可），`README.md` 固定。三份必备提示词各写什么 → `references/prompt-set.md`。

## 四条主线

### 1 初始化（首次）

```
1 探明项目：组件目录、样式源、技术栈证据、已有约定
2 有团队规范 / 踩坑记录 → 优先采用（这是效果关键，机器补不上）
   没有 → 用 references/interaction-baseline.md 的通用基线起草
3 产出三份必备提示词（references/prompt-set.md）
   样式部分按 references/style-wiki.md 探明并写成 wiki
4 写 README.md 清单（每份一句话说明管什么）
```

### 2 修订

新结论**回写到对应的那份提示词**，不另存文档。见「回写」。

### 3 审查存量

分两步，不要混：先**找出**违规（搜索即可），再**判断**是不是问题（模型做）。
可稳定检出的项与判定口径 → `references/review.md`。

### 4 统一风格（项目无样式体系时）

**从现状归纳，不从零发明**：统计重复出现的值 → 提出最小令牌集（附出现次数 / 出处）→ 用户确认 → 写入项目 → 更新 wiki。
完整流程 → `references/style-wiki.md`。

## 回写（贯穿所有主线）

每次判断的结论都要回写，否则下次重新问一遍：

| 结论类型 | 回写到 |
|---|---|
| 场景 → 形态 的消歧结论 | 组件创建提示词 |
| 用法类新约定 | 组件使用提示词 |
| 建法类新约定（命名、目录、样式） | 组件创建提示词 |
| 审查口径 | 审查类提示词（若有） |
| 样式源位置 / 机制 / 新增值方式 | 组件创建提示词的样式 wiki |

- **没有对应提示词**：会反复用到的，按 `references/prompt-set.md` 的判断标准新建一份；一次性的写进最相关那份。
- **写通用形态，不写组件名**：组件名随换库 / 升级失效，「可搜索的单选选择」不会。
- **晋升**：同类结论出现 ≥2 次 → 固化为约定，下次直接采用不再走流程。

## 硬规则

- **不写解析器、不做中间层**：模型能读任何格式的样式文件，它需要的是知道**去哪读**。样式值不该有第二份定义。
- **不预建空文件**：用到再加，不为「完整」凑数。
- **检查不做成硬门禁**：检测不到样式体系时不报错，改列全部硬编码值及频次——那正好是归纳令牌的输入。
- 只描述**约束**，不教消费方怎么写代码。

## 跨 skill 引用

审查存量需要**预设组件提示词**（随 `component-create` 提供）。Skill 之间不能 import，只能显式 `Read`：

```
1 项目级：    .trae/skills/component-create/references/preset/
2 用户级：    ~/.trae-cn/skills/component-create/references/preset/
3 本仓库开发： skills/component-create/references/preset/
```

依次探测，找到即用；**都找不到 → 降级**：只用 `references/review.md` 的通用清单判定，不依赖预设提示词。

## references

| 文件 | 内容 |

| `references/prompt-set.md` | 三份必备提示词各写什么 + README 清单格式 + 何时新增一份 |

| `references/interaction-baseline.md` | 通用交互惯例基线（团队规范缺失时的起草素材） |
