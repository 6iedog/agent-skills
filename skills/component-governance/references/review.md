# 存量审查

## 两步法

```
第一步 找出违规       →  搜索 / 文本模式匹配，输出「位置 + 证据」
第二步 判断是不是问题  →  模型读上下文判定，不交给工具
```

两部分都要做。只跑第一步会产出大量误报（很多硬编码是有依据的）。

## 可稳定检出的项（文本模式，可靠）

| 检出 | 依据 |
|---|---|
| 硬编码色值 `#f0f5ff` / `rgb()` | 正则匹配 hex / rgb 字面量 |
| 魔法圆角 / 间距 | 在项目样式源里找不到对应定义 |
| `outline: none` 无替代焦点 | 正则 + 确认无 `:focus-visible` |
| 可点击的 div（键盘不可达） | 正则匹配 `<div ... onClick` |
| 图标按钮缺无障碍名称 | 正则匹配 `<button>` 内直接含图标 |
| 状态缺失 | 搜索状态标识词（disabled / loading / error / empty） |

**第二步判定口径**：把「找到的值」拿去和**样式源**对。对得上 → 有出处，不是问题；对不上 → 疑似魔法值，报告。

## 待验证范围（未实测前不要声称支持）

- 真实项目的样式体系读取（按 `style-wiki.md`）
- 多框架（React 之外的场景）
- 大项目下的性能与误报率

> 陷阱：在自己造的小样本上通过 ≠ 可用。验证必须在真实 / 仿真的工程上做。
