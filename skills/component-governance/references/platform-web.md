# PC 平台交互规范

> 仅收录与通用规范（`interaction-ux.md`）的**差异部分**。通用条目不重复。

## 1. 指针交互（PC 的核心差异）

### 1.1 hover 态是必需的，不是可选的

鼠标是 PC 的主要输入设备，**所有可交互元素必须有 hover 态**。这与移动端根本不同。

```css
/* 正确 */
.btn { background: var(--color-bg-container); }
.btn:hover { background: var(--color-bg-hover); }
.btn:active { background: var(--color-bg-active); }

/* 错误：只有 focus 没有 hover —— 鼠标用户永远看不到反馈 */
```

hover 与 focus 必须是**两套独立样式**，不能混用。鼠标点击也会产生 focus，若用 `:focus` 会导致点击后按钮一直带焦点环。

### 1.2 光标形状

| 元素 | cursor |
|---|---|
| 可点击按钮/链接/卡片 | `pointer` |
| 禁用元素 | `not-allowed` |
| 可拖拽 | `grab` / 拖拽中 `grabbing` |
| 文本可选 | `text` |
| 禁止选择（如工具栏） | `default` |
| 缩放/移动类 | `move` / `nwse-resize` 等 |

禁用态用 `not-allowed` 而非保持 `pointer`——这是 PC 用户判断"能不能点"的重要线索。

### 1.3 右键菜单

右键菜单是 PC 独有能力，触屏没有。

```
可行：把右键作为「次要操作的加速入口」，且菜单内的操作在别处也能到达
禁止：把关键操作只放在右键菜单里
```

**判定标准**：一个操作如果只能通过右键访问，就是不可访问的。触屏用户、以及用右键习惯关闭菜单的 PC 用户都拿不到它。

被用户关闭右键菜单的浏览器上，触发方式应退化为长按或显式按钮。

## 2. 焦点与键盘

### 2.1 用 :focus-visible，不要用 :focus

```css
/* 正确：只有键盘导航才显示焦点环 */
.btn:focus-visible { outline: 2px solid var(--color-border-focus); outline-offset: 2px; }

/* 错误 */
.btn:focus { outline: 2px solid; }              /* 鼠标点击也会显示，很丑 */
.btn:focus { outline: none; }                    /* 键盘用户彻底失去焦点提示 */
```

`outline: none` 必须配 `:focus-visible` 替代样式，不能单独使用。`check_tokens.py` 会检测这一项。

### 2.2 焦点环样式

| 属性 | 要求 |
|---|---|
| 宽度 | 2px |
| 颜色 | `color.border-focus` |
| 偏移 | `outline-offset: 2px`（避免压住边框） |
| 圆角 | 跟随元素圆角 |
| 禁止 | 用 `box-shadow` 替代 outline（会破坏其他元素的层叠关系） |

### 2.3 快捷键

| 场景 | 快捷键 | 说明 |
|---|---|---|
| 弹窗关闭 | `Esc` | 有例外：必须完成的流程不可关 |
| 列表项删除 | `Delete` / `Backspace` | 需选中行 |
| 提交表单 | `Ctrl`/`⌘` + `Enter` | 输入框内也要能触发 |
| 保存 | `Ctrl`/`⌘` + `S` | 需拦截浏览器默认行为 |
| 搜索聚焦 | `Ctrl`/`⌘` + `K` | 全局搜索常见模式 |
| 复制/粘贴 | `Ctrl`/`⌘` + `C/V` | 不拦截浏览器默认 |
| 切换侧边栏 | `Ctrl`/`⌘` + `B` | 布局类应用常见 |

**规范要求**：

- 显示快捷键位置：Tooltip 末尾用 `kbd` 标签展示，如「复制 `⌘C`」
- 区分 Mac 与 Windows：`⌘` vs `Ctrl`，用 `navigator.platform` 或 `mod` 抽象
- 单键快捷键（`Delete`）必须避开了输入框内的正常输入
- 快捷键注册要集中管理，避免多处绑定冲突
- 不得用快捷键覆盖浏览器默认行为（`Ctrl+R`、`Ctrl+W` 等）

### 2.4 焦点管理

- 弹窗打开时焦点进入弹窗内第一个可交互元素（不是关闭按钮——那会诱导误关）
- 弹窗关闭后焦点**回到触发元素**
- 焦点陷阱（focus trap）：Tab 循环不得跳出弹窗
- 删除列表项后，焦点移到相邻项，不落回 body（否则键盘用户彻底失去位置）

## 3. 点击目标尺寸

PC 用鼠标精度高，**不需要 44px**。

| 元素 | 最小尺寸 |
|---|---|
| 表格内图标按钮 | 24×24 |
| 紧凑工具栏按钮 | 24×24 |
| 普通按钮 | 24×24 |
| 主要操作按钮 | 32×32 |
| 卡片整体（可点击） | 不限 |

**扩大热区而不改视觉尺寸**（密集工具栏必备技巧）：

```css
.icon-btn {
  width: 24px;
  height: 24px;
  position: relative;
}
.icon-btn::after {           /* 视觉不变，热区扩到 32px */
  content: '';
  position: absolute;
  inset: -4px;
}
```

`check_tokens.py --platform web` 用 24px 阈值；移动端用 44px。**不要用移动端阈值卡 PC 组件。**

## 4. 布局与窗口响应

### 4.1 滚动容器

- 弹层必须挂到 `document.body`，除非明确要跟随某个局部容器
- 表格容器独立滚动时，表头与表体都要考虑 hover 态不丢失
- 弹层在滚动容器内：需要 `getPopupContainer` 指向该容器，否则被 `overflow: hidden` 裁剪
- 视口边缘的弹层自动翻转：`placement` 要能根据空间自动调整（顶部空间不足时下移）

### 4.2 尺寸档位

PC 窗口跨度大，组件尺寸要能连续适配而非跳变：

| 断点 | 宽度 | 布局策略 |
|---|---|---|
| 窄 | < 1200px | 表单单列，侧边栏收起为图标 |
| 中 | 1200-1600px | 标准布局 |
| 宽 | > 1600px | 侧边栏展开，表格列可多显示 |

- 容器查询优于媒体查询（组件关心的是自己的容器，不是视口）
- 表格横向滚动优于压缩列
- 表单标签位置（顶/左）在窄屏下统一转顶部，不做两套布局

### 4.3 密度切换

数据密集型 PC 应用通常提供「紧凑/默认」密度：

- 紧凑模式减小行高与内边距，同屏显示更多行
- 密度选择应持久化到用户偏好
- 密度令牌与尺寸令牌分离：`size.control-height` 不变，只改 `line-height` 与 `padding`

## 5. PC 特有的组件类型

core 的通用分类未覆盖的 PC 组件：

| 类型 | PC 特有性 | 关键点 |
|---|---|---|
| 树形视图 | 高 | 展开状态、大量节点虚拟滚动、右键菜单、拖拽排序 |
| 数据表格 | 高 | 列宽拖拽、列显隐、排序、多选、固定列、密度切换 |
| 穿梭框 | 高 | 大量数据搜索、双列表、批量操作 |
| 右键菜单 | 高 | 分组、快捷键、危险项置底分隔 |
| 快捷键录入 | 中 | 录制组合键、冲突检测 |
| 窗口/浮窗 | 中 | 可拖拽、可缩放、焦点管理、层级管理 |
| 悬浮工具提示 | 高 | 延迟显示、跟随光标、边界翻转、可交互（用 Popover 而非 Tooltip） |
| 树形下拉 | 高 | 大数据量、搜索定位、父子联动 |
| 仪表盘布局 | 中 | 栅格拖拽、布局持久化、响应式重排 |

## 6. 拖拽（PC 高频交互）

拖拽是 PC 独有的强交互，但**必须提供替代路径**。

### 硬性要求

1. **非拖拽可达**：同一操作必须能通过按钮或菜单完成
2. **键盘可达**：能聚焦被拖拽项，用 `Ctrl+↑/↓` 或 `Space` 切换「拾起/放下」模式
3. **有落点反馈**：拖拽过程中必须显示插入位置指示
4. **可撤销**：操作后应有撤销机会（尤其删除类）
5. **防误触**：拖拽手柄需明显（`cursor: grab` + 图标），不能整行都能拖

### 拖拽冲突

- 与文本选区冲突：拖拽手柄区域要 `user-select: none`
- 与右键菜单冲突：拖拽区域右键不弹菜单
- 拖拽 iframe / 图片 / 链接要 `draggable="false"`，否则会出现浏览器原生拖拽图标
- 拖拽跨越 iframe 会失效——若页面含 iframe，改用非拖拽方案

## 7. 悬浮提示

PC 上 Tooltip 的使用边界比其他平台宽松，但仍有约束：

| 内容 | 载体 |
|---|---|
| 纯文字补充说明 | `Tooltip` |
| 需要交互（按钮/链接/输入） | `Popover` |
| 承载点击操作 | 两者都不行 —— 直接放界面元素 |

- 显示延迟 300-500ms，立即显示会干扰鼠标移动
- 同一区域同时只显示一个 Tooltip
- 靠近视口边缘时自动翻转方向，不被裁剪
- **可交互内容一律不用 Tooltip**（鼠标移开就消失，点不到）

---

## 8. 校验清单（PC 专属）

在 core 检查清单之外，PC 组件额外确认：

- [ ] 所有可交互元素有 hover 态，且与 active 态可区分
- [ ] 用 `:focus-visible` 而非 `:focus`
- [ ] `outline: none` 配有替代焦点样式
- [ ] cursor 语义正确，禁用态用 `not-allowed`
- [ ] 右键菜单中的操作在别处也可达
- [ ] 快捷键有 Tooltip 提示，区分 Mac/Windows
- [ ] 弹窗关闭后焦点回到触发元素
- [ ] 弹层在 `overflow` 容器内已正确挂载
- [ ] 拖拽有键盘替代路径
- [ ] 点击目标 ≥ 24px（密集区域已用伪元素扩热区）
- [ ] 布局在窄屏下有确定行为，不靠浏览器自动收缩
- [ ] 密度切换（若支持）不影响组件尺寸令牌

## 与移动端的差异速查

同一组件在两端复用时的分叉点：

| 维度 | PC | 移动端 |
|---|---|---|
| hover | 必需 | **不存在**，用按下态代替 |
| 选中 | hover 预览 + 点击 | 直接触发 |
| 右键菜单 | 支持 | 不支持 |
| 快捷键 | 支持 | 不支持 |
| 拖拽 | 支持 | 与滚动冲突，改用长按或上移操作 |
| 点击目标 | 24px | 44px |
| Tooltip | 支持 | 改用 Popover 或点击展开 |
| 悬停预览 | 可用于表格行预览 | 不存在 |
