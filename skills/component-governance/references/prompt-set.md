# 项目组件提示词集：三份必备 + 清单

## 目录与命名

`docs/components/` 下的文件由项目自定命名（能看懂即可）。唯一的固定名是 `README.md`——它是清单。

## README.md（清单，固定）

模型靠它知道**有哪些提示词、该取哪份**。每份一行，写清「管什么」：

| 文件 | 管什么 |
|---|---|
| `usage.md` | 在这个项目里，组件怎么写才算对 |
| `discovery.md` | 已经有什么、去哪找 |
| `creation.md` | 新建组件按什么规矩（含样式 wiki） |

> 新增提示词后**必须更新清单**，否则加了也没人取。

## 1 组件使用提示词（必备）

回答「在**这个项目**里，组件怎么写才算对」。

| 写什么 | 例 |
|---|---|
| 优先用现成组件 | 不要用 div 手搓按钮、下拉 |
| 场景 → 组件映射 | 要选一项用什么、要确认用什么、空数据用什么 |
| 交互习惯 | 危险操作怎么确认、加载态怎么表现、空状态写什么 |
| 项目特有约定 | 与通用习惯不同的地方 |
| 禁止用法 | 明确不能怎么做 |

**这一份直接对应「生成的东西不符合操作习惯」这个痛点，要写实。**

## 2 组件查找提示词（必备）

回答「项目里已经有什么、去哪找」。

| 写什么 | 例 |
|---|---|
| 组件在哪些目录 | `src/components`、`src/ui` |
| 命名规律 | `XxxFilter` 是筛选类、`XxxDialog` 是弹层类 |
| 怎么判断能否复用 | 看**变体轴**覆盖不覆盖需求 |
| 已有组件清单 | 可选，也可现场搜 |

**用普通搜索查文件，不建索引缓存**（缓存会过期、要维护、要处理失效；搜文件永远最新且够便宜）。

## 3 组件创建提示词（必备）

回答「新建一个组件时按什么规矩」。

| 写什么 | 例 |
|---|---|
| 样式定义在哪 | 样式 wiki：位置 + 机制 + 新增一个值怎么加（→ `style-wiki.md`） |
| 规格文档模板 | 强制七段 |
| 命名与目录约定 | 新组件放哪、怎么命名 |
| 平台差异 | PC / 移动端各自约束 |

**规格文档七段，缺一不可**：1 角色定义（含「不解决什么」）2 使用流程 3 Props 契约 4 状态全枚举 5 键盘与无障碍 6 Do & Don't 7 可扩展插槽。

第 4、6 段最常被省略，也最影响成品质量；「不解决什么」不写，模型会在不该用它的时候用它。

## 何时新增一份提示词

判断标准：**某个约定需要反复解释，写下来能减少后续沟通** → 值得单独一份。

常见方向（**举例，非清单**）：修改 / 扩展组件的时机、审查清单、废弃与迁移、项目特有复杂组件的用法、页面 / 布局约定、术语表。

**不要为「完整」预建空文件**，用到再加。
