# 通用操作习惯规范库

> 跨平台条目。平台特有条目（hover、触控热区、拖拽等）见同目录 `platform-web.md`。
> **平台包与本文件冲突时，以平台包为准**（平台事实优先于通用经验）。

## 怎么用这份文件

**生成前**：把适用条目作为硬约束写进组件实现，不是写完再检查。

**生成后**：逐条过检查清单，标记「满足 / 违反 / 不适用」。不适用要说明原因，不许静默跳过。

**持续演进**：用户明确反对某条时，以「例外条款」追加到项目 `.ui-kit/conventions.md`，**不要改本文件**——本文件是通用默认，项目例外是项目事实，两者混在一起两边都不准。

## 1. 危险操作与确认

### 1.1 确认方式按影响面分级

| 影响面 | 方式 | 不要用 |
|---|---|---|
| 可撤销（删除一条草稿） | 直接执行 + Toast 撤销 | 弹窗确认 |
| 不可撤销但影响小（删除一个文件） | Popconfirm / 轻确认 | Modal |
| 不可撤销且影响大（删除项目、清空数据） | Modal 二次确认 | Popconfirm |
| 批量操作 | Modal 确认，**必须明确写影响条数** | 任何轻量确认 |

### 1.2 确认弹窗的按钮顺序（国内通行习惯）

```
[ 取消 ]  [ 确定 ]        ← 取消在左，确定在右
```

- 危险操作：确定按钮用危险色
- 取消按钮永远是次要样式，永远是左边的那个
- **不要**把确定放左边——这是 Windows 之外多数地区的习惯，写反了用户会下意识点错

### 1.3 确认文案

- 标题说清对象：「删除项目」优于「确认操作」
- 正文说清后果，不说空话：「删除后该项目下的 12 个文件将一并移除，且无法恢复」优于「确定要删除吗？」
- 危险按钮文案用动词，不用「确定」：用「删除」而非「确定」——用户看按钮就能预判后果
- **不要**在确认弹窗里放表单或输入框

### 1.4 禁止项

- 确认弹窗里不放表单
- 不用 Toast 做需要判断的确认
- 不把「删除」放在操作列第一个位置（防误触）
- 同一页面不出现两种确认风格

## 2. 表单

### 2.1 布局一致性

- label 位置（顶 / 左）在同一表单内**必须统一**
- 必填标记的位置必须统一（都在 label 前或都在 label 后）
- label 与控件的间距取 `tokens` 间距令牌，不写魔法数字
- 标签宽度对齐用栅格，不用固定像素

### 2.2 校验时机

- 提交型表单：失焦即校验（`onBlur`），提交时全量校验并聚焦第一个错误项
- 筛选型表单：不做校验，只做输入约束
- 同一表单内**不得混用**失焦校验和提交校验
- 用户修改过并通过校验的字段，再次失焦**不重复报错**（避免打扰）

### 2.3 错误提示

- 位置：字段下方，紧贴控件
- 文案说清怎么改，不只是「格式错误」——用「手机号需为 11 位数字」
- 不用 Tooltip 承载错误文案（鼠标移开就看不到了）
- 一个字段同时只显示一条错误，不要堆叠

### 2.4 提交

- 提交中：按钮内联 loading **并禁用**，防重复提交
- 失败：错误信息在表单顶部汇总，同时聚焦第一个错误字段
- 成功：关闭弹层或跳转，并给出明确反馈
- 不静默失败

## 3. 加载状态

按耗时分级，不同耗时用不同形态：

| 耗时 | 形态 | 约束 |
|---|---|---|
| < 300ms | 不显示 loading | 显示 loading 反而闪烁 |
| 300ms - 1s | 局部 spinner 或按钮 loading | |
| 1s - 10s | 骨架屏 | **不用**整块 spinner |
| > 10s | 进度提示 + 可取消 | |

- 区域加载用骨架屏，不用整块遮罩
- **首屏不用全屏遮罩 loading**
- 按钮 loading 时必须同时禁用，否则仍可重复点击
- 分页加载：只给列表区域加局部 loading，不要遮整个页面
- 提交 loading 禁止超过 10s 无反馈

---

## 4. 空状态

三件套，缺一不可：

```
说明为什么空  +  行动按钮  +  （首次）引导说明
```

- 标题说清原因：「还没有筛选结果」优于「暂无数据」
- 区分两种空：**首次为空**（引导创建）与**筛选后为空**（引导清除筛选）
- 首次为空必须给行动按钮
- 插图不是必需，但纯文字空状态在列表页显得单薄
- 搜索无结果时提供「清除搜索条件」入口

## 5. 反馈

### 5.1 反馈时延

| 时延 | 处理 |
|---|---|
| < 100ms | 直接完成，无需反馈 |
| 100ms - 1s | loading 指示 |
| > 1s | 进度条 / 步骤提示 |
| > 10s | 可中断、可离开 |

**任何超过 1 秒的操作都必须有反馈**，否则用户会重复点击。

### 5.2 反馈载体

| 类型 | 载体 | 用途 |
|---|---|---|
| 轻量成功 | Toast | 操作已完成，无需后续动作 |
| 失败 | 消息 / 表单内联 | 需要用户处理或重试 |
| 危险结果 | Modal | 已发生且不可自动恢复 |
| 过程 | loading / 进度 | 执行中 |

- Toast **不用**承载需要用户决策的信息
- 不用 Alert 承载瞬时反馈（太重，会遮挡内容）
- 不用 Modal 承载成功提示（应该直接关闭或跳转）
- 报错要可复制（便于用户反馈给客服）

## 6. 列表与表格

- 批量操作需二次确认，**确认文案必须写明影响条数**（「删除选中的 12 项」）
- 操作列 > 3 个：折叠进「更多」下拉
- 危险操作不放在操作列首位，且与主操作视觉区分
- 空数据、无权限、加载中、无搜索结果 —— 四种状态各有独立呈现，不共用一个「暂无数据」
- 排序、筛选状态要反映在 URL 或状态管理中（可分享、可回退）
- 长列表必须分页或虚拟滚动，不允许无限滚动到底

---

## 7. 弹层

- 右上角关闭按钮（除非有且仅有单个按钮）
- ESC 可关闭（除非是必须完成的流程）
- **遮罩点击行为全站一致** —— 不能有的弹层点遮罩能关、有的不能
- 弹层内可滚动时，滚动只在内容区，标题与底部按钮固定
- 弹层宽度取 `tokens` 令牌，同类弹层宽度一致
- 弹层不能被父级 `overflow: hidden` 裁剪 —— 需要 `getPopupContainer` 指定挂载节点
- 嵌套弹层不超过两层
- 同一时刻只应有一个「主动」弹层

---

## 8. 禁用 vs 隐藏

- **不可用优先 `disabled`**，并通过 Tooltip 说明原因
- 直接隐藏会让用户困惑（「为什么别人有我没有」）
- 例外：会造成信息过载或暴露权限设计时才隐藏
- 禁用态必须有说明，光是灰着没用

---

## 9. 键盘与无障碍

- 所有可交互元素键盘可达，Tab 顺序符合视觉顺序
- 焦点状态**必须可见**（不要 `outline: none` 了事）
- 弹层打开时焦点进入弹层，关闭后回到触发元素
- 图标按钮必须有 `aria-label`
- 表单控件必须有关联 label
- 不能只用颜色传达信息（需配合图标或文字）
- 尊重 `prefers-reduced-motion`

---

## 10. 交互模式反模式速查

| 反模式 | 问题 | 正确做法 |
|---|---|---|
| 能滚不用分页 | 定位成本高，回到顶部要重滚 | 长列表分页 |
| 能下拉不用弹窗 | 层级过重，关闭成本高 | 轻量操作用下拉 |
| 用 Tooltip 承载可点击内容 | 悬停才能发现，触屏不可用 | 用 Popover |
| 用 Popconfirm 承载长文案 | 空间不足被截断 | 改 Modal |
| 危险操作放在首个位置 | 最高频误触 | 放末位并视觉区分 |
| 多个弹层套嵌 | 用户迷失 | 扁平化 |
| 确认框里放输入 | 用户不理解为什么要填 | 取消即撤销 |
| 加载时禁用整个页面 | 用户无法做其他事 | 局部 loading |
| 空状态只写「暂无数据」 | 用户不知道下一步 | 说明原因 + 给按钮 |
| 组件自己发明交互 | 与全站不一致 | 复用已有组件 |

---

## 11. 文案口径

- 按钮用动词，不用「确定 / 是 / 好」——用户看按钮就该知道点了会发生什么
- 错误文案说清「怎么改」，不只说「错了」
- 不用专业术语替代用户语言（「非法参数」→「请输入有效的邮箱地址」）
- 空状态标题说原因，不说状态
- 数字与单位不省略，但也不要堆砌精度

---

## 12. 状态必须全枚举

任何组件的规格文档必须覆盖以下状态，逐条写明视觉与行为。**这是使用体验差距最大、也最容易被漏的部分。**

```
default      默认
hover        悬停（移动端跳过）
focus        聚焦（键盘）
active       按下
selected     选中
disabled     禁用（附原因说明）
readonly     只读（附与 disabled 的区别说明）
loading      加载中（附是否阻塞交互）
error        错误（附错误文案口径）
empty        空（区分首次空 / 筛选后空）
```

**disabled 与 readonly 必须区分**：disabled 不可交互且通常置灰；readonly 不可编辑但内容可读可复制，视觉上不应置灰。表单里混用两者是常见错误。
